## 1. Claude Code とは

Claude Code は、Anthropic 社の AI「Claude」が **あなたのパソコンのファイルを読み、編集し、コマンドを実行して、作業を最後までやり切ってくれる道具** です。

ふつうのチャット AI との違いは次のとおりです。

| | チャット AI（claude.ai など） | Claude Code |
|---|---|---|
| ファイル | 自分でコピペして渡す | **自分でフォルダの中を探して読む** |
| 作業 | 答えを教えてくれる | **実際にファイルを書き換え、コマンドを実行する** |
| 確認 | 自分で試す | **自分でテストを動かし、失敗したら直す** |
| 向いていること | 相談・文章作成 | アプリ・サイト作り、データ整理、自動化、ドキュメント整備など「手を動かす仕事」 |

「プログラマー向け」と思われがちですが、**フォルダの中のファイルを扱う仕事なら何でも任せられます**。たとえば次のような使い方です。

- ホームページや LP（ランディングページ）を作る・直す
- CSV の売上データを集計してグラフ付きのレポートにする
- 大量の文章ファイルの表記ゆれをまとめて直す
- 毎朝の情報収集を自動化する
- 自分専用の業務ツール（家計簿、タスク管理など）を作る

### どこで使えるか

中身は同じ Claude Code で、使う場所（画面）が選べます。CLAUDE.md（5章）や設定ファイル（8章）の書き方はどこでも同じです。ただし Web やスマホから使う場合はクラウド上で動くため、自分のパソコンの中のファイルや設定は直接は見えません。

| 使う場所 | 特徴 |
|---|---|
| **ターミナル（CLI）** | 基本の形。黒い画面に文字で指示する。機能がいちばん揃っている |
| **デスクトップアプリ** | Mac / Windows 用のアプリ（Linux 版はベータ）。画面で操作できて初心者にやさしい |
| **Web（claude.ai/code）** | ブラウザから使う。クラウド上で動くので、パソコンを閉じても作業が続く |
| **スマホ（Claude アプリ）** | 外出先から指示・確認ができる |
| **VS Code / JetBrains** | プログラミング用エディタの中で使う |
| **GitHub Actions など** | GitHub 上で `@claude` と書くと自動で作業する（10章） |

### 必要なもの

- **Claude の有料プラン**（Pro / Max / Ultra / Team / Enterprise。おすすめ）、または Claude Console（API）のアカウント
- 無料プランでは Claude Code は使えません

> **データの扱いについて**: Claude Code に読ませたファイルの内容は、処理のために Anthropic のサーバーへ送られます。個人向けプラン（Pro / Max など）では、設定の「モデル改善への利用」がオンだと最長5年、オフだと30日保存されます。Team / Enterprise / API は標準で30日保存で、学習には使われません。また、会話の記録は自分のパソコンの `~/.claude/projects/` にも30日間そのまま残ります。お客様の個人情報などは必要最小限だけ扱わせるようにしましょう。

### 用語ミニ解説

| 用語 | 意味 |
|---|---|
| ターミナル | 文字でパソコンに命令する画面。Mac は「ターミナル」、Windows は「PowerShell」など |
| コマンド | ターミナルに打ち込む命令文（例: `cd`, `ls`） |
| プロジェクト | 作業対象のフォルダ。Claude Code は基本的に「今いるフォルダ」の中で働く |
| セッション | Claude Code を起動してから終了するまでの1回分の会話 |
| コンテキスト | AI がその会話で覚えていられる情報。量に上限があり、いっぱいになると古い内容が要約される |
| トークン | AI が文章を数える単位。料金や上限の計算に使われる |
| Git（ギット） | ファイルの変更履歴を記録する仕組み。失敗しても前の状態に戻せる |
| スラッシュコマンド | Claude Code の中で `/` から始めて入力する命令（例: `/clear`） |
| `~/`（ホームフォルダ） | 自分のユーザー用フォルダのこと。`~/.claude` は「ホームフォルダの中の `.claude` フォルダ」 |
| 隠しフォルダ | `.claude` のように `.` で始まるフォルダ。普段は見えない（Mac の Finder では `⌘ + Shift + .` で表示） |
| Markdown | `#` で見出し、`-` で箇条書きを書く簡単な書式。ファイル名は `.md` |
| JSON | `{ "名前": "値" }` の形で設定を書く書式。カンマや括弧が1つずれるだけで動かなくなるので注意 |
| API / API キー | API はサービス同士をつなぐ窓口。API キーはそれを使うための合言葉（パスワードのようなもの） |
| MCP | Claude Code を外部サービス（Notion、GitHub など）とつなぐ仕組み（7-3） |
| リポジトリ | Git で管理しているフォルダのこと。GitHub 上に置いたものも指す |
| Issue / プルリクエスト | GitHub の機能。Issue は「やること・不具合のメモ」、プルリクエストは「この変更を取り込んでください」という依頼 |
| Node.js | プログラムを動かすための土台ソフトの一つ。一部のツールで必要になる |
| `.env` | パスワードや API キー（サービスの合言葉）を書いておくファイル。人にも AI にも見せない |
| コミット / プッシュ | Git で「今の状態を記録すること」/「記録を GitHub などにアップロードすること」 |
| テスト | プログラムが正しく動くかを自動で確かめる仕組み |

## 2. はじめての Claude Code（15分チュートリアル）

### 手順0：ターミナルを開く

- **Mac**: `⌘ + Space` で Spotlight を開き、「ターミナル」と入力して開く
- **Windows**: スタートメニューで「PowerShell」と入力して開く

### 手順1：インストールする

ターミナルで、使っているパソコンに合わせて1行だけ実行します。

**Mac / Linux**（Windows で WSL＝Windows 上で Linux を動かす仕組み を使っている人もこちら。分からなければ下の PowerShell の方で OK）

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

**Windows（PowerShell）**

```powershell
irm https://claude.ai/install.ps1 | iex
```

> Mac で Homebrew を使っている人は `brew install --cask claude-code` でも入れられます（この場合は自動更新されないので、ときどき `brew upgrade claude-code` を実行します）。

入ったか確認します。バージョン番号が表示されれば成功です。

```bash
claude --version
```

> **画面操作が好みなら**: デスクトップアプリから始めることもでき、この資料の内容はほぼそのまま当てはまります。Web 版（claude.ai/code）はクラウドで動くため、手元のファイルを直接扱う手順（2章など）は異なります。

### 手順2：作業用フォルダを作って起動する

```bash
mkdir my-first-project   # フォルダを作る
cd my-first-project      # そのフォルダに移動する
claude                   # Claude Code を起動する
```

初めての起動ではブラウザが開き、ログインを求められます。Claude のアカウントでログインしてください。

> - 作ったフォルダは、ホームフォルダの中にできます。Mac は `open .`、Windows は `explorer .` と入力すると、そのフォルダが開きます。
> - **デスクトップやホームフォルダそのもので `claude` を起動しない** でください。Claude は起動したフォルダの中を作業場所にするので、関係ないファイルまで扱える状態になってしまいます。作業ごとに専用のフォルダを作るのが基本です。

### 手順3：最初のお願いをする

画面の入力欄に、日本語でそのまま書きます。

```text
自己紹介用のシンプルな1ページのホームページを index.html に作って。
名前は「山田花子」、仕事は「Webデザイナー」、連絡先ボタンも付けて。スマホでも見やすくして。
```

すると Claude は次のように動きます。

1. 何を作るか考える
2. ファイルを作ってよいか **確認を求めてくる**（何をしようとしているか読んでから「Yes」を選ぶ。分からなければ「No」で止めて「今何をしようとしてる？」と聞けば OK）
3. `index.html` を作って、何をしたか報告する

できた `index.html` をダブルクリックすると、ブラウザで見られます。

### 手順4：直してもらう

```text
背景を淡いベージュにして、名前の文字をもっと大きくして
```

このように **会話しながら少しずつ直していく** のが基本の使い方です。

### 手順5：終了する

`/exit` と入力するか、入力欄が空の状態で `Ctrl + C` を2回押します。次回、同じフォルダで続きから始めたいときは次のように起動します。

```bash
claude -c   # 前回の会話の続きから
```

### うまくいかない時

| 症状 | 対処 |
|---|---|
| `claude: command not found` と出る | ターミナルを一度閉じて開き直す。それでも出る場合は手順1のインストールをもう一度実行する |
| ログインできない | 無料プランでは使えません。有料プランに入っているか確認してください。別のアカウントでログインし直すには、Claude Code の中で `/login` |
| 何か調子がおかしい | ターミナルで `claude doctor` を実行するとインストールや設定の状態を診断できる。Claude Code の中なら `/doctor` |

## 3. 基本の使い方

### 3-1. 指示の出し方

Claude Code には **ふつうの日本語で頼めば大丈夫** です。ただ、次の4点を入れると結果がぐっと良くなります。

| 入れること | 悪い例 | 良い例 |
|---|---|---|
| **目的** | 「直して」 | 「問い合わせフォームの送信ボタンが反応しないので直して」 |
| **場所** | 「グラフを作って」 | 「`data/sales.csv` から月別売上のグラフを作って」 |
| **条件** | 「きれいにして」 | 「色は青系、スマホでも崩れないように」 |
| **確認方法** | （なし） | 「直したらブラウザで開いて動作を確認して」 |

**特に大事なのは「確認方法」です**。Claude が自分で結果を確かめられると、間違いに気づいて自分で直してくれます。

### 3-2. ファイルを指定する（`@`）

`@` を入力すると、ファイル名の候補が出ます。ファイルを指定すると、Claude はその中身を読んでから作業します。

```text
@docs/proposal.md の誤字を直して、もっと読みやすくして
```

### 3-3. 画像を見せる

スクリーンショットやデザインの画像を見せられます。

- 画像ファイルを入力欄に **ドラッグ＆ドロップ**
- コピーした画像を **`Ctrl + V`** で貼り付け（Mac でも `⌘` ではなく `Ctrl`。Windows は `Alt + V`）

```text
（画像を貼り付けて）このデザインと同じ見た目にして
```

### 3-4. 止める・やり直す

| やりたいこと | 操作 |
|---|---|
| Claude の作業を **途中で止める** | `Esc` を押す（止めたあと、指示を言い直せる） |
| **前の状態に巻き戻す** | 入力欄が空の状態で `Esc` を2回押す、または `/rewind` |
| 会話を **リセット** する | `/clear` |

`/rewind` では「ファイル（コード）も会話も戻す」「会話だけ戻す」「ファイルだけ戻す」などを選べます。ただし、コマンド実行で変わったファイルやサブエージェントによる変更は戻りません。**大事な作業は Git でも記録しておく** と安心です（次の 3-5）。

### 3-5. Git で保存する（Claude に頼めば OK）

Git はファイルの「セーブポイント」を作る仕組みです。コマンドを覚えなくても、Claude に頼めばやってくれます。

```text
このフォルダを Git で管理できるようにして
```

```text
ここまでの変更を、分かりやすい説明付きでコミット（保存）して
```

```text
昨日の状態と比べて、何が変わったか教えて
```

うまくいっている時にこまめにコミットしておけば、失敗しても「さっきのコミットの状態に戻して」で元に戻せます。ただし戻すと、**コミットしていない変更は消えます**。不安なら「戻す前に、消える変更がないか確認して」と添えてください。

### 3-6. コマンドを自分で実行する（`!`）

入力の先頭に `!` を付けると、そのままターミナルのコマンドとして実行され、結果が会話に入ります。

```text
! ls
```

### 3-7. 会話の続きから始める

| やりたいこと | コマンド |
|---|---|
| 前回の続きから始める | `claude -c` |
| 過去の会話を選んで再開する | `claude --resume`（または Claude Code の中で `/resume`） |
| 会話に名前を付ける | Claude Code の中で `/rename` |

### 3-8. ビジネスでの使い方例（そのままコピーして使えます）

ファイル名は自分のものに置き換えてください。

**売上・請求の集計**

```text
invoices/ フォルダにある今月の請求書 CSV を全部読んで、取引先ごとの合計金額を表にして reports/2026-11_請求集計.md に保存して。
合計が元データと合っているか、最後に検算して結果を教えて。
```

**お問い合わせ返信のテンプレート作り**

```text
@faq.md を参考に、よくある問い合わせ5種類（料金・納期・キャンセル・支払い方法・修正依頼）への返信テンプレートを templates/返信テンプレ.md に作って。
丁寧だけど堅すぎない文体で、1通200字以内。
```

**ブログ記事の表記ゆれを一括で直す**

```text
blog/ フォルダの記事全部で、表記ゆれ（「出来る/できる」「サーバ/サーバー」など）を探して一覧にして。
直す前に一覧を見せて、私が OK したら直して。
```

**競合サービスの比較表**

```text
「オンライン英会話」の主な競合5社を Web で調べて、料金・特徴・ターゲット・強み弱みを比較表にして research/競合比較.md に保存して。
参考にした URL も付けて。
```

（Web 検索やページ閲覧の許可を求められたら、内容を見て Yes を選びます）

**毎朝の情報まとめを自動化**

```text
/schedule 毎朝 日本時間の7時に、生成AI業界の昨日のニュースを5つ選んで3行ずつ要約して
```

（`/schedule` は 10-3 で説明するクラウドの機能です。設定の途中で Claude が詳細を質問してきます。クラウドで動くので手元のパソコンのファイルは読めず、実行のたびにプランの利用量を消費します）

## 4. 権限モード：Claude にどこまで任せるか

Claude Code は、ファイルの編集やコマンドの実行の前に **「やってもいいですか？」と確認** してきます。この確認の度合いを **権限モード** で切り替えられます。

**`Shift + Tab` を押すたびにモードが切り替わります**（画面の下に今のモードが表示されます）。

| モード | 動き | 向いている場面 |
|---|---|---|
| **default（通常）** | 編集やコマンドのたびに確認する | 慣れないうち、大事なファイルを扱う時 |
| **acceptEdits（編集は自動）** | ファイル編集は確認なしで進める | 作業を任せてテンポよく進めたい時 |
| **plan（プランモード）** | **読むだけ**。編集せずに計画を立てて見せてくれる | 大きな作業の前、何をするか先に確認したい時 |
| **auto（自動）** | 安全かどうかを AI が判断し、危なそうな時だけ確認する | 慣れてきて、任せる範囲を広げたい時 |
| dontAsk（上級者向け） | 確認が必要な操作は **すべて自動で拒否** する | 許可済みの操作だけで動かす自動処理 |
| bypassPermissions（上級者向け） | 確認を **ほぼすべて省略** する（deny の禁止ルールは有効なまま） | 隔離された専用環境のみ。**普段は絶対に使わない** |

> - default は画面上で「Manual」と表示されることがあります。
> - auto は対応しているモデルと、組織の設定（Team / Enterprise では管理者がオフにできる）が必要です。条件を満たさない環境では `Shift + Tab` で選べません。
> - dontAsk と bypassPermissions は通常 `Shift + Tab` の切り替えには出てきません。
> - 利用環境やバージョンによって、最初のモードや選べるモードは異なります。今のモードは画面の下で確認してください。

### おすすめの進め方：「まず計画、それから実行」

大きめの作業は、いきなり始めさせずに **プランモードで計画を立てさせる** と失敗が減ります。

1. `Shift + Tab` でプランモードにする
2. 「ホームページに料金ページとお問い合わせフォームを追加したい。どう進めるか計画を立てて」と頼む
3. 出てきた計画を読んで、気になる点を直してもらう
4. 計画に納得したら承認して実行させる

### よく使う操作を「毎回確認しない」ようにする

確認画面で「今後は確認しない（don't ask again）」を選ぶと、そのコマンドは次から自動で許可されます（そのプロジェクトの `.claude/settings.local.json` に保存されます）。

設定ファイル（8章）にまとめて書くこともできます。たとえばプロジェクトの `.claude/settings.json` に次のように書きます。

```json
{
  "permissions": {
    "allow": ["Bash(ls *)"],
    "deny": ["Read(./.env)", "Bash(git push *)"]
  }
}
```

- `allow` は確認なしで許可、`deny` は禁止です。**deny が常に優先** されます。
- 上の例は「フォルダの中身の一覧表示（`ls`）は自動で許可」「パスワードなどが入った `.env` ファイルは読ませない」「GitHub などへのアップロード（push）は禁止」という意味です。
- **すでにファイルがある場合は、丸ごと上書きせずに中身を合体させてください**。自信がなければ Claude に「この設定を .claude/settings.json に追加して」と頼むのが安全です。

## 5. CLAUDE.md：Claude に覚えておいてほしいことを書く

Claude Code は会話が終わると内容を忘れます。毎回同じ説明をしなくて済むように、**プロジェクトのルールや前提を書いておくファイル** が `CLAUDE.md` です。起動するたびに自動で読み込まれます。

### 作り方

Claude Code の中で次を実行すると、フォルダの中身を調べて下書きを作ってくれます。

```text
/init
```

あとは自分で書き足したり、「CLAUDE.md に『〜』というルールを追加して」と頼んだりして育てていきます。

### 書く内容の例

```markdown
# このプロジェクトについて
- 個人事業のホームページ。お客様は30〜50代の女性が中心

# ルール
- 文章は「です・ます」調で、専門用語を使わない
- 色はブランドカラーの #2E7D6B を基準にする
- 画像は images/ フォルダに入れる

# 確認方法
- 変更したら index.html をブラウザで開いて、スマホ幅でも崩れていないか確認する
```

### 置き場所

| ファイル | 効く範囲 | 用途 |
|---|---|---|
| `~/.claude/CLAUDE.md` | 自分の全プロジェクト | 「日本語で答えて」など、自分の好み |
| `./CLAUDE.md`（プロジェクトのフォルダ） | そのプロジェクト | プロジェクトのルール。チームで共有する |
| `./CLAUDE.local.md` | そのプロジェクト・自分だけ | 共有したくない個人メモ |

### 書くときのコツ

- **短く保つ**（公式の目安は1ファイル200行以内）。長すぎると守られにくくなり、毎回のコンテキストも圧迫します
- 「Claude が見ただけでは分からないこと」を書く（お客様像、ブランドのルール、確認の手順など）
- 別のファイルを読み込ませたい時は `@ファイル名` と書けます（例: `@docs/brand-guide.md`）
- 中身の確認・編集は `/memory` からもできます

> Claude Code には、作業中に気づいたことを Claude 自身がメモしておく **自動メモリ** 機能もあります。`/memory` でオン・オフや中身を確認できます。

## 6. コンテキストとコストの上手な管理

Claude Code の利用量は、プランごとに **一定時間あたり・1週間あたりの上限** があります（API 利用の場合は使った分だけ課金）。会話が長くなるほど、1回のやり取りで消費する量も増えます。

### 覚えておきたい4つのコマンド

| コマンド | 何をするか | いつ使うか |
|---|---|---|
| `/clear` | 会話をリセットする | **別の作業に移る時**（いちばん効果的） |
| `/compact` | これまでの会話を要約して軽くする | 同じ作業を続けたいが会話が長くなった時 |
| `/context` | 今どれくらいコンテキストを使っているか表示する | 重くなってきた気がする時 |
| `/usage` | 利用量・上限の状況を表示する | 使いすぎていないか確認したい時 |

### 節約のコツ

1. **作業が変わったら `/clear`**。前の話が残っていると、無駄に読み返す量が増えます
2. **2回直してもうまくいかない時は、`/clear` して指示を書き直す**。同じ会話で何度も直させるより早いことが多いです
3. **CLAUDE.md は短く**。毎回読み込まれるので、長いと毎回コストがかかります
4. **簡単な作業は軽いモデルで**（次の節）
5. **大量の調べものはサブエージェントに任せる**（9章）。途中経過がメインの会話に溜まらないので、会話が長くなりにくくなります（ただしサブエージェントの分も利用量は消費します）
6. **使わない MCP サーバーやプラグインは切る**（7章）。有効なだけで毎回少しずつ消費します

### モデルと「考える深さ」を選ぶ

`/model` で使う AI のモデルを切り替えられます。

| モデル | 特徴 | 向いている作業 |
|---|---|---|
| **Opus** | 最も賢い。標準のモデル | 難しい設計、複雑な不具合、大きな作業 |
| **Sonnet** | 賢さと速さのバランスが良い | 日常的な作業の多く |
| **Haiku** | 速くて軽い | 簡単な修正、単純な調べもの |

また `/effort` で **考える深さ**（`low` / `medium` / `high` / `xhigh` / `max`）を変えられます。深くするほど丁寧になりますが、時間と利用量も増えます。主なモデルの標準は `medium` です。迷ったら標準のままで構いません。

## 7. 機能を広げる：拡張機能の全体像

Claude Code には、自分の仕事に合わせて「育てる」ための仕組みがいくつかあります。最初は全部覚える必要はありません。**困ったことが出てきたら、対応する機能を使う** くらいで十分です。

| こんな時は | 使う機能 | ひとことで |
|---|---|---|
| 毎回同じ説明をしている | **CLAUDE.md**（5章） | 常に覚えておいてほしいこと |
| 決まった手順の作業を何度も頼む | **スキル** | 手順書。`/名前` で呼び出せる |
| 専門の担当者に任せたい／会話を散らかしたくない | **サブエージェント** | 専門の助手（9章） |
| 「必ず〜する」「絶対〜させない」を徹底したい | **フック** | 決まったタイミングで自動実行される処理 |
| Notion・Slack・GitHub などの外部サービスとつなぎたい | **MCP** | 外部サービスとの接続口 |
| 上の機能をまとめて入れたい・配りたい | **プラグイン** | 機能の詰め合わせパック |

### 7-1. スキル：よく使う手順を登録する

決まった手順を書いたファイルを置いておくと、`/名前` で呼び出せます。Claude が必要だと判断して自動で使うこともあります。

保存するファイル: `.claude/skills/weekly-report/SKILL.md`

```markdown
---
name: weekly-report
description: 今週の売上データから週次レポートを作る。「週報」「週次レポート」と言われたら使う。
---

1. data/ フォルダの今週分の CSV を読む
2. 売上合計・前週比・よく売れた商品トップ5を計算する
3. reports/ フォルダに「YYYY-MM-DD_週報.md」として保存する
4. 気になる変化があれば、最後に3行でコメントする
```

使い方:

```text
/weekly-report
```

- 自分の全プロジェクトで使うなら `~/.claude/skills/<名前>/SKILL.md`、そのプロジェクトだけなら `.claude/skills/<名前>/SKILL.md` に置きます
- 自分でファイルを作るのが面倒なら、「週報を作るスキルを .claude/skills/weekly-report に作って」と Claude に頼めば作ってくれます
- 以前からある `.claude/commands/` に置く「カスタムコマンド」も引き続き使えます（今はスキルと統合されています）

### 7-2. フック：決まったタイミングで必ず実行する

CLAUDE.md に書いたルールは「お願い」なので、守られないこともあります。**絶対に守らせたい** ことはフックにします。たとえば「ファイルを編集したら必ず整形ツールを実行する」「特定のコマンドは実行させない」などです。

- 設定ファイル（8章）の `hooks` に書きます。`/hooks` で確認できます
- 主なタイミング: ツール実行の前（`PreToolUse`）・後（`PostToolUse`）、作業が終わった時（`Stop`）、セッション開始時（`SessionStart`）など

例: Claude がファイルを編集・作成するたびに、**そのファイルだけ** を整形ツール Prettier できれいに整える（保存するファイル: `.claude/settings.json`）

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "f=$(jq -r '.tool_input.file_path') && npx --yes prettier --write --ignore-unknown \"$f\""
          }
        ]
      }
    ]
  }
}
```

> - Mac / Linux 向けの例で、Node.js と jq（JSON を扱うツール）が必要です。Windows ではそのままでは動きません。整形ツールを使っていないなら、試さなくて大丈夫です。
> - ブログ記事の Markdown や CLAUDE.md なども整形の対象になり、改行などが変わることがあります。
> - フックは **あなたの権限で、確認なしに** 自動実行されます。内容を理解したものだけを設定してください。
> - `.`（フォルダ全体）を対象にするコマンドは、関係ないファイルまで書き換えてしまうので避けましょう。
> - 自分で書くのが不安なら、「ファイルを編集したら自動で整形するフックを設定して」と Claude に頼むこともできます。

### 7-3. MCP：外部サービスとつなぐ

MCP を使うと、Claude Code から GitHub・Notion・ブラウザ操作などの機能を使えるようになります。

**初心者は、まず `/plugin` から公式マーケットプレイスのプラグイン（7-4）を選ぶのが簡単です**。MCP の接続が入ったプラグインもあります。自分で追加する場合は、ターミナルで次のように実行します（URL は各サービスの説明ページに載っています）。

```bash
# Web 上の MCP サーバーを追加する例
claude mcp add --transport http <名前> <サーバーのURL>

# 追加済みの一覧を見る / 削除する
claude mcp list
claude mcp remove <名前>
```

- Claude Code の中で `/mcp` を開くと、接続状況の確認やログインができます
- 何も付けないと、そのプロジェクトで自分だけが使える設定になります。`--scope user` で自分の全プロジェクトに、`--scope project` でプロジェクトの `.mcp.json`（プロジェクトに置く MCP 設定ファイル）に保存され、チームで共有できます
- **信頼できる提供元のものだけを使ってください**。外部サービスにデータが送られます

### 7-4. プラグイン：まとめて入れる

スキル・サブエージェント・フック・MCP をまとめたパックです。Claude Code の中で `/plugin` を開くと、公式のマーケットプレイスなどから探してインストールできます。入れたら `/reload-plugins` で反映されます。

## 8. 設定ファイル（settings.json）

権限・フック・使うモデルなどは JSON 形式の設定ファイルに書きます。普段は `/config`（設定画面）や、確認画面での選択で自動的に書き込まれるので、**直接編集するのは慣れてからで大丈夫** です。

| ファイル | 効く範囲 | Git で共有 |
|---|---|---|
| `~/.claude/settings.json` | 自分の全プロジェクト | しない |
| `.claude/settings.json` | そのプロジェクト | **する**（チームで同じ設定に） |
| `.claude/settings.local.json` | そのプロジェクト・自分だけ | しない（Claude Code が作った場合は自動で Git の対象外になる。手で作った時は `.gitignore` に追加） |

- 同じ項目が複数の場所にあると、**よりプロジェクトに近い方（local → プロジェクト → ユーザーの順）が優先** されます。会社などで管理者が配布する設定は、さらに上位です
- `permissions.allow` などのリストは、上書きではなく **足し合わされます**
- JSON なのでコメント（`//`）は書けません
- どの設定ファイルが読み込まれているかは `/status` で確認できます。読み込めなかった項目などの詳しい診断は、ターミナルで `claude doctor`
- `/config` や `/model` で変えた設定の多くは、ユーザー用の `~/.claude/settings.json` に保存されます（一部の項目は別のファイル）

## 9. サブエージェント：専門の助手に任せる

サブエージェントは、**メインの会話とは別のコンテキストで動く専門の助手** です。調べものの途中経過はメインの会話に入らず、**結果の要約だけが戻ってくる** ので、メインの会話が散らかりません（サブエージェントの利用分も、プランの利用量にはカウントされます）。

```text
サブエージェントを使って、このフォルダの中で古い料金表が残っているページを全部探して
```

- 「Explore（調査担当）」など、最初から入っているサブエージェントがあり、Claude が必要に応じて自動で使います
- `.claude/agents/` に Markdown ファイルを置くと、自分専用の助手（校正担当、市場調査担当など）を作れます

> 作り方や実例は、別資料 **[Claude Code サブエージェント入門ガイド](./claude-code-subagents.md)** で詳しく解説しています。

## 10. 一歩進んだ使い方

### 10-1. 非対話モード（`-p`）で自動化する

`-p` を付けると、1回だけ質問して答えを受け取り、すぐ終了します。決まった作業を自動化したい時に便利です。

```bash
claude -p "data/sales.csv を集計して、今月の売上合計だけを答えて"

# 他のコマンドの結果を渡すこともできる
cat report.txt | claude -p "この文章を3行で要約して"
```

### 10-2. 複数の作業を並行する

- **ターミナルを複数開いて**、それぞれで Claude Code を動かせます
- 同じフォルダで同時に作業させるとぶつかるので、`claude --worktree <名前>`（または `-w`）を使うと、作業用の分身フォルダの中で動かせます（Git で管理しているフォルダでのみ使えます）
- 時間のかかるコマンドは `Ctrl + B` でバックグラウンドに回せます

### 10-3. クラウドで動かす（Web・スマホ）

claude.ai/code やスマホの Claude アプリから始めた作業は、Anthropic のクラウド上で動きます。

> クラウド機能は Pro / Max / Ultra / Team / Enterprise のプランで使えます（Enterprise は席の種類による。無料プラン不可）。`--cloud` や `/teleport` は claude.ai アカウントでのログインが必要で、API キーだけの利用では使えません。クラウドでの作業もプランの利用量にカウントされます。

- **パソコンを閉じても作業が続く**ので、外出前に頼んでおいて、あとで結果を見る使い方ができます
- ターミナルから `claude --cloud "〜を直して"` でクラウドに任せることもできます
- クラウドの作業を手元に持ってくるには `/teleport`
- 定期的に動かしたい作業は `/schedule` で予約できます（例: 毎朝のニュースまとめ）

### 10-4. GitHub と連携する

- Claude Code の中で `/install-github-app` を実行すると、GitHub との連携を設定できます（github.com のリポジトリが対象。そのリポジトリの管理者権限が必要）
- 設定後は、GitHub の Issue やプルリクエストのコメントに `@claude` と書くだけで、Claude が作業してくれます
- 「変更内容をコミットして」「プルリクエストを作って」と頼むだけで Git の操作もしてくれます

## 12. 上手に使うための10か条

1. **目的・場所・条件・確認方法** を伝える（3-1）
2. **確認方法を渡す**。テストやブラウザでの確認を Claude 自身にさせると、品質が大きく上がる
3. **大きな作業はプランモードで計画から**（4章）
4. **別の作業に移ったら `/clear`**（6章）
5. **2回直してだめなら、指示を書き直してやり直す**
6. **CLAUDE.md は短く、Claude が知らないことだけ書く**（5章）
7. **大事な作業の前に Git で保存**（3-5）。巻き戻し（`/rewind`）だけに頼らない
8. **絶対のルールはフックや権限設定で**（4章・7章）。CLAUDE.md の「お願い」だけに頼らない
9. **秘密情報（パスワード・APIキー）を会話に貼らない**。`.env` は `deny` で読ませない（4章）。お客様の個人情報も必要最小限だけ扱わせる
10. **最後は人が確認する**。特に公開・送信・削除・支払いに関わる作業は、内容を見てから実行させる
