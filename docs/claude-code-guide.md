## 1. Claude Code とは

Claude Code は、Anthropic 社の AI「Claude」が **あなたのパソコンのファイルを読み、編集し、コマンドを実行して、作業を最後までやり切ってくれる道具** です。

ふつうのチャット AI との違いは次のとおりです。

| | チャット AI（claude.ai など） | Claude Code |
|---|---|---|
| ファイル | 自分でコピペして渡す | **自分でフォルダの中を探して読む** |
| 作業 | 答えを教えてくれる | **実際にファイルを書き換え、コマンドを実行する** |
| 確認 | 自分で試す | **自分でテストを動かし、失敗したら直す** |
| 向いていること | 相談・文章作成 | アプリ・サイト作り、データ整理、自動化、ドキュメント整備など「手を動かす仕事」 |

「プログラマー向け」と思われがちですが、**フォルダの中のファイルを扱う仕事なら何でも任せられます**。たとえば次のような使い方です。

- ホームページや LP（ランディングページ）を作る・直す
- CSV の売上データを集計してグラフ付きのレポートにする
- 大量の文章ファイルの表記ゆれをまとめて直す
- 毎朝の情報収集を自動化する
- 自分専用の業務ツール（家計簿、タスク管理など）を作る

### どこで使えるか

中身は同じ Claude Code で、使う場所（画面）が選べます。設定ファイルや CLAUDE.md（5章）はどこでも共通です。

| 使う場所 | 特徴 |
|---|---|
| **ターミナル（CLI）** | 基本の形。黒い画面に文字で指示する。機能がいちばん揃っている |
| **デスクトップアプリ** | Mac / Windows 用のアプリ。画面で操作できて初心者にやさしい（有料プランが必要） |
| **Web（claude.ai/code）** | ブラウザから使う。クラウド上で動くので、パソコンを閉じても作業が続く |
| **スマホ（Claude アプリ）** | 外出先から指示・確認ができる |
| **VS Code / JetBrains** | プログラミング用エディタの中で使う |
| **GitHub Actions など** | GitHub 上で `@claude` と書くと自動で作業する（10章） |

### 必要なもの

- **有料プラン**: Pro / Max / Team / Enterprise などの Claude のサブスクリプション（おすすめ）、または Claude Console（API）のアカウント
- 無料プランでは Claude Code は使えません

### 用語ミニ解説

| 用語 | 意味 |
|---|---|
| ターミナル | 文字でパソコンに命令する画面。Mac は「ターミナル」、Windows は「PowerShell」など |
| コマンド | ターミナルに打ち込む命令文（例: `cd`, `ls`） |
| プロジェクト | 作業対象のフォルダ。Claude Code は基本的に「今いるフォルダ」の中で働く |
| セッション | Claude Code を起動してから終了するまでの1回分の会話 |
| コンテキスト | AI がその会話で覚えていられる情報。量に上限があり、いっぱいになると古い内容が要約される |
| トークン | AI が文章を数える単位。料金や上限の計算に使われる |
| Git（ギット） | ファイルの変更履歴を記録する仕組み。失敗しても前の状態に戻せる |
| スラッシュコマンド | Claude Code の中で `/` から始めて入力する命令（例: `/clear`） |

## 2. はじめての Claude Code（15分チュートリアル）

### 手順1：インストールする

ターミナルを開き、使っているパソコンに合わせて1行だけ実行します。

**Mac / Linux（Windows の WSL も）**

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

**Windows（PowerShell）**

```powershell
irm https://claude.ai/install.ps1 | iex
```

> Mac で Homebrew を使っている人は `brew install --cask claude-code` でも入れられます（この場合は自動更新されないので、ときどき `brew upgrade claude-code` を実行します）。

入ったか確認します。バージョン番号が表示されれば成功です。

```bash
claude --version
```

> **画面操作が好みなら**: デスクトップアプリや Web（claude.ai/code）から始めることもできます。この資料の内容はほぼそのまま当てはまります。

### 手順2：作業用フォルダを作って起動する

```bash
mkdir my-first-project   # フォルダを作る
cd my-first-project      # そのフォルダに移動する
claude                   # Claude Code を起動する
```

初めての起動ではブラウザが開き、ログインを求められます。Claude のアカウントでログインしてください。

### 手順3：最初のお願いをする

画面の入力欄に、日本語でそのまま書きます。

```text
自己紹介用のシンプルな1ページのホームページを index.html に作って。
名前は「山田花子」、仕事は「Webデザイナー」、連絡先ボタンも付けて。スマホでも見やすくして。
```

すると Claude は次のように動きます。

1. 何を作るか考える
2. ファイルを作ってよいか **確認を求めてくる**（「Yes」を選ぶ）
3. `index.html` を作って、何をしたか報告する

できた `index.html` をダブルクリックすると、ブラウザで見られます。

### 手順4：直してもらう

```text
背景を淡いベージュにして、名前の文字をもっと大きくして
```

このように **会話しながら少しずつ直していく** のが基本の使い方です。

### 手順5：終了する

`/exit` と入力するか、`Ctrl + C` を2回押します。次回、同じフォルダで続きから始めたいときは次のように起動します。

```bash
claude -c   # 前回の会話の続きから
```

### うまくいかない時

| 症状 | 対処 |
|---|---|
| `claude: command not found` と出る | ターミナルを一度閉じて開き直す。それでもだめなら `claude doctor` ではなくインストールをやり直す |
| ログインできない | 無料プランでは使えない。プランを確認する。別アカウントに切り替えるには `/login` |
| 何か調子がおかしい | Claude Code の中で `/doctor` を実行すると、設定や環境の問題を診断してくれる |

## 3. 基本の使い方

### 3-1. 指示の出し方

Claude Code には **ふつうの日本語で頼めば大丈夫** です。ただ、次の4点を入れると結果がぐっと良くなります。

| 入れること | 悪い例 | 良い例 |
|---|---|---|
| **目的** | 「直して」 | 「問い合わせフォームの送信ボタンが反応しないので直して」 |
| **場所** | 「グラフを作って」 | 「`data/sales.csv` から月別売上のグラフを作って」 |
| **条件** | 「きれいにして」 | 「色は青系、スマホでも崩れないように」 |
| **確認方法** | （なし） | 「直したらブラウザで開いて動作を確認して」 |

**特に大事なのは「確認方法」です**。Claude が自分で結果を確かめられると、間違いに気づいて自分で直してくれます。

### 3-2. ファイルを指定する（`@`）

`@` を入力すると、ファイル名の候補が出ます。ファイルを指定すると、Claude はその中身を読んでから作業します。

```text
@docs/proposal.md の誤字を直して、もっと読みやすくして
```

### 3-3. 画像を見せる

スクリーンショットやデザインの画像を見せられます。

- 画像ファイルを入力欄に **ドラッグ＆ドロップ**
- コピーした画像を **`Ctrl + V`** で貼り付け（Windows は `Alt + V`）

```text
（画像を貼り付けて）このデザインと同じ見た目にして
```

### 3-4. 止める・やり直す

| やりたいこと | 操作 |
|---|---|
| Claude の作業を **途中で止める** | `Esc` を押す（止めたあと、指示を言い直せる） |
| **前の状態に巻き戻す** | 入力欄が空の状態で `Esc` を2回押す、または `/rewind` |
| 会話を **リセット** する | `/clear` |

`/rewind` では「コードも会話も戻す」「会話だけ戻す」「コードだけ戻す」などを選べます。ただし、コマンド実行で変わったファイルなどは戻らないことがあるので、**大事な作業は Git でも記録しておく** と安心です。

### 3-5. コマンドを自分で実行する（`!`）

入力の先頭に `!` を付けると、そのままターミナルのコマンドとして実行され、結果が会話に入ります。

```text
! ls
```

### 3-6. 会話の続きから始める

| やりたいこと | コマンド |
|---|---|
| 前回の続きから始める | `claude -c` |
| 過去の会話を選んで再開する | `claude --resume`（または Claude Code の中で `/resume`） |
| 会話に名前を付ける | Claude Code の中で `/rename` |

## 4. 権限モード：Claude にどこまで任せるか

Claude Code は、ファイルの編集やコマンドの実行の前に **「やってもいいですか？」と確認** してきます。この確認の度合いを **権限モード** で切り替えられます。

**`Shift + Tab` を押すたびにモードが切り替わります**（画面の下に今のモードが表示されます）。

| モード | 動き | 向いている場面 |
|---|---|---|
| **default（通常）** | 編集やコマンドのたびに確認する | 慣れないうち、大事なファイルを扱う時 |
| **acceptEdits（編集は自動）** | ファイル編集は確認なしで進める | 作業を任せてテンポよく進めたい時 |
| **plan（計画モード）** | **読むだけ**。編集せずに計画を立てて見せてくれる | 大きな作業の前、何をするか先に確認したい時 |
| **auto（自動）** | 安全かどうかを AI が判断し、危なそうな時だけ確認する | 慣れてきて、任せる範囲を広げたい時 |
| dontAsk / bypassPermissions | 確認をしない（上級者向け） | 隔離された環境での自動実行のみ。**普段は使わない** |

> 利用環境やバージョンによって、最初のモードや選べるモードは異なります。今のモードは画面の下で確認してください。

### おすすめの進め方：「まず計画、それから実行」

大きめの作業は、いきなり始めさせずに **plan モードで計画を立てさせる** と失敗が減ります。

1. `Shift + Tab` で plan モードにする
2. 「会員登録機能を追加したい。どう進めるか計画を立てて」と頼む
3. 出てきた計画を読んで、気になる点を直してもらう
4. 計画に納得したら承認して実行させる

### よく使う操作を「毎回確認しない」ようにする

確認画面で「今後は確認しない」を選ぶと、そのコマンドは次から自動で許可されます。設定ファイル（8章）にまとめて書くこともできます。

```json
{
  "permissions": {
    "allow": ["Bash(npm run test *)"],
    "deny": ["Read(./.env)", "Bash(git push *)"]
  }
}
```

- `allow` は確認なしで許可、`deny` は禁止です。**deny が常に優先** されます。
- 上の例は「テストの実行は自動で許可」「パスワードなどが入った `.env` ファイルは読ませない」「GitHub への送信（push）は禁止」という意味です。

## 5. CLAUDE.md：Claude に覚えておいてほしいことを書く

Claude Code は会話が終わると内容を忘れます。毎回同じ説明をしなくて済むように、**プロジェクトのルールや前提を書いておくファイル** が `CLAUDE.md` です。起動するたびに自動で読み込まれます。

### 作り方

Claude Code の中で次を実行すると、フォルダの中身を調べて下書きを作ってくれます。

```text
/init
```

あとは自分で書き足したり、「CLAUDE.md に『〜』というルールを追加して」と頼んだりして育てていきます。

### 書く内容の例

```markdown
# このプロジェクトについて
- 個人事業のホームページ。お客様は30〜50代の女性が中心

# ルール
- 文章は「です・ます」調で、専門用語を使わない
- 色はブランドカラーの #2E7D6B を基準にする
- 画像は images/ フォルダに入れる

# 確認方法
- 変更したら index.html をブラウザで開いて、スマホ幅でも崩れていないか確認する
```

### 置き場所

| ファイル | 効く範囲 | 用途 |
|---|---|---|
| `~/.claude/CLAUDE.md` | 自分の全プロジェクト | 「日本語で答えて」など、自分の好み |
| `./CLAUDE.md`（プロジェクトのフォルダ） | そのプロジェクト | プロジェクトのルール。チームで共有する |
| `./CLAUDE.local.md` | そのプロジェクト・自分だけ | 共有したくない個人メモ |

### 書くときのコツ

- **短く保つ**（公式の目安は1ファイル200行以内）。長すぎると守られにくくなり、毎回のコンテキストも圧迫します
- 「Claude が見ただけでは分からないこと」を書く（お客様像、ブランドのルール、確認の手順など）
- 別のファイルを読み込ませたい時は `@ファイル名` と書けます（例: `@docs/brand-guide.md`）
- 中身の確認・編集は `/memory` からもできます

> Claude Code には、作業中に気づいたことを Claude 自身がメモしておく **自動メモリ** 機能もあります。`/memory` でオン・オフや中身を確認できます。

## 6. コンテキストとコストの上手な管理

Claude Code の利用量は、プランごとに **一定時間あたり・1週間あたりの上限** があります（API 利用の場合は使った分だけ課金）。会話が長くなるほど、1回のやり取りで消費する量も増えます。

### 覚えておきたい4つのコマンド

| コマンド | 何をするか | いつ使うか |
|---|---|---|
| `/clear` | 会話をリセットする | **別の作業に移る時**（いちばん効果的） |
| `/compact` | これまでの会話を要約して軽くする | 同じ作業を続けたいが会話が長くなった時 |
| `/context` | 今どれくらいコンテキストを使っているか表示する | 重くなってきた気がする時 |
| `/usage` | 利用量・上限の状況を表示する | 使いすぎていないか確認したい時 |

### 節約のコツ

1. **作業が変わったら `/clear`**。前の話が残っていると、無駄に読み返す量が増えます
2. **2回直してもうまくいかない時は、`/clear` して指示を書き直す**。同じ会話で何度も直させるより早いことが多いです
3. **CLAUDE.md は短く**。毎回読み込まれるので、長いと毎回コストがかかります
4. **簡単な作業は軽いモデルで**（次の節）
5. **大量の調べものはサブエージェントに任せる**（9章）。途中経過がメインの会話に溜まりません
6. **使わない MCP サーバーやプラグインは切る**（7章）。有効なだけで毎回少しずつ消費します

### モデルと「考える深さ」を選ぶ

`/model` で使う AI のモデルを切り替えられます。

| モデル | 特徴 | 向いている作業 |
|---|---|---|
| **Opus** | 最も賢い。標準のモデル | 難しい設計、複雑な不具合、大きな作業 |
| **Sonnet** | 賢さと速さのバランスが良い | 日常的な作業の多く |
| **Haiku** | 速くて軽い | 簡単な修正、単純な調べもの |

また `/effort` で **考える深さ**（`low` / `medium` / `high` / `xhigh` / `max`）を変えられます。深くするほど丁寧になりますが、時間と利用量も増えます。迷ったら標準のままで構いません。

## 7. 機能を広げる：拡張機能の全体像

Claude Code には、自分の仕事に合わせて「育てる」ための仕組みがいくつかあります。最初は全部覚える必要はありません。**困ったことが出てきたら、対応する機能を使う** くらいで十分です。

| こんな時は | 使う機能 | ひとことで |
|---|---|---|
| 毎回同じ説明をしている | **CLAUDE.md**（5章） | 常に覚えておいてほしいこと |
| 決まった手順の作業を何度も頼む | **スキル** | 手順書。`/名前` で呼び出せる |
| 専門の担当者に任せたい／会話を散らかしたくない | **サブエージェント** | 専門の助手（9章） |
| 「必ず〜する」「絶対〜させない」を徹底したい | **フック** | 決まったタイミングで自動実行される処理 |
| Notion・Slack・GitHub などの外部サービスとつなぎたい | **MCP** | 外部サービスとの接続口 |
| 上の機能をまとめて入れたい・配りたい | **プラグイン** | 機能の詰め合わせパック |

### 7-1. スキル：よく使う手順を登録する

決まった手順を書いたファイルを置いておくと、`/名前` で呼び出せます。Claude が必要だと判断して自動で使うこともあります。

`.claude/skills/weekly-report/SKILL.md`

```markdown
---
name: weekly-report
description: 今週の売上データから週次レポートを作る。「週報」「週次レポート」と言われたら使う。
---

1. data/ フォルダの今週分の CSV を読む
2. 売上合計・前週比・よく売れた商品トップ5を計算する
3. reports/ フォルダに「YYYY-MM-DD_週報.md」として保存する
4. 気になる変化があれば、最後に3行でコメントする
```

使い方:

```text
/weekly-report
```

- 自分の全プロジェクトで使うなら `~/.claude/skills/<名前>/SKILL.md`、そのプロジェクトだけなら `.claude/skills/<名前>/SKILL.md` に置きます
- 以前からある `.claude/commands/` に置く「カスタムコマンド」も引き続き使えます（今はスキルと統合されています）

### 7-2. フック：決まったタイミングで必ず実行する

CLAUDE.md に書いたルールは「お願い」なので、守られないこともあります。**絶対に守らせたい** ことはフックにします。たとえば「ファイルを編集したら必ず整形ツールを実行する」「特定のコマンドは実行させない」などです。

- 設定ファイル（8章）の `hooks` に書きます。`/hooks` で確認できます
- 主なタイミング: ツール実行の前（`PreToolUse`）・後（`PostToolUse`）、作業が終わった時（`Stop`）、セッション開始時（`SessionStart`）など

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command", "command": "npx prettier --write ." }]
      }
    ]
  }
}
```

（ファイルを編集・作成するたびに、整形ツール Prettier を実行する例）

> フックは自動でコマンドを実行する強力な機能です。内容を理解したものだけを設定してください。

### 7-3. MCP：外部サービスとつなぐ

MCP を使うと、Claude Code から GitHub・Notion・ブラウザ操作などの機能を使えるようになります。ターミナルで次のように追加します。

```bash
# Web 上の MCP サーバーを追加する例
claude mcp add --transport http <名前> <サーバーのURL>

# 追加済みの一覧を見る / 削除する
claude mcp list
claude mcp remove <名前>
```

- Claude Code の中で `/mcp` を開くと、接続状況の確認やログインができます
- `--scope project` を付けると `.mcp.json` に保存され、チームで共有できます
- **信頼できる提供元のものだけを使ってください**。外部サービスにデータが送られます

### 7-4. プラグイン：まとめて入れる

スキル・サブエージェント・フック・MCP をまとめたパックです。Claude Code の中で `/plugin` を開くと、公式のマーケットプレイスなどから探してインストールできます。入れたら `/reload-plugins` で反映されます。

---

## 8. 設定ファイル（settings.json）

権限・フック・使うモデルなどは JSON 形式の設定ファイルに書きます。普段は `/config`（設定画面）や、確認画面での選択で自動的に書き込まれるので、**直接編集するのは慣れてからで大丈夫** です。

| ファイル | 効く範囲 | Git で共有 |
|---|---|---|
| `~/.claude/settings.json` | 自分の全プロジェクト | しない |
| `.claude/settings.json` | そのプロジェクト | **する**（チームで同じ設定に） |
| `.claude/settings.local.json` | そのプロジェクト・自分だけ | しない（自動で除外される） |

- 同じ項目が複数の場所にあると、**よりプロジェクトに近い方（local → プロジェクト → ユーザーの順）が優先** されます。会社などで管理者が配布する設定は、さらに上位です
- `permissions.allow` などのリストは、上書きではなく **足し合わされます**
- JSON なのでコメント（`//`）は書けません
- どの設定が効いているかは `/status` で確認できます

---

## 9. サブエージェント：専門の助手に任せる

サブエージェントは、**メインの会話とは別のコンテキストで動く専門の助手** です。調べものの途中経過はメインの会話に入らず、**結果の要約だけが戻ってくる** ので、会話が散らからず、利用量の節約にもなります。

```text
サブエージェントを使って、このフォルダの中で古い料金表が残っているページを全部探して
```

- 「Explore（調査担当）」など、最初から入っているサブエージェントがあり、Claude が必要に応じて自動で使います
- `.claude/agents/` に Markdown ファイルを置くと、自分専用の助手（校正担当、市場調査担当など）を作れます

> 作り方や実例は、別資料 **[Claude Code サブエージェント入門ガイド](./claude-code-subagents.md)** で詳しく解説しています。

## 10. 一歩進んだ使い方

### 10-1. 非対話モード（`-p`）で自動化する

`-p` を付けると、1回だけ質問して答えを受け取り、すぐ終了します。決まった作業を自動化したい時に便利です。

```bash
claude -p "data/sales.csv を集計して、今月の売上合計だけを答えて"

# 他のコマンドの結果を渡すこともできる
cat report.txt | claude -p "この文章を3行で要約して"
```

### 10-2. 複数の作業を並行する

- **ターミナルを複数開いて**、それぞれで Claude Code を動かせます
- 同じフォルダで同時に作業させるとぶつかるので、`claude --worktree <名前>`（または `-w`）を使うと、作業用の別コピーの中で動かせます
- 時間のかかるコマンドは `Ctrl + B` でバックグラウンドに回せます

### 10-3. クラウドで動かす（Web・スマホ）

claude.ai/code やスマホの Claude アプリから始めた作業は、Anthropic のクラウド上で動きます。

- **パソコンを閉じても作業が続く**ので、外出前に頼んでおいて、あとで結果を見る使い方ができます
- ターミナルから `claude --cloud "〜を直して"` でクラウドに任せることもできます
- クラウドの作業を手元に持ってくるには `/teleport`
- 定期的に動かしたい作業は `/schedule` で予約できます（例: 毎朝のニュースまとめ）

### 10-4. GitHub と連携する

- Claude Code の中で `/install-github-app` を実行すると、GitHub との連携を設定できます
- 設定後は、GitHub の Issue やプルリクエストのコメントに `@claude` と書くだけで、Claude が作業してくれます
- 「変更内容をコミットして」「プルリクエストを作って」と頼むだけで Git の操作もしてくれます

## 12. 上手に使うための10か条

1. **目的・場所・条件・確認方法** を伝える（3-1）
2. **確認方法を渡す**。テストやブラウザでの確認を Claude 自身にさせると、品質が大きく上がる
3. **大きな作業は plan モードで計画から**（4章）
4. **別の作業に移ったら `/clear`**（6章）
5. **2回直してだめなら、指示を書き直してやり直す**
6. **CLAUDE.md は短く、Claude が知らないことだけ書く**（5章）
7. **大事な作業の前に Git で保存**。巻き戻し（`/rewind`）だけに頼らない
8. **絶対のルールはフックや権限設定で**（4章・7章）。CLAUDE.md の「お願い」だけに頼らない
9. **秘密情報（パスワード・APIキー）を会話に貼らない**。`.env` は `deny` で読ませない
10. **最後は人が確認する**。特に公開・送信・削除・支払いに関わる作業は、内容を見てから実行させる
