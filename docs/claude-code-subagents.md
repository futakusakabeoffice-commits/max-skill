# Claude Code サブエージェント入門ガイド

- **対象**: Claude Code を使い始めた人〜日常的に使っている人（エンジニアでなくても読めるように書いています）
- **情報の基準**: 公式ドキュメント「Subagents」 https://code.claude.com/docs/en/sub-agents （2026年11月時点）
- **注意**: Claude Code は更新が速いため、細かい仕様はバージョンで変わります。迷ったら公式ドキュメントを確認してください。

### この資料の読み方

| 目的 | 読むところ |
|---|---|
| まず仕組みを知りたい | 1章 |
| とにかく1つ作って動かしたい | **2章（5分チュートリアル）** |
| 実務で使える形を知りたい | 3〜7章 |
| 設定項目を細かく調べたい | 8〜9章（上級者向け・最初は飛ばしてOK） |

## 1. サブエージェントとは

サブエージェントは、Claude Code（メインの会話）が仕事の一部を任せる **「専門の助手」** のようなものです。それぞれのサブエージェントには次の特徴があります。

- **自分専用のコンテキスト**（その会話で覚えている内容）で動く
- **専用のシステムプロンプト**（役割ややり方を書いた指示書）を持つ
- **使えるツール**（ファイルを読む・書く、コマンドを実行する など）を絞れる
- **使うモデルや権限を個別に設定**できる

いちばん大事な性質は、**サブエージェントが途中で読んだファイルや試行錯誤はメインの会話に入らず、最終報告だけが戻ってくる** ことです。

```text
あなた ──▶ メインの Claude
              │  「このバグの原因を調べて」
              ▼
         サブエージェント（別のコンテキスト）
           ・ファイルを50個読む
           ・テストを何度も実行
              │
              ▼  「原因は auth.ts の42行目。理由は〜」（要約だけ）
         メインの Claude（会話はスッキリしたまま）
```

### 使うメリット

| メリット | 内容 |
|---|---|
| コンテキストを節約できる | 大量の検索結果やログをメインの会話に溜めない。長い作業でも会話が散らからない |
| 制約を確実に守らせられる | 「読むだけ」「編集はさせない」をツール設定で強制できる |
| 使い回せる | 一度作れば、全プロジェクトで（チームがいれば全員で）同じサブエージェントを使える |
| 出力の質が安定する | 役割を1つに絞った指示を書けるので、毎回同じ観点・同じ形式で返ってくる |
| コストを調整できる | 簡単な作業は Haiku など速くて安いモデルに任せられる |

> **注意**: サブエージェントの利用も、メインの会話と同じ利用上限にカウントされます。「無料で並列に働いてくれる」わけではありません。

### 使うべき時・使わない方がいい時

| サブエージェント向き | メインの会話向き |
|---|---|
| 結果の要約だけ欲しい調査（大量のファイル検索、ログ解析） | 何度もやり取りしながら詰める作業 |
| ツールを制限して安全にやらせたい作業 | それまでの話の流れを強く引き継ぐ作業 |
| それ単体で完結するタスク（レビュー、テスト実行など） | 1〜2行の小さな修正 |
| 互いに独立した作業を並行させたい時 | すぐ返事が欲しい作業（サブエージェントは文脈ゼロから読み直すぶん時間がかかる） |

### 用語ミニ解説

| 用語 | 意味 |
|---|---|
| コンテキスト | AI がその会話で覚えていられる情報の量・中身。いっぱいになると古い内容が要約・圧縮される |
| トークン | AI が文章を数える単位。日本語ならおおよそ1〜2文字で1トークン |
| システムプロンプト | AI に最初に渡す「あなたは〇〇です。こう動いてください」という指示書 |
| フロントマター | Markdown ファイル冒頭の `---` で囲んだ設定欄。YAML という書式で書く |
| MCP | Claude に外部サービス（GitHub、ブラウザなど）の機能を追加する仕組み |
| フック | 「ツールを使う直前にこのスクリプトを実行する」など、決まったタイミングで自動実行される処理 |
| 親・継承 | 「親」はサブエージェントを呼び出した側（ふつうはメインの会話）。「継承」は親と同じ設定を引き継ぐこと |
| セッション | Claude Code を起動してから終了するまでの1回分の会話 |
| スキル | よく使う手順や知識をまとめた指示ファイル。必要な時に Claude が読み込む |
| プラグイン | サブエージェントやスキルなどをまとめて配布する拡張パック |
| 環境変数 | Claude Code を起動する前にターミナルで設定しておく値（上級者向け） |

## 2. 5分チュートリアル：最初のサブエージェントを作る

ここでは「文章を校正するサブエージェント」を作ります。コードを書かない人でもすぐ試せます。

### 手順1：フォルダを作る

作業中のプロジェクトのフォルダで、次を実行します（Claude に「`.claude/agents` フォルダを作って」と頼んでもOK）。

```bash
mkdir -p .claude/agents
```

> 全プロジェクトで使いたい場合は、代わりに自分のホームフォルダに作ります（`mkdir -p ~/.claude/agents`）。一人で使うならこちらでも構いません。両方に同じ `name` があるとプロジェクト側（`.claude/agents/`）が優先されます（詳しくは8章）。

### 手順2：ファイルを1つ保存する

`.claude/agents/proofreader.md` という名前で、次の内容を保存します。

> **保存のしかた**: VS Code などのエディタで保存するか、Claude に「この内容で `.claude/agents/proofreader.md` を作って」と貼り付けて頼むのが簡単です。Mac の「テキストエディット」はリッチテキスト形式になりやすいので避けましょう。

```markdown
---
name: proofreader
description: ブログ記事・LP・SNS投稿などの日本語の文章を校正する専門家。文章の下書きができたら積極的に使う（use proactively）。
tools: Read, Grep, Glob
model: sonnet
---

あなたは日本語の校正・編集の専門家です。
指定されたファイルを読み、次の観点で問題点を探してください。

1. 誤字・脱字・変換ミス
2. 表記の揺れ（例: 「サーバー」と「サーバ」、「出来る」と「できる」）
3. 意味が二通りに取れる文、長すぎる文
4. 読者に伝わりにくい専門用語

報告の形式:
- 問題ごとに「場所（何行目あたり）」「元の文」「修正案」「理由」を書く
- 重要なものから順に並べる
- 最後に全体の印象を3行以内でまとめる

ファイルは編集せず、提案だけを返してください。
```

上の `---` で囲んだ部分が **設定**、その下の本文が **このサブエージェントへの指示書（システムプロンプト）** です。

### 手順3：使ってみる

Claude Code を開いて、こう頼みます。

```text
proofreader サブエージェントを使って、drafts/blog-01.md を校正して
```

`drafts/blog-01.md` は、自分が校正したいファイル名に置き換えてください。試すファイルがなければ、先に Claude に「テスト用の短いブログ下書きを drafts/blog-01.md に作って」と頼みましょう。

### 手順4：動いたか確認する

- 実行中は、サブエージェントが動いていることが画面に表示されます（表示の形はバージョンや利用環境で異なります）。
- 終わると、メインの会話には **サブエージェントからの校正結果の報告** が戻ってきます。途中で読んだファイルの中身などは戻ってきません。

### うまく動かない時

- **ファイルの場所と名前**を確認する（`.claude/agents/` の中に `.md` で保存されているか）
- **`name` の綴り**と、頼むときの名前が一致しているか確認する
- 先頭の `---` から2つ目の `---` までの書式が崩れていないか確認する
- Claude Code を一度終了して起動し直す
- それでもだめなら7章「よくあるつまずき」へ

> **自分で書かなくてもOK**: Claude に「ブログ記事を校正するサブエージェントを `.claude/agents/` に作って」と頼めば、ファイルごと作ってくれます。なお `/agents` と入力すると、現在のバージョンでは「Claude に頼むか、フォルダのファイルを直接編集してください」という案内が出ます（古いバージョンでは一覧・作成用の管理画面が開きます）。

## 3. 最初から入っている（組み込み）サブエージェント

自分で作らなくても、Claude Code には次のサブエージェントが用意されていて、Claude が必要に応じて自動で使います。**最初は「Explore」と「general-purpose」の2つを知っていれば十分** です。

| 名前 | 何をするか | 使えるツール | モデル |
|---|---|---|---|
| **Explore** | コードやファイルの高速検索・調査。調べる深さを `quick` / `medium` / `very thorough` から選ぶ | 読み取り専用（編集不可） | メインと同じ ※ |
| **general-purpose** | 調べて、実際に手も動かす複数ステップの作業 | サブエージェントが使える全ツール | メインと同じ |
| **Plan** | プランモード（実行前に計画だけ立てるモード）中の調査 | 読み取り専用（編集不可） | メインと同じ |
| **claude** | 他に当てはまらない作業の受け皿 | サブエージェントが使える全ツール | 9-2 のモデル決定順に従う |
| **claude-code-guide** | Claude Code の使い方の質問に、公式ドキュメントを調べて答える | 検索・閲覧のみ | Haiku |
| **web-fetch** | Web ページを読んで内容を答える | Web ページの取得のみ | Haiku（使えない場合はメインと同じ） |
| **statusline-setup** | `/statusline`（画面下部の情報表示）の設定 | 設定ファイルの読み書き | Sonnet |

※ 接続方法によっては別のモデルになる場合があります。

> 自分で同じ名前（例: `Explore`）のサブエージェントを作ると、組み込みのものより優先されます。

## 4. サブエージェントの呼び出し方

| 方法 | やり方 | 向いている場面 |
|---|---|---|
| **自動で任せる** | 何もしない。Claude が `description` を読んで判断する | 普段使い |
| **言葉で指名** | 「proofreader サブエージェントを使って〜して」 | 確実にそのサブエージェントを使わせたい |
| **@メンション** | `@` を入力して一覧から選ぶ（`@"proofreader (agent)"` のように入る）、または `@agent-<名前>` と書く（プラグインのものは `@agent-<プラグイン名>:<名前>`） | 素早く指名したい |
| **セッション全体をそのサブエージェントで** | `claude --agent proofreader` で起動、または `.claude/settings.json` に `"agent": "proofreader"` と書く（両方あれば起動時の指定が優先） | 会話全体をその役割で進めたい |

### 自動で任せてもらうコツ：`description` の書き方

自動で使われるかどうかは **`description` の書き方でほぼ決まります**。

- ❌ 悪い例: `コードレビュー`
- ✅ 良い例: `コードの品質・安全性・保守性をレビューする専門家。コードを書いたり変更したりした直後に積極的に使う（use proactively）。`

コツは3つです。

1. **何をするか** だけでなく **どんな時に使うか** を書く
2. 公式ドキュメントで紹介されている英語の `use proactively` を日本語と併記しておくと確実
3. 他のサブエージェントと役割がかぶらないように書く

## 5. すぐ使える実例

すべて `.claude/agents/` に保存すれば使えます（自分専用にするなら `~/.claude/agents/`）。

### 例1：競合・市場の調べもの担当（ビジネス向け）

> この例は公式ドキュメントの例ではなく、この資料のオリジナルです。Web 検索・取得ツールがサブエージェントで使えるかは利用環境によるので、最初に一度試して確認してください。

`.claude/agents/market-researcher.md`

```markdown
---
name: market-researcher
description: 競合サービス・市場動向・料金相場などを Web で調べて要約する。新しい事業アイデアや商品を検討するときに積極的に使う（use proactively）。
tools: WebSearch, WebFetch, Read
model: haiku
color: green
---

あなたは市場調査の担当者です。

1. 依頼されたテーマについて、信頼できる情報源を複数調べる
2. 次の形式で、10行程度にまとめて報告する
   - 結論（ひとことで）
   - 主な競合とその特徴・料金
   - 狙えそうなすき間（チャンス）
   - 参考にした URL
3. 古い情報や確かでない情報は、そう明記する
```

### 例2：コードレビュー担当（基本は読むだけ。`git diff` のために Bash を許可）

`.claude/agents/code-reviewer.md`

```markdown
---
name: code-reviewer
description: コードの品質・安全性・保守性をレビューする専門家。コードを書いたり変更したりした直後に積極的に使う（use proactively）。
tools: Read, Grep, Glob, Bash
model: inherit
---

あなたは経験豊富なシニアエンジニアとしてコードレビューを行います。

呼ばれたら:
1. `git diff` を実行して最近の変更を確認する
2. 変更されたファイルに集中してレビューする

チェック項目:
- 読みやすさ（名前の付け方、重複がないか）
- エラー処理
- 秘密情報（API キーなど）が含まれていないか
- 入力チェック
- テストがあるか

結果は重要度順に、次の3段階で報告する:
- 🔴 必ず直す（重大）
- 🟡 直した方がよい（警告）
- 🟢 検討してほしい（提案）

それぞれ、具体的な直し方の例を付けること。ファイルは編集しないこと。
```

> **注意**: `Write`・`Edit` を外していても、`Bash` があればコマンド経由でファイルを変更できてしまいます。完全に読み取り専用にしたいなら `Bash` も外すか、例4のようにフックで制限します。

### 例3：デバッグ担当（原因を調べて直すところまで）

`.claude/agents/debugger.md`

```markdown
---
name: debugger
description: エラー・テスト失敗・想定外の動作の原因を調べて直す専門家。問題が起きたら積極的に使う（use proactively）。
tools: Read, Edit, Bash, Grep, Glob
---

あなたは根本原因の分析が得意なデバッグの専門家です。

1. エラーメッセージと、エラーが起きた場所の記録（スタックトレース）を確認する
2. 再現手順を特定する
3. 失敗している場所を絞り込む
4. 最小限の修正を入れる
5. 直ったことを確認する

報告には、根本原因・その根拠・修正内容・確認方法・再発防止の提案を含めること。
症状だけを隠す修正はしない。
```

`model` を省略しているので、メインの会話と同じモデルで動きます。

### 例4：データベースを読み取り専用で調べる担当（フックで制限）

`tools` では「Bash は使ってよいが、書き込み系の SQL は禁止」のような細かい制限はできません。そういう時は **フック** を使います。

`.claude/agents/db-reader.md`

```markdown
---
name: db-reader
description: データベースに読み取り専用のクエリを実行して分析する。売上や会員数などのデータを調べたいときに使う。
tools: Bash
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "\"${CLAUDE_PROJECT_DIR}\"/scripts/validate-readonly-query.sh"
---

あなたはデータ分析担当です。SELECT 文だけを使ってデータを調べ、結果を分かりやすくまとめてください。
```

`scripts/validate-readonly-query.sh`

```bash
#!/bin/bash
# jq がないとチェックが素通りになるので、その場合は安全側（ブロック）に倒す
command -v jq >/dev/null 2>&1 || { echo "jq が見つかりません。インストールしてください。" >&2; exit 2; }

# ツールの入力（JSON）は標準入力で渡される。jq でコマンド部分を取り出す
COMMAND=$(jq -r '.tool_input.command')

# 書き込み系の SQL キーワードが含まれていたらブロック
if printf '%s\n' "$COMMAND" | grep -qiwE '(INSERT|UPDATE|DELETE|DROP|CREATE|ALTER|TRUNCATE|REPLACE|MERGE|GRANT)'; then
  echo "書き込み系の操作はできません。SELECT を使ってください。" >&2
  exit 2   # 終了コード 2 = このツール実行をブロックし、理由を Claude に伝える
fi
exit 0
```

スクリプトを置いて、実行できるようにします。

```bash
mkdir -p scripts
# （上のスクリプトを scripts/validate-readonly-query.sh に保存してから）
chmod +x scripts/validate-readonly-query.sh
```

> - `jq`（JSON を扱うコマンド）が必要です。Mac なら `brew install jq` などで入れておきます。
> - これは **簡易チェック** です。`SELECT REPLACE(...)` のような関数や、`'DELETE'` という文字列を含む検索も止めてしまう一方、書き方によってはすり抜けることもあります。本当に守りたいなら、**読み取り権限しかないデータベースユーザー** で接続させるのが確実です。
> - フロントマターに書いたフックは、そのサブエージェントが動いている間だけ有効です。

## 6. 上手に使うためのチェックリスト

作ったサブエージェントを見直すときに使ってください。

- [ ] **役割は1つだけか**（「レビューもテストも文書作成も」になっていないか）
- [ ] **`description` に「いつ使うか」が書いてあるか**（他のサブエージェントとかぶっていないか）
- [ ] **ツールは必要最小限か**（読むだけの仕事なら `Read, Grep, Glob` だけ）
- [ ] **報告の形式と長さを指定しているか**（「結論と根拠を10行以内で」など。報告が長いと結局メインの会話を圧迫する）
- [ ] **依頼に必要な情報を書いているか**（サブエージェントはメインの会話を見ていない。目的・対象・完了条件を伝える）
- [ ] **守らせたいルールは念押ししているか**（CLAUDE.md のルールで特に大事なものは、依頼文やシステムプロンプトにも書く）
- [ ] **細かい禁止事項はフックにしたか**（`tools` で表現できない制限は `PreToolUse` フックで）
- [ ] **チームがいるなら共有したか**（`.claude/agents/` に置いて Git で管理）

## 7. よくあるつまずき

| 症状 | 原因と対策 |
|---|---|
| 作ったのに自動で使われない | `description` があいまい。「いつ使うか」と `use proactively` を書く。または名前で指名する |
| 設定が効いていない | 項目名の綴りミス。**知らない項目名はエラーにならず無視される**。例: `disallowed_tools` ではなく `disallowedTools` |
| 同じ名前なのに思った動きをしない | 優先順位の高い場所に同名の定義がある（8章の表）。`.claude/agents/` と `~/.claude/agents/` の両方を確認する |
| サブエージェントが前の話を知らない | 仕様通り。依頼に必要な文脈を書く（会話をまるごと引き継ぎたいなら9-5 の「フォーク」を使う） |
| メインの会話がすぐいっぱいになる | サブエージェントの報告が長すぎる。報告の長さを指定する |
| 「読むだけ」のはずがファイルが変わった | `Bash` が許可されている。外すかフックで制限する |
| `Concurrent subagent limit reached` と出る | 同時実行の上限（既定20個）に達している。終わるのを待つ |

## 8. 置き場所と優先順位

同じ `name` のサブエージェントが複数あると、**表の上にあるものが優先** されます。

| 優先度 | 置き場所 | 使える範囲 |
|---|---|---|
| 1（最優先） | 管理者による設定（組織で一括配布するもの） | 組織全体 |
| 2 | 起動時の `--agents` オプション | その起動中だけ |
| 3 | `.claude/agents/` | そのプロジェクト |
| 4 | `~/.claude/agents/` | 自分の全プロジェクト |
| 5 | プラグインの `agents/` フォルダ | プラグインを有効にした場所 |

- **一人で使うなら `~/.claude/agents/`**、**プロジェクト専用やチーム共有なら `.claude/agents/`**（Git にコミット）が基本です。
- フォルダの中のサブフォルダも読まれます。サブエージェントの識別は **ファイル名ではなく `name` 項目** で決まります。
- ファイルを追加・変更すると、基本的に再起動なしで反映されます。

### 起動時だけ使うサブエージェント（`--agents`）

ファイルを作らず、その起動の間だけ使うサブエージェントを JSON で渡せます（保存はされません）。`prompt` が Markdown の本文（システムプロンプト）に当たります。

```bash
# Mac / Linux のターミナル用（Windows の PowerShell では引用符の書き方が異なります）
claude --agents '{
  "code-reviewer": {
    "description": "コードレビューの専門家。コードを変更した後に積極的に使う。",
    "prompt": "あなたは熟練のコードレビュアーです。品質・安全性・ベストプラクティスに注目してください。",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  }
}'
```

## 9. 上級者向けリファレンス

### 9-1. 設定項目（フロントマター）

**必須は `name` と `description` の2つだけ** です。複数単語の項目名はキャメルケース（`disallowedTools` のように2語目以降の頭を大文字にする書き方）で書きます。

**よく使う項目**

| 項目 | 内容 | 例 |
|---|---|---|
| `name` | 識別名（必須）。重複不可。`:` は使えない（プラグイン用に予約） | `code-reviewer` |
| `description` | いつこのサブエージェントに任せるべきか（必須） | 4章を参照 |
| `tools` | 使ってよいツールの許可リスト。**省略すると、サブエージェントが使えるツールをすべて継承** | `Read, Grep, Glob` |
| `disallowedTools` | 使わせないツールの禁止リスト。`tools` と両方に書かれたツールは使えない | `Write, Edit` |
| `model` | `sonnet` / `opus` / `haiku` / `fable` / 完全なモデル ID / `inherit`（メインと同じ）。省略時もメインと同じ | `haiku` |
| `color` | 画面上の表示色。`red` / `blue` / `green` / `yellow` / `purple` / `orange` / `pink` / `cyan` | `cyan` |

**必要になったら使う項目**（最初は使わなくて大丈夫です）

| 項目 | 内容 |
|---|---|
| `permissionMode` | 権限の確認方法。`default`（毎回確認）/ `acceptEdits`（編集は自動で許可）/ `plan`（計画のみ）/ `auto` / `dontAsk` / `bypassPermissions`（確認なし・危険）など。`manual` は `default` の別名 |
| `maxTurns` | 最大ターン数。上限に達すると途中結果として返る |
| `skills` | 起動時に読み込ませるスキル（中身がまるごと渡される） |
| `mcpServers` | このサブエージェントだけが使う MCP サーバー（名前で参照、または直接定義） |
| `hooks` | このサブエージェントが動いている間だけ有効なフック |
| `memory` | 会話をまたいで覚えるメモ帳。`user` / `project` / `local` から選ぶ（公式は `project` を推奨） |
| `background` | `true` にすると常にバックグラウンドで動かす |
| `isolation` | `worktree` にすると、一時的な作業用コピー（git worktree）の中で動く。元の作業ファイルを汚さない |
| `effort` | 考える深さ。`low` / `medium` / `high` / `xhigh` / `max` |
| `omitClaudeMd` | `true` で CLAUDE.md を読み込ませない |
| `initialPrompt` | `--agent` でセッション全体として起動したときに、最初に自動で送る指示 |
| `autoCompactWindow` | 会話を自動で圧縮し始めるトークン数（100000 以上の整数。`200k` ではなく `200000` と書く）。v2.1.296 以降。`--agent` でセッション全体を任せている場合は効かない |

> プラグインに入っているサブエージェントでは、安全のため `permissionMode`・`hooks`・`mcpServers` は無視されます。

**ツール指定の書き方**（いずれか1つを選んで書きます。同じ項目を2回書かないこと）

```yaml
# パターンA: この4つだけ許可する
tools: Read, Grep, Glob, Bash
```

```yaml
# パターンB: 書き込み系だけ禁止し、他は継承する
disallowedTools: Write, Edit
```

```yaml
# パターンC: GitHub の MCP サーバーのツールだけ許可する（* は「すべて」の意味）
tools: mcp__github__*
```

```yaml
# パターンD: GitHub の MCP サーバーのツールをまとめて禁止する（サーバー名だけで指定）
disallowedTools: mcp__github
```

### 9-2. モデルが決まる順番

上から順に見て、最初に当てはまったものが使われます。

1. Claude が呼び出し時に指定したモデル
2. 定義ファイルの `model`（`inherit` を含む）
3. 環境変数 `CLAUDE_CODE_SUBAGENT_MODEL`
4. メインの会話のモデル（入れ子の場合は、呼び出し元のサブエージェントのモデル）

### 9-3. サブエージェントが最初に知っていること

通常のサブエージェントは **メインの会話の履歴を見られません**。起動時に渡されるのは主に次のものです。

- 自分のシステムプロンプト
- Claude からの依頼文
- CLAUDE.md（`omitClaudeMd: true` のときや、Explore など一部の組み込みでは渡されない）
- git の状態などの基本情報
- `skills` で指定したスキル

→ **依頼文に、目的・対象ファイル・完了条件・報告の形式を書き切ることが重要** です。

### 9-4. フォアグラウンドとバックグラウンド

| | フォアグラウンド | バックグラウンド |
|---|---|---|
| メインの会話 | 終わるまで待つ | 待たずに会話を続けられる |
| 権限の確認 | そのまま表示される | メイン画面に「どのサブエージェントからか」付きで表示される |

- どちらで動くかは Claude の判断や `background` 設定、利用環境によって変わります。
- 実行中のタスクは **Ctrl+B** でバックグラウンドに回せます。
- 確認画面で **Esc** を押すと、そのツール実行だけを拒否します（サブエージェント自体は止まりません）。

### 9-5. フォーク（会話をまるごと引き継ぐ分身）

通常のサブエージェントとは別に、**それまでの会話をまるごと引き継いだ分身（フォーク）** を作る仕組みもあります。

- フォークは親と同じ文脈を持つので、説明し直す必要がありません。Claude が自分の判断でフォークを使うこともあります。
- `/subtask <やること>` で、自分でフォークを始められます（例: `/subtask ここまでのパーサー変更の単体テストを書いて`）。
- フォークからさらにフォークは作れません。
- Claude が自分でフォークを始めないようにするには、設定の `permissions.deny` に `"Agent(fork)"` を入れます。フォーク機能そのものを切るには環境変数 `CLAUDE_CODE_FORK_SUBAGENT=0` を設定します。

### 9-6. 続きを頼む（再開）

- 呼び出すたびに、基本は **新しいサブエージェント** が作られます。
- 終わったサブエージェントには ID が付き、Claude は `SendMessage` ツールでその ID（または名前）宛てに **続きの仕事を頼めます**。それまでの記憶はそのまま残ります。
- 記録は `~/.claude/projects/{プロジェクト}/{セッションID}/subagents/` に保存され、設定 `cleanupPeriodDays`（既定30日）が過ぎると削除されます。

### 9-7. 入れ子・同時実行の上限と、無効化の方法

| やりたいこと | 方法 |
|---|---|
| 入れ子の深さを変える | 既定はメインの下3階層まで。環境変数 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` で変更（`1` で入れ子なし） |
| 特定のサブエージェントに他を呼ばせない | `tools` に `Agent` を入れない、または `disallowedTools` に `Agent` を入れる |
| 同時実行数を変える | 既定20個。環境変数 `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` で変更 |
| 特定のサブエージェントを使えなくする | 設定の `permissions.deny` に `"Agent(Explore)"` や `"Agent(my-agent)"` を書く |
| 全サブエージェントのモデルを強制する | `CLAUDE_CODE_SUBAGENT_MODEL` にモデル名、`CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` を設定（v2.1.257 以降。各定義の `model` は無視される） |

- 自作サブエージェント（組み込みを除く）の `description` の合計が約15,000トークンを超えると、起動時に警告が出ます。説明は簡潔に。

## 10. まとめ

- サブエージェントは **専用のコンテキスト・指示書・ツールを持つ専門の助手**。結果の要約だけが戻るので、メインの会話がきれいに保てる。
- 作り方は **Markdown ファイル1つ**。必須は `name` と `description` だけ。
- 置き場所は、自分用なら `~/.claude/agents/`、プロジェクト・チーム用なら `.claude/agents/`。
- 自動で使われるかは **`description` 次第**。ツールは最小限に、役割は1つに。
- まずは2章の校正サブエージェントを作って、動きを体験してみよう。
