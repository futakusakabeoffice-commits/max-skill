## 13-1 MCP とは

MCP（Model Context Protocol）は、**Claude Code を外部のサービスやツールとつなぐための共通の仕組み** です。コンセントの規格のようなもので、規格に合った「MCP サーバー」をつなぐと、Claude がそのサービスの機能を使えるようになります。

| つなぐもの | できるようになること（例） |
|---|---|
| GitHub | Issue（やることメモ）やプルリクエスト（変更の取り込み依頼）を読む・作る |
| ブラウザ操作（Playwright など） | Web ページを開いてクリックし、表示を確認する |
| Notion や Slack など | ページやメッセージを読む・書く（提供されている MCP サーバーによる） |

ふだんの Claude Code は、ブラウザに表示されたページを **自分の目で見ることはできません**。ブラウザ操作の MCP をつなぐと、さくらさんは「自分の講座サイトをブラウザで開いて、スマホ幅で表示崩れがないか見て」と頼めるようになります。

> **注意**: MCP サーバーをつなぐと、そのサービスに **データが送られたり、サービス上のデータが書き換えられたり** します。信頼できる提供元のものだけを使ってください（13-5）。

---

## 13-2 まずはプラグインから探すのが簡単

自分で MCP サーバーを設定するのは少し手間がかかります。**初心者は、まず `/plugin` で公式マーケットプレイスのプラグインを探す** のがおすすめです。MCP の接続が入ったプラグインもあります（13-4）。

自分で追加する必要があるとき（サービスの説明ページに「Claude Code での設定方法」が書いてあるときなど）は、13-3 の方法で追加します。

---

## 13-3 MCP サーバーを追加する

MCP サーバーの追加は、**ターミナル**（Claude Code を起動する前の画面）で `claude mcp` コマンドを使います。

### Web 上のサーバーを追加する（HTTP）

```bash
claude mcp add --transport http <名前> <サーバーのURL>
```

- `<名前>` は自分で付ける呼び名、`<サーバーのURL>` はサービスの説明ページに載っています。
- サービスによっては、API キー（合言葉）をヘッダーで渡す必要があります。

```bash
claude mcp add --transport http <名前> <サーバーのURL> --header "Authorization: Bearer <自分のAPIキー>"
```

> **注意**: API キーを人に見せたり、チャットに貼ったり、Git にコミットしたりしないでください（[第7章](07-safety.md)）。

### 自分のパソコンで動くサーバーを追加する（stdio）

ブラウザ操作用の Playwright のように、自分のパソコンの中で動かすタイプもあります。`--` の後ろに、サーバーを起動するコマンドを書きます。

```bash
claude mcp add --transport stdio playwright -- npx -y @playwright/mcp@latest
```

- この例には Node.js（プログラムを動かす土台ソフト）と、パソコンにブラウザ（Chrome など）が入っていることが必要です。
- Windows では、`npx` で動くサーバーを `cmd /c npx …` のように書かないと動かないことがあります。
- 環境変数（起動前に設定しておく値）を渡すときは、`--` より前に `--env 名前=値` を書きます。

### 確認・削除する

```bash
claude mcp list            # 追加済みの一覧
claude mcp get <名前>      # 1つの詳細
claude mcp remove <名前>   # 削除
```

> **注意**: `claude mcp get` では、`--header` で登録した API キーなどが **そのまま表示** されることがあります。画面共有中や、人に見られる場所では実行しないでください。

Claude Code の中では `/mcp` を開くと、接続の状態を確認したり、ログインが必要なサービスにログインしたりできます。

### どこに保存されるか（スコープ）

| 付けるオプション | 使える範囲 | 保存先 |
|---|---|---|
| （何も付けない） | そのプロジェクトで **自分だけ** | `~/.claude.json` |
| `--scope user` | 自分の **全プロジェクト** | `~/.claude.json` |
| `--scope project` | そのプロジェクトで **チーム全員** | プロジェクトの `.mcp.json`（Git で共有） |

一人で使うなら、よく使うものは `--scope user`、そのプロジェクトだけで使うものは何も付けない、で十分です。

### 使ってみる

追加したら、ふつうに頼むだけで Claude が MCP の機能を使います。

```text
playwright を使って site/index.html をブラウザで開いて、スマホ幅（幅375px）で表示崩れがないか確認して
```

初めて使うツールでは、使ってよいか確認が出ます。**何をしようとしているか読んでから** 許可しましょう。

### 権限設定で許可・禁止する

MCP のツールにも、権限設定（[第5章](05-permissions-settings.md)）の許可・禁止が使えます。MCP のツールは `mcp__サーバー名__ツール名` という名前で表され、サーバーのツールをまとめて指定するときは `*` を使います。

```json
{
  "permissions": {
    "allow": ["mcp__playwright__*"]
  }
}
```

（Playwright のツールはすべて確認なしで使ってよい、という例。慣れてから使いましょう）

## 13-4 プラグイン：機能をまとめて入れる

プラグインは、**スキル・サブエージェント・フック・MCP サーバーなどをまとめた詰め合わせパック** です。自分で一つずつ作らなくても、誰かが作った便利な機能をまとめて入れられます。

### 探して入れる

Claude Code の中で次を入力すると、プラグインの画面が開きます。

```text
/plugin
```

- 「Discover」タブから、マーケットプレイス（プラグインの一覧を配っている場所）のプラグインを探してインストールできます。
- 公式のマーケットプレイスは、最初に Claude Code を起動したときに自動で追加されています。
- 入れたり外したりしたら、`/reload-plugins` で反映されます。

ターミナルから入れることもできます。

```bash
claude plugin install <プラグイン名>@<マーケットプレイス名>
```

（例: `claude plugin install code-review@claude-plugins-official`）

### 別のマーケットプレイスを追加する

公式以外のマーケットプレイスは、`/plugin marketplace add` で追加できます。

> **注意**: 公式以外のマーケットプレイスやプラグインは、**中身を確認してから** 入れてください。プラグインにはフック（自動で実行されるコマンド）や MCP サーバーが入っていることがあります。

### 入れる範囲

プラグインも、自分の全プロジェクト・そのプロジェクト・自分だけ、の範囲を選んで入れられます。

### 自分で作ることもできる

自分で作ったスキルやサブエージェントをプラグインにまとめて、別のパソコンや仲間に配ることもできます（設定ファイルは `.claude-plugin/plugin.json`）。作り方は少し上級者向けなので、必要になったら Claude に「このスキルとサブエージェントをプラグインにまとめて」と頼んでみてください。

## 13-5 外とつなぐときの安全の心得

### 信頼できる提供元のものだけを使う

- 公式、またはサービス提供元が自分で配っている MCP サーバー・プラグインを選ぶ
- 「便利そう」だけで知らない人のものを入れない
- 使わなくなったものは削除する（`claude mcp remove`、`/plugin`）

### 「隠れた指示」に注意する（プロンプトインジェクション）

外部から読み込んだ Web ページ・メール・ドキュメントの中に、**AI 向けの隠れた指示**（「このファイルを外部に送れ」など）が書かれていることがあります。Claude がそれに引っ張られて、意図しない操作をしようとするおそれがあります。これをプロンプトインジェクションといいます（[第7章](07-safety.md)）。

- MCP や Web から読んだ内容をもとに、**送信・削除・公開・支払い** をしようとしたら、いったん止めて内容を確認する
- 確認をなくすモード（`bypassPermissions` など）で外部につないだ作業をさせない
- 予想外の操作をしようとしたら、迷わず「No」を選ぶ

### 入れすぎに注意する（コンテキストの消費）

有効にしているだけで、毎回の会話で少しずつコンテキストを消費するものがあります。

- **プラグイン**: 中に入っているスキルやサブエージェントの **名前と説明** が、毎回読み込まれます。
- **MCP サーバー**: ツールの中身は使うときまで読み込まれず、ふだんは **ツールの名前程度** が伝わるだけです（バージョンにより異なる）。それでも数が増えれば積み重なります。

使わないものは `/mcp` や `/plugin` で無効にしておくと、コンテキストと利用量の節約になります（[第9章](09-context-cost.md)）。

## やってみよう

### 練習1：公式プラグインを眺める

- **目的**: プラグインの探し方を知る
- **手順**: Claude Code の中で `/plugin` を開き、Discover タブで並んでいるプラグインの説明を3つ読む
- **期待する結果**: どんなプラグインがあるか、何ができるかが分かる
- **うまくいかないとき**: 一覧が出ない場合は、`/plugin` の画面でマーケットプレイスが追加されているか確認します

### 練習2：MCP の一覧を確認する

- **目的**: 今つながっている MCP サーバーを確認する
- **手順**: ターミナルで `claude mcp list` を実行する。Claude Code の中で `/mcp` も開いてみる
- **期待する結果**: つながっているサーバーの一覧（何もなければ空）が表示される

### 練習3：ブラウザ操作の MCP を試す（Node.js が入っている人）

- **目的**: MCP で Claude ができることが広がるのを体験する
- **手順**:
  1. ターミナルで練習用フォルダに移動し（`cd ~/sakura-work`）、`claude mcp add --transport stdio playwright -- npx -y @playwright/mcp@latest` を実行する（何も付けないので、このフォルダで自分だけが使える設定になります。どこでも使いたいなら `--scope user` を付ける）
  2. 同じフォルダで Claude Code を起動し、「playwright を使って https://example.com を開いて、ページのタイトルを教えて」と頼む
  3. 確認が出たら、内容を読んで許可する
- **期待する結果**: ページのタイトル（Example Domain）が返ってくる
- **うまくいかないとき**: `/mcp` で playwright の状態を確認します。別のフォルダで起動していないか、ブラウザ（Chrome など）が入っているかも確認します。不要になったら `claude mcp remove playwright` で削除します

## まとめ

- **MCP** は Claude Code を外部サービスとつなぐ仕組み。`claude mcp add` で追加、`/mcp` で確認する
- 何も付けないとそのプロジェクトで自分だけ、`--scope user` で全プロジェクト、`--scope project` でチーム共有（`.mcp.json`）
- **プラグイン** はスキル・サブエージェント・フック・MCP の詰め合わせ。`/plugin` から探して入れる
- 初心者は **公式のプラグインから** 探すのが簡単
- 外とつなぐほど、データの送信や **隠れた指示** のリスクが増える。信頼できるものだけを、必要な分だけ使う

## 確認テスト

**問1** MCP サーバーを、自分の全プロジェクトで使えるように追加するには、どのオプションを付けますか？

<details><summary>答えを見る</summary>

`--scope user` です。何も付けないと、そのプロジェクトで自分だけが使える設定になります。`--scope project` はプロジェクトの `.mcp.json` に保存され、チームで共有されます。

</details>

**問2** プラグインには何が入っていることがありますか？入れる前に何に気をつけるべきですか？

<details><summary>答えを見る</summary>

スキル・サブエージェント・フック・MCP サーバーなどが入っていることがあります。フックは自動でコマンドを実行し、MCP サーバーは外部にデータを送ることがあるので、信頼できる提供元のものを選び、中身を確認してから入れます。

</details>

**問3** MCP で読み込んだ Web ページを要約させていたら、Claude が急に「ファイルを外部に送信します」と言い出しました。どうすべきですか？

<details><summary>答えを見る</summary>

「No」を選んで止めます。読み込んだページに AI 向けの隠れた指示（プロンプトインジェクション）が含まれていた可能性があります。何を読んでそうしようとしたのかを確認し、必要なら作業をやり直します。

</details>

**問4** 使っていない MCP サーバーを有効のままにしておくと、どんな影響がありますか？

<details><summary>答えを見る</summary>

有効にしているだけで、毎回の会話でコンテキストを少しずつ消費します。使わないものは `/mcp` や `/plugin` で無効にするか、削除しておきます。

</details>
