# 第5章 権限モードと設定ファイル：どこまで任せるかを決める

> **この章で学ぶこと**
> - Claude Code が「やっていいですか？」と確認してくる理由
> - 6つの権限モードの違いと、`Shift + Tab` での切り替え方
> - 「まず計画、それから実行」というプランモードの使い方
> - よく使う操作を自動で許可し、危ない操作を禁止する設定の書き方
> - 設定ファイル（settings.json）の置き場所と優先順位
>
> 所要時間の目安: 40分 ／ 前提: [第4章](04-prompting.md)

## 5-1 なぜ「確認」が出てくるのか

Claude Code は、ファイルを書き換えたりコマンドを実行したりできる道具です。便利な反面、間違った操作をすると大事なファイルを消してしまうこともあります。

そこで Claude Code は、**ファイルの編集やコマンドの実行の前に「やってもいいですか？」と確認** してきます。この確認画面は、あなたが Claude の行動をチェックできる大切な関門です。

確認画面が出たら、次の順で判断します。

1. **何をしようとしているか読む**（どのファイルを、どう変えるのか。どんなコマンドか）
2. 意味が分かって、問題なければ **Yes**
3. 分からない・不安なら **No** を選び、「今何をしようとしてる？」「そのコマンドは何をするの？」と聞く

確認画面は英語で表示されます。たとえば `Do you want to make this edit to index.html?` のような質問の下に、次の選択肢が出ます。

| 表示 | 意味 |
|---|---|
| `Yes` | 今回だけ許可する |
| `Yes, and don't ask again …` | 今回許可し、同じ種類の操作は次から確認しない（5-4） |
| `No` | 許可しない（理由や別の指示を伝えられる） |

> **注意**: 確認画面を読まずに Yes を連打するのは、内容を読まずに契約書にハンコを押すのと同じです。慣れるまでは必ず一度読みましょう。

### さくらさんの場合

Web デザイナーのさくらさんは、ポートフォリオサイトの修正を Claude に頼みました。すると Claude が `rm` という見慣れないコマンドの確認を出してきました。さくらさんは No を選んで「このコマンドは何をするの？」と聞き、それが「ファイルを削除するコマンド」で、古い画像を消そうとしていたと分かりました。消してよい画像だったので、改めて頼み直しました。

**分からないものは止めて聞く**。これが一番安全な使い方です。

## 5-2 6つの権限モード

確認の度合いは **権限モード** で切り替えられます。**`Shift + Tab` を押すたびにモードが切り替わり**、今のモードは画面の下に表示されます（Mac でも `⌘` ではなく `Shift` キーと `Tab` キーです）。

| モード | 動き | 向いている場面 |
|---|---|---|
| **default（通常）** | 編集やコマンドのたびに確認する。画面上で「Manual」と表示されることもある | 慣れないうち、大事なファイルを扱うとき |
| **acceptEdits（編集は自動）** | ファイル編集は確認なしで進める | 作業を任せてテンポよく進めたいとき |
| **plan（プランモード）** | ファイルは編集せず、調べて計画を立てて見せてくれる | 大きな作業の前、何をするか先に確認したいとき |
| **auto（自動）** | 安全かどうかを AI が判断し、危なそうなときだけ確認する | 慣れてきて、任せる範囲を広げたいとき |
| dontAsk（上級者向け） | 確認が必要な操作は **すべて自動で拒否** する | 許可済みの操作だけで動かす自動処理 |
| bypassPermissions（上級者向け） | 確認を **ほぼすべて省略** する（禁止ルールは有効なまま） | 隔離された専用環境のみ。**普段は絶対に使わない** |

> **注意**
> - auto は、対応しているモデル（環境により条件が異なる）を使っているときに選べます。Team / Enterprise では初期状態で有効で、管理者がオフにできます。条件を満たさない環境では `Shift + Tab` で選べません。
> - bypassPermissions が危ないのは、Claude が間違えたときや、Web ページなどに仕込まれた悪い指示（プロンプトインジェクション、第7章）に引っ張られたときに、削除や送信のような **取り返しのつかない操作を止める機会がなくなる** からです。
> - dontAsk と bypassPermissions は、通常 `Shift + Tab` の切り替えには出てきません。
> - 最初のモードや選べるモードは、利用環境やバージョンにより異なります。最近のバージョン（v2.1.283 以降）では、**起動したときから auto になっている** ことがあります。画面の下の表示を確認し、練習中は `Shift + Tab` で default（`Manual` と表示）に切り替えてください。
> - Windows の一部のターミナルでは `Shift + Tab` が効かないことがあります。その場合は、次の節のように起動時にモードを指定してください。

### 初心者におすすめの使い分け

| 段階 | おすすめのモード |
|---|---|
| 使い始めの1〜2週間 | **default**。起動時に auto になっていたら `Shift + Tab` で切り替え、確認画面を読む練習をする |
| 慣れてきたら | 文章やページの修正など、失敗しても Git で戻せる作業は **acceptEdits** |
| 大きな作業の前 | まず **プランモード** で計画を見る |
| さらに慣れたら | 条件が合えば **auto** も試す |

起動するときにモードを指定することもできます。

```bash
claude --permission-mode plan          # プランモードで起動
claude --permission-mode acceptEdits   # 編集は自動のモードで起動
claude --permission-mode default       # 通常モードで起動
```

## 5-3 「まず計画、それから実行」：プランモード

大きめの作業は、いきなり始めさせると「思っていたのと違う」ものができがちです。**プランモードで先に計画を立てさせる** と失敗がぐっと減ります。

### 手順

1. `Shift + Tab` を何回か押して、画面の下に `⏸ plan mode on` と表示される状態にする
2. やりたいことを伝える

   ```text
   オンライン講座の申し込みページを作りたい。
   講座の説明、料金（3コース）、よくある質問、申し込みフォームを入れたい。
   どう進めるか計画を立てて。
   ```

3. 出てきた計画を読み、気になる点を伝える

   ```text
   よくある質問は5つで十分。フォームは Google フォームへのリンクにしたいので、自作しなくていい。
   ```

4. 計画に納得したら承認して、実行に移る

### プランモードが役立つ場面

- 複数のファイルにまたがる作業（サイト全体のデザイン変更など）
- 何から手をつければいいか分からないとき（「今のフォルダの状態を調べて、整理の計画を立てて」）
- 失敗すると面倒な作業（大量のファイルの名前を変えるなど）

## 5-4 「毎回確認しない」「絶対させない」を設定する

### 確認画面から許可する

確認画面で `Yes, and don't ask again`（今後は確認しない）を選ぶと、そのコマンドは次から自動で許可されます。この許可は、そのプロジェクトの `.claude/settings.local.json` に保存されます。

### 設定ファイルにまとめて書く

**許可（allow）** と **禁止（deny）** を設定ファイルにまとめて書くこともできます。

保存するファイル: `.claude/settings.json`（プロジェクトのフォルダの中）

```json
{
  "permissions": {
    "allow": ["Bash(ls *)"],
    "deny": ["Read(./.env)", "Bash(git push *)"]
  }
}
```

この例の意味は次のとおりです。

| 書いたもの | 意味 |
|---|---|
| `"Bash(ls *)"` を allow | フォルダの中身の一覧表示（`ls`）は確認なしで許可 |
| `"Read(./.env)"` を deny | パスワードなどを書いた `.env` ファイルは読ませない（第7章） |
| `"Bash(git push *)"` を deny | GitHub などへのアップロード（push）は禁止（第6章） |

### ツールの名前

Claude Code の中で Claude が使う道具（ツール）には、次のような名前が付いています。ルールにはこの名前を書きます（[付録B 用語集](appendix-b-glossary.md)も参照）。

| ツール名 | していること |
|---|---|
| `Read` | ファイルを読む |
| `Edit` / `Write` | ファイルを編集する / 新しく作る |
| `Bash` | コマンドを実行する |
| `Grep` / `Glob` | ファイルの中身やファイル名を探す |
| `WebFetch` / `WebSearch` | Web ページを読む / Web を検索する |
| `Agent` | サブエージェントを呼び出す（第11章） |

### ルールの書き方

ルールは「ツール名」または「ツール名(対象)」の形で書きます。

| 書き方の例 | 意味 |
|---|---|
| `Bash(npm run build)` | このコマンドちょうど |
| `Bash(npm run *)` | `npm run` で始まるコマンド全部（`*` は「何でも」） |
| `Read(./.env)` | `.env` ファイルの読み取り |
| `WebFetch(domain:example.com)` | example.com のページの取得 |

**優先順位は「deny → ask → allow」**。つまり **禁止（deny）が常に一番強く**、許可リストに書いてあっても禁止リストにあれば実行されません。

> **注意**
> - すでに `.claude/settings.json` がある場合は、**丸ごと上書きせずに中身を合体** させてください。自信がなければ「この設定を .claude/settings.json に追加して」と Claude に頼むのが安全です。
> - JSON は、カンマや括弧が1つずれるだけで読み込めなくなります。コメント（`//`）も書けません。
> - `Read(./.env)` の禁止は、`cat` `head` `tail` `sed` など、Claude Code が中身を読み取れる Bash コマンドで `.env` を読む場合にも効きます。ただし、スクリプトの中で読むなど、Claude Code が判断できない形には効きません。**禁止ルールは完全な防御ではない** ので、本当に危ないものは、そもそも扱わせない工夫と組み合わせましょう（第7章）。

## 5-5 設定ファイル（settings.json）の置き場所と優先順位

権限・フック・使うモデルなどの設定は、JSON 形式の設定ファイルに書きます。普段は `/config`（設定画面）や確認画面での選択で自動的に書き込まれるので、**直接編集するのは慣れてからで大丈夫** です。

| ファイル | 効く範囲 | Git で共有 |
|---|---|---|
| `~/.claude/settings.json` | 自分の全プロジェクト | しない |
| `.claude/settings.json` | そのプロジェクト | **する**（チームで同じ設定に） |
| `.claude/settings.local.json` | そのプロジェクト・自分だけ | しない（Claude Code が作った場合は自動で Git の対象外になる。手で作ったときは `.gitignore` に追加） |

`~/` はホームフォルダのことです。`.claude` のように `.` で始まるフォルダは **隠しフォルダ** で、普段は見えません（Mac の Finder では `⌘ + Shift + .` で表示できます）。用語は[付録B 用語集](appendix-b-glossary.md)も参照してください。

### 優先順位

同じ項目が複数の場所に書かれていると、次の順で強いほうが使われます。

1. 会社などの管理者が配布する設定（最優先）
2. 起動時のコマンドで指定したもの
3. `.claude/settings.local.json`
4. `.claude/settings.json`
5. `~/.claude/settings.json`

つまり **「自分のプロジェクトに近いほうが強い」** と覚えておけば十分です。

- ただし `permissions.allow` などの **リストは上書きではなく足し合わされます**。
- `/config` や `/model` で変えた設定の多くは `~/.claude/settings.json` に保存されます（一部の項目は別のファイル）。

### 設定が効いているか確かめる

| 方法 | 分かること |
|---|---|
| Claude Code の中で `/status` | どの設定ファイルが読み込まれているか |
| ターミナルで `claude doctor` | 読み込めなかった項目など、詳しい診断 |

## やってみよう

### 練習1：権限モードを切り替えてみる

- **目的**: `Shift + Tab` で今のモードを確認・変更できるようになる
- **手順**:
  1. 練習用フォルダ `~/sakura-work` で `claude` を起動する
  2. `Shift + Tab` を1回ずつ押し、画面の下の表示がどう変わるか見る
  3. プランモードにして「このフォルダの中身を調べて、整理の計画を立てて」と頼む
- **期待する結果**: ファイルは変更されず、計画だけが表示される
- **うまくいかないとき**: 画面の下の表示が見当たらない場合は、ターミナルのウィンドウを広げる。モードの数が表と違うのは、環境やバージョンによる違いなので問題ありません。`Shift + Tab` が効かなければ、一度終了して `claude --permission-mode plan` で起動する

### 練習2：`.env` を読ませない設定を入れる

- **目的**: 禁止ルール（deny）を自分で設定できるようになる
- **手順**:
  1. Claude に次のように頼む

     ```text
     .claude/settings.json に、.env ファイルを読めないようにする deny ルールを追加して。
     すでに設定があれば合体させて。
     ```

  2. 確認画面で変更内容を読んでから Yes を選ぶ
  3. `/status` で設定ファイルが読み込まれているか確認する
- **期待する結果**: `.claude/settings.json` に `"Read(./.env)"` が deny として入っている
- **うまくいかないとき**: `claude doctor` を実行して、JSON の書き間違いがないか確認する

### 練習3：プランモードで計画を直してもらう

- **目的**: 計画を読んで、修正の指示を出す練習をする
- **手順**: プランモードで「自己紹介ページに、実績紹介のセクションを追加する計画を立てて」と頼み、計画に1つ注文をつける（例:「実績は3件だけでいい」）
- **期待する結果**: 注文を反映した計画に更新される
- **うまくいかないとき**: いきなり実行が始まりそうなら `Esc` で止め、`Shift + Tab` でプランモードになっているか確かめる

---

## まとめ

- 確認画面は **「読んでから」Yes**。分からなければ No で止めて聞く
- `Shift + Tab` で権限モードを切り替える。最初は default、慣れたら acceptEdits や auto
- 大きな作業は **プランモードで計画から**
- 設定ファイルの `allow` で自動許可、`deny` で禁止。**deny が常に優先**
- 設定ファイルは「プロジェクトに近いほど強い」。確認は `/status` と `claude doctor`

**問4** bypassPermissions を普段使ってはいけないのはなぜですか？
