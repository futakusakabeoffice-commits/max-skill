# 第4章 伝わる指示の出し方

> **この章で学ぶこと**
> - 結果が大きく良くなる「指示の4つの要素」
> - Claude に自分で確かめさせる「確認方法」の渡し方
> - 大きな仕事の分け方と、うまくいかないときの立て直し方
> - そのまま使えるビジネスの依頼文テンプレート
>
> **所要時間の目安**: 40分 ／ **前提**: [第3章](03-first-session.md)

---

## 4-1 指示の4つの要素

Claude Code には、ふつうの日本語で頼めば大丈夫です。ただ、次の **4つの要素** を入れると、結果がぐっと良くなります。

| 要素 | 伝えること | 悪い例 | 良い例 |
|---|---|---|---|
| **目的** | 何のために、何をしたいか | 「直して」 | 「申込ボタンを押しても反応しないので直して」 |
| **場所** | どのファイル・フォルダか | 「グラフを作って」 | 「`data/sales.csv` から月別売上のグラフを作って」 |
| **条件** | 守ってほしいこと、好み | 「きれいにして」 | 「色は青系、スマホでも崩れないように」 |
| **確認方法** | どうなったら完成か、どう確かめるか | （なし） | 「直したらブラウザで開いて、ボタンが動くか確かめて」 |

### ビフォー・アフター

さくらさんの最初の頼み方と、4つの要素を入れた頼み方を比べてみましょう。

**ビフォー**

```text
ブログを直して
```

→ Claude は「何を」「どこまで」直せばいいか分からず、全部の記事を大きく書き換えてしまうかもしれません。

**アフター**

```text
【目的】ブログ記事を読みやすくしたい
【場所】blog/ フォルダの 2026-11 で始まる記事3本
【条件】内容は変えずに、1文を短くして、見出しを付ける。です・ます調に統一
【確認方法】直す前と後で、記事の主張が変わっていないかを最後にチェックして報告して
```

【 】で区切る必要はありませんが、**4つが入っているか** を意識するだけで結果が変わります。

---

## 4-2 一番大事なのは「確認方法」

4つの中で、特に大事なのが **確認方法** です。

Claude Code は、結果を自分で確かめられると、**間違いに気づいて自分で直してくれます**。確認方法がないと、「できました」と言いながら間違っていることがあります。

| 仕事 | 渡す確認方法の例 |
|---|---|
| 集計 | 「最後に元データの合計と一致するか検算して」 |
| ホームページ | 「ブラウザで開いて、スマホの幅でも崩れていないか確かめて」 |
| 文章の修正 | 「直す前と後で、意味が変わっていないかチェックして」 |
| 調べもの | 「参考にした URL を付けて。古い情報や確かでない情報はそう書いて」 |
| ファイル整理 | 「移動する前に一覧を見せて、私が OK してから移動して」 |

> **注意**: 確認方法を渡しても、AI が間違える可能性はゼロにはなりません。お金・契約・公開に関わるものは、**最後に自分の目でも確かめましょう**（[第7章](07-safety.md)）。

## 4-3 「先に見せて」で事故を防ぐ

たくさんのファイルを変える作業や、元に戻しにくい作業は、**いきなりやらせずに、先に計画や一覧を見せてもらう** のが安全です。

```text
blog/ フォルダの全記事で、表記ゆれ（「出来る/できる」「サーバ/サーバー」など）を探して一覧にして。
直す前に一覧を見せて、私が OK したら直して。
```

```text
このフォルダのファイルを、種類ごとにフォルダ分けしたい。
まず、どう分けるかの案を表で見せて。まだ移動はしないで。
```

もっと大きな作業では、**プランモード**（編集せずに計画だけ立てるモード）を使います。詳しくは [第5章](05-permissions-settings.md) で学びます。

## 4-4 分からないことは先に質問させる

頼みたいことがまだぼんやりしているときは、**Claude に質問させる** とうまくいきます。

```text
講座の申込フォームを作りたい。
作り始める前に、決めておくべきことを質問して。質問は5つまでにして。
```

Claude が「入力項目は何にしますか？」「申込後の確認メールは必要ですか？」などと聞いてくれるので、答えていくうちに頼みたいことがはっきりします。

---

## 4-5 大きな仕事は分けて頼む

「講座サイトを全部作って」のように大きすぎる依頼は、途中で方向がずれやすくなります。**小さな単位に分けて、1つずつ確認しながら** 進めましょう。

```text
講座サイトを作りたい。全体を5つくらいの作業に分けて、順番を提案して。
```

↓ 提案を見て

```text
いいね。では1つ目の「トップページ」だけ作って。終わったら止まって。
```

↓ 確認して

```text
OK。2つ目の「講座一覧ページ」に進んで。
```

1つ終わるたびに、Git でセーブポイントを作っておくと安心です（[第6章](06-git.md)）。

## 4-6 うまくいかないときの立て直し方

### 2回直してもだめなら、やり直す

同じことを3回、4回と言い直しても、うまくいかないことがよくあります。会話に失敗の記録がたまって、Claude が混乱しているからです。

**2回直してもうまくいかないときは、次の手順で立て直します。**

1. `/clear` で会話をリセットする
2. これまでの失敗から分かったことを入れて、**指示を書き直す**
3. 最初から頼み直す

```text
（/clear のあとで）
@index.html の申込ボタンの色を変えたい。
前回は CSS の別の場所を変えてしまったので、ボタン部分（class="apply-btn"）だけを変えて。
変えたらブラウザで確認して。
```

### 説明しながら進めてもらう

何をしているか分からなくて不安なときは、こう頼みます。

```text
説明しながら進めて。何をするか、なぜそうするかを、1ステップずつ初心者向けに教えて
```

作業が少し遅くなりますが、**仕事をしながら学べる** ので、慣れるまではおすすめです。

## 4-7 そのまま使えるビジネスの依頼文テンプレート

ファイル名やフォルダ名は、自分のものに置き換えてください。

### 売上・請求の集計

```text
invoices/ フォルダにある今月の請求書 CSV を全部読んで、取引先ごとの合計金額を表にして
reports/2026-11_請求集計.md に保存して。
合計が元データと合っているか、最後に検算して結果を教えて。
```

### お問い合わせ返信のテンプレート作り

```text
@faq.md を参考に、よくある問い合わせ5種類（料金・日程・キャンセル・支払い方法・受講環境）への
返信テンプレートを templates/返信テンプレ.md に作って。
丁寧だけど堅すぎない文体で、1通200字以内。
```

### ブログ記事の表記ゆれを一括で直す

```text
blog/ フォルダの記事全部で、表記ゆれを探して一覧にして。
直す前に一覧を見せて、私が OK したら直して。
```

### 競合サービスの比較表

```text
「オンラインの Web デザイン講座」の主な競合5つを Web で調べて、
料金・期間・特徴・ターゲット・強み弱みを比較表にして research/競合比較.md に保存して。
参考にした URL も付けて。確かでない情報はそう書いて。
```

（Web 検索やページ閲覧の許可を求められたら、内容を見て Yes を選びます）

### 講座の案内メールの下書き

```text
@course/第3回_概要.md をもとに、受講生への案内メールを3パターン下書きして
drafts/案内メール.md に保存して。
件名も付けて。送信はしないで、下書きだけ作って。
```

> **注意**: メールの送信・SNS への投稿・ファイルの削除など、**外に出る操作や取り返しのつかない操作** は、下書きまでにとどめて、最後は自分の目で確かめてから行いましょう。

## やってみよう

### 練習1：自分の依頼文を4つの要素で書き直す

- **目的**: 4つの要素を体で覚える
- **手順**:
  1. 第1章の練習1で選んだ「任せたい仕事」を1つ取り出す
  2. まず思いついたままの依頼文を書く
  3. 4-1 の表を見ながら、目的・場所・条件・確認方法を足して書き直す
  4. 書き直した方を Claude Code に頼む
- **期待する結果**: 一度で、ほぼイメージどおりの結果が出る
- **うまくいかないとき**: 「この依頼文に足りない情報はある？」と Claude に聞いてみましょう

### 練習2：質問させてから作る

- **目的**: ぼんやりした依頼をはっきりさせる方法を体験する
- **手順**: 4-4 の例のように「作り始める前に質問して」と頼み、質問に答えてから作ってもらう
- **期待する結果**: 自分が考えていなかった点に気づける
- **うまくいかないとき**: 質問が多すぎるときは「3つまでにして」と数を指定しましょう

### 練習3：立て直しの練習

- **目的**: うまくいかないときに `/clear` で立て直す
- **手順**: 何か小さな修正を頼み、2回直しても思いどおりにならなかったら、4-6 の手順で `/clear` → 書き直し → 頼み直しをする
- **期待する結果**: 書き直した依頼で、うまくいく
- **うまくいかないとき**: 作業を4-5 のように小さく分けてみましょう

---

## まとめ

- 指示には **目的・場所・条件・確認方法** の4つを入れる
- 一番大事なのは **確認方法**。Claude が自分で確かめられると品質が上がる
- 元に戻しにくい作業は **「先に見せて」**。大きな作業は分けて1つずつ
- ぼんやりしているときは **先に質問させる**
- **2回直してだめなら `/clear` して書き直す**
- 外に出る操作（送信・公開・削除）は、**下書きまでにして最後は自分で確認**
