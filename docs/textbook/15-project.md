# 第15章 総まとめ実践：さくらさんの「業務ツール」を作る

> **この章で学ぶこと**
> - これまでの章で学んだことを、1つのプロジェクトの中で通して使う流れ
> - 「フォルダ → CLAUDE.md → Git → 作業 → 育てる → 守る → 自動化」という、実務での順番
> - 各ステップで「できたかどうか」を確かめる方法
>
> 所要時間の目安: 2〜3時間（休憩しながら、2日に分けても OK） ／ 前提: [第14章](14-automation-cloud.md)まで

---

## 15-1 この章で作るもの

主人公は、Web デザインとオンライン講座を一人で運営している個人事業主の **さくらさん** です。さくらさんには、こんな悩みがあります。

- 毎週、売上を集計して振り返りたいが、つい後回しになる
- ブログや講座の案内文を書いても、誤字や表記ゆれに自分では気づけない
- 業界の動きを追いたいが、毎朝ニュースを探す時間がない

この章では、さくらさんと一緒に **「さくらさんの業務ツール」** というフォルダを作り、Claude Code にこれらを任せられる状態にします。

### 完成したときのフォルダ

```text
~/sakura-office/
├── CLAUDE.md                     ← プロジェクトのルール（ステップ2）
├── .env                          ← 秘密情報。Claude には読ませない（ステップ7）
├── .gitignore                    ← Git に記録しないファイルの一覧（ステップ3・7）
├── data/
│   └── sales-sample.csv          ← 練習用の売上データ（ステップ4）
├── reports/
│   └── YYYY-MM-DD_週報.md         ← 自動で作る週報（ステップ5）
├── drafts/
│   └── blog-01.md                ← ブログの下書き（ステップ6）
└── .claude/
    ├── settings.json             ← 権限の設定（ステップ7）
    ├── skills/
    │   └── weekly-report/
    │       └── SKILL.md          ← 週報スキル（ステップ5）
    └── agents/
        └── proofreader.md        ← 校正サブエージェント（ステップ6）
```

### ステップの全体像

| ステップ | やること | 学んだ章 |
|---|---|---|
| 1 | 専用フォルダを作って起動する | 第2章・第3章 |
| 2 | CLAUDE.md を作る | 第8章 |
| 3 | Git で管理を始める | 第6章 |
| 4 | サンプル売上データを作って集計する | 第4章 |
| 5 | 週報スキルをさくらさん用に直す | 第10章 |
| 6 | 校正サブエージェントを用意する | 第11章 |
| 7 | `.env` を読ませない設定にする | 第5章・第7章 |
| 8 | 毎朝のニュースまとめを予約する | 第14章 |
| 9 | 仕上げ：コミットして振り返る | 第6章・第9章 |

> **注意**: この章のデータはすべて **練習用の架空のデータ** です。本物のお客様の情報や売上データは使わないでください。慣れてから、本物のデータに置き換えましょう（第7章）。

## 15-2 ステップ1：専用フォルダを作って起動する（第2章・第3章）

ターミナルを開き、次を実行します。

```bash
mkdir ~/sakura-office
cd ~/sakura-office
claude
```

（第2〜14章の練習で使った `~/sakura-work` とは別の、新しいフォルダです）

> **注意**: デスクトップやホームフォルダそのもので `claude` を起動しないでください。Claude は起動したフォルダの中を作業場所にするので、関係ないファイルまで扱える状態になってしまいます（第2章）。

**ここまでできたら✅**: Claude Code の画面が開き、入力欄が表示されている

## 15-3 ステップ2：CLAUDE.md を作る（第8章）

まだ空のフォルダなので、`/init` ではなく、Claude に直接頼んで作ります。複数行の依頼の入力のしかたは、[第3章 3-1](03-first-session.md) を見てください。

```text
このフォルダは、個人事業主「さくらさん」の業務用フォルダです。次の内容で CLAUDE.md を作って。

- 事業: Webデザインの受託とオンライン講座の運営（一人で運営）
- お客様: 30〜50代の個人事業主・小さなお店のオーナーが中心
- 文章のルール: 「です・ます」調。専門用語は使わず、使うときは説明を添える
- ブランドカラー: #2E7D6B
- フォルダの使い方: 売上データは data/、レポートは reports/、下書きは drafts/
- 数字を扱うときは、最後に必ず検算して結果を報告する
- .env ファイルは絶対に読まない・表示しない
```

できあがった `CLAUDE.md` を開いて、内容を確認します。

- 自分の言葉で直したいところがあれば、「CLAUDE.md の〇〇を△△に直して」と頼みます
- **短く保つ** のがコツです（第8章）。まずはこのくらいで十分です

**ここまでできたら✅**: `CLAUDE.md` があり、上の7つのルールが書かれている

## 15-5 ステップ4：サンプル売上データを作って集計する（第4章）

### 手順4-1 練習用のデータを作ってもらう

```text
練習用の架空の売上データを data/sales-sample.csv に作って。
列は「日付, 商品, 種類, 金額」。種類は「デザイン受託」「オンライン講座」「個別相談」の3つ。
日付は、今日から数えて直近2週間分（先週と今週がそろうように）で30行くらい。実在の人名や会社名は使わないで。
```

> 日付を「直近2週間」にするのは、ステップ5の週報スキルが **先週分** を集計するからです。

### 手順4-2 集計してもらう

第4章で学んだ **目的・場所・条件・確認方法** の4点を入れて頼みます。

```text
data/sales-sample.csv を集計して、次の3つを表にして見せて。
1. 種類ごとの売上合計
2. 週ごとの売上合計
3. 売上が多かった商品トップ3
最後に、全体の合計が元データの金額の合計と一致するか検算して、結果を教えて。
```

### 手順4-3 結果を自分で確かめる

- 表の合計が、検算の結果と合っているか見ます
- 1〜2行だけ、自分でも CSV を開いて確かめてみましょう

> **注意**: AI は **自信満々に間違える** ことがあります。特に数字は、Claude に検算させたうえで、ときどき自分でも確かめる習慣をつけましょう（第7章）。

**ここまでできたら✅**: 3つの表と、検算の結果（「一致しました」など）が表示されている

区切りが良いので、ここでもコミットしておきます。

```text
ここまでの変更をコミットして
```

## 15-6 ステップ5：週報スキルをさくらさん用に直す（第10章）

ステップ4のような集計を毎週頼むなら、**同じ説明を毎回するのは無駄** です。[第10章](10-skills.md) で作った週報スキル（`weekly-report`）を、このフォルダに用意して、さくらさんの売上データに合わせて少しだけ直します。

> 目安は「同じ説明を3回したら、CLAUDE.md かスキルにする」です（[第8章](08-claude-md-memory.md)）。

### 手順5-1 第10章のスキルをこのフォルダに用意する

- 第10章のスキルを `~/.claude/skills/weekly-report/SKILL.md`（自分の全プロジェクト用）に置いた場合は、そのままこのフォルダでも使えます
- 第10章の練習用フォルダ（`.claude/skills/`）に置いた場合や、まだ作っていない場合は、[第10章 10-2](10-skills.md) の内容で `.claude/skills/weekly-report/SKILL.md` を作ります（「第10章の週報スキルと同じものを .claude/skills/weekly-report に作って」と頼んでも OK）

### 手順5-2 さくらさん用に直す

第10章のスキルは「講座トップ3」を集計しますが、さくらさんの売上には **デザイン受託・オンライン講座・個別相談** の3種類があります。次の1か所だけ直します（`-` の行を消して、`+` の行を足すという意味です）。

```diff
 2. 次を計算する
    - 売上合計（税込）
    - 前週比（%）
-   - 売上が多かった講座トップ3
+   - 種類（デザイン受託・オンライン講座・個別相談）ごとの合計
+   - 売上が多かった商品トップ3
```

自分で直さずに、次のように頼んでも OK です。

```text
.claude/skills/weekly-report/SKILL.md の「売上が多かった講座トップ3」を、
「種類（デザイン受託・オンライン講座・個別相談）ごとの合計」と「売上が多かった商品トップ3」の2行に直して。他は変えないで。
```

> **注意**: `~/.claude/skills/` に置いたスキルを直すと、**全プロジェクト** の週報が変わります。このフォルダだけ変えたいときは、プロジェクト側の `.claude/skills/weekly-report/SKILL.md` に作って直します（プロジェクト側が優先されます）。

### 手順5-3 使ってみる

```text
/weekly-report
```

**ここまでできたら✅**: `reports/` フォルダに先週分の週報ができ、種類ごとの合計と検算の結果が報告されている

> 「データがありません」と報告された場合は、ステップ4の CSV に先週分の日付が入っているか確認します。うまく呼び出せないときは、ファイルの場所と先頭の `---` の書式を確認します（[付録C](appendix-c-troubleshooting.md#c-7)）。

## 15-7 ステップ6：校正サブエージェントを用意する（第11章）

ブログや講座の案内文の校正は、**専門の助手（サブエージェント）** に任せます。校正中の細かいやり取りはメインの会話に入らず、結果の報告だけが戻ってくるので、会話が散らかりません。

### 手順6-1 校正する文章を用意する

```text
練習用に、オンライン講座「はじめての Web デザイン」の案内ブログ記事の下書きを drafts/blog-01.md に作って。
600字くらいで、わざと誤字を3つと、表記ゆれ（「出来る/できる」など）を2つ入れておいて。
```

### 手順6-2 サブエージェントを用意する

[第11章](11-subagents.md) で作った `proofreader` を使います。

- **第11章で `~/.claude/agents/` に置いていれば、この手順は不要** です。そのまま手順6-3へ進みます
- 第11章の練習用フォルダ（`.claude/agents/`）に置いた場合は、同じ内容で `~/sakura-office/.claude/agents/proofreader.md` を作ります（「第11章の proofreader と同じサブエージェントを .claude/agents に作って」と頼んでも OK）

さくらさんのお客様に合わせたいなら、読者についての1行だけ直します。

```diff
-4. 読者に伝わりにくい専門用語
+4. 読者（30〜50代の個人事業主・小さなお店のオーナー）に伝わりにくい専門用語
```

`proofreader` の `tools` は `Read, Grep, Glob`（読む・探すだけ）なので、**ファイルを書き換えられません**。

### 手順6-3 使ってみる

```text
proofreader サブエージェントを使って、drafts/blog-01.md を校正して
```

報告を読んで、直したいものだけを選んで頼みます。

```text
報告のうち、誤字と表記ゆれだけを直して。言い回しはそのままでいい。
```

**ここまでできたら✅**: わざと入れた誤字3つ・表記ゆれ2つが見つかり、選んだものだけが直っている

> 見つからないものがあっても大丈夫です。AI の校正は完璧ではありません。最後は自分の目でも読みましょう。

## 15-8 ステップ7：`.env` を読ませない設定にする（第5章・第7章）

さくらさんは、今後ネットショップの API キー（サービスを使うための合言葉）を `.env` に保存する予定です。CLAUDE.md にも「読まない」と書きましたが、**CLAUDE.md はあくまで「お願い」** です。絶対に守らせたいことは、権限の設定（deny）で禁止します。

### 手順7-1 練習用の `.env` を作る

```text
練習用に .env ファイルを作って。中身は「SHOP_API_KEY=dummy-key-for-practice」の1行だけ。
```

### 手順7-2 読ませない設定を書く

```text
.claude/settings.json に、.env を読めないようにする deny ルールを追加して。
既にファイルがある場合は、今の中身を消さずに追加して。
```

できあがった `.claude/settings.json` は、次のような内容になっているはずです。

保存するファイル: `.claude/settings.json`

```json
{
  "permissions": {
    "deny": ["Read(./.env)"]
  }
}
```

### 手順7-3 本当に読めないか確かめる

設定を確実に反映させるため、一度 `/exit` で終了し、もう一度 `claude` で起動してから試します。

```text
.env の中身を表示して
```

**ここまでできたら✅**: Claude が「読めない（拒否された）」と答え、中身が表示されない

> **注意**: Bash で `cat` などを使っても、Claude Code が解析できるコマンドなら deny は効きます。ただし、スクリプトの中など Claude Code が解析できない経路は防げません（[第5章](05-permissions-settings.md)）。もし Claude が「Bash で `cat .env` を実行してよいか」と確認してきたら、**No** を選んでください。本物の API キーを扱うときは、**会話に貼らない・Git に記録しない・公開しない** の3つも合わせて守ってください（第7章）。

`.gitignore` に `.env` が入っているかも確認します。

```text
.gitignore に .env が入っているか確認して。入っていなければ追加して。
```

## 15-9 ステップ8：毎朝のニュースまとめを予約する（第14章）

最後に、毎朝の情報収集を自動化します。クラウドで動く機能なので、**Pro / Max / Ultra / Team / Enterprise のプラン** と **claude.ai アカウントでのログイン** が必要です（第14章）。

```text
/schedule 毎朝 日本時間の7時に、Webデザイン業界とオンライン講座業界の昨日のニュースを5つ選んで、3行ずつ要約して。それぞれ参考にしたURLも付けて。
```

設定の途中で Claude が詳細を質問してくるので、答えていきます。

> **注意**:
> - クラウドで動くので、`sakura-office` フォルダの中のファイルは読めません
> - 実行のたびにプランの利用量を消費します（第9章）
> - Web の情報には、間違いや「隠れた指示」が混ざることがあります。まとめの内容をそのまま SNS に投稿したりせず、気になるものは元の記事を確認しましょう（第7章）

**ここまでできたら✅**: 予約ができたと報告され、翌朝7時以降に要約が届いている

> プランの都合でクラウドが使えない場合は、このステップは飛ばして構いません。代わりに、朝 `claude` を起動して（対話モードで）「Webデザイン業界の最近の話題を3つ、参考URL付きで教えて」と頼む方法もあります。Web 検索の許可を求められたら内容を見て Yes を選びます（`claude -p` の非対話モードでは確認画面に答えられないため、ここでは使いません）。

## 15-11 振り返り

この章では、さくらさんと一緒に次の流れを体験しました。

1. **場所を決める**: 専用フォルダで起動する
2. **前提を伝える**: CLAUDE.md にルールを書く
3. **セーブする**: Git でこまめにコミットする
4. **頼む**: 目的・場所・条件・確認方法を入れて頼み、結果を確かめる
5. **育てる**: 繰り返す作業はスキルに、専門の作業はサブエージェントに
6. **守る**: 絶対のルールは deny で。秘密情報は会話にも Git にも入れない
7. **任せる**: 定期的な作業は予約して、結果は人が確認する

この順番は、どんなプロジェクトでもほぼ同じです。新しい仕事を Claude Code に任せるときは、この7つを思い出してください。

---

## 15-12 次の一歩

- **本物のデータで使う**: 練習用データを、自分の本当の売上データ（個人情報を除いたもの）に置き換えてみる
- **自分の仕事のスキルを1つ作る**: 毎月の請求書作成、講座の受講者への案内メールなど、繰り返している作業を1つスキルにする
- **CLAUDE.md を育てる**: Claude に同じ注意を3回したら、CLAUDE.md に書き足す
- **フックに挑戦する**: 「ファイルを保存したら自動で〇〇する」を試す（第12章）
- **外部サービスとつなぐ**: `/plugin` から、使っているサービスのプラグインを探してみる（第13章）
- **分からないことは Claude Code に聞く**: 「〇〇のやり方を公式ドキュメントで調べて」と頼めば、最新の情報を調べてくれます
- **ときどき公式ドキュメントを見る**: Claude Code は更新が速いので、月に一度くらい新機能をチェックすると、もっと楽になる方法が見つかります

### 練習1：自分版の業務フォルダを作る

- **目的**: この章の流れを、自分の仕事で再現する

- **目的**: 役割ごとにサブエージェントを分ける感覚をつかむ
- **手順**:
  1. 「SNS投稿の案を3つ作る担当」など、校正とは別の役割を1つ考える
  2. ステップ6を参考に、`.claude/agents/` に新しいサブエージェントを作る（Claude に「〇〇担当のサブエージェントを作って」と頼んでも OK）
  3. 名前を指定して使ってみる
- **期待する結果**: 新しいサブエージェントが、指定した形式で報告を返す
- **うまくいかないとき**: `name` の綴りと呼び出すときの名前が一致しているか、付録C を確認する

---

## まとめ

- 実務では「フォルダ → CLAUDE.md → Git → 作業 → 育てる → 守る → 任せる」の順に進めると失敗が少ない
- 数字や事実は、Claude に検算・出典を求めたうえで、最後は自分で確かめる
- 繰り返す作業はスキルに、専門の作業はサブエージェントに、絶対のルールは deny やフックに
- 秘密情報は deny で読ませず、`.gitignore` で Git に記録せず、会話にも貼らない
- 定期作業は `/schedule` で予約できるが、クラウドでは手元のファイルは読めない

## 確認テスト

**問1.** さくらさんは CLAUDE.md に「.env は絶対に読まない」と書きました。それなのに、なぜ `.claude/settings.json` にも deny ルールを書いたのですか？

<details><summary>答えを見る</summary>

CLAUDE.md の内容は Claude への **「お願い」** なので、守られないこともあるからです。権限ルールの `deny` は、Claude Code の仕組みとして操作そのものを禁止します。絶対に守らせたいことは、deny やフックで設定します（第5章・第12章）。

</details>

**問2.** 週報の作り方を毎週説明するのをやめるために、さくらさんは何を作りましたか？ また、どうやって呼び出しますか？

<details><summary>答えを見る</summary>

**スキル**（`.claude/skills/weekly-report/SKILL.md`）を作りました。`/weekly-report` と入力すると呼び出せます。また、「週報を作って」のように頼んだときに、Claude が自動で使うこともあります（第10章）。

</details>

**問3.** 校正サブエージェントの `tools` に `Read, Grep, Glob` だけを入れたのはなぜですか？

<details><summary>答えを見る</summary>

校正担当は **提案だけ** をすればよく、ファイルを書き換える必要がないからです。必要な道具だけを渡すと、勝手に書き換えられる心配がなく、動きも予想しやすくなります（第11章）。

</details>

**問4.** `/schedule` で予約した毎朝のまとめに「sakura-office/data の売上も一緒にまとめて」と追加しても、うまくいきません。なぜですか？

<details><summary>答えを見る</summary>

`/schedule` は **クラウドで動く** ため、手元のパソコンにある `sakura-office` フォルダのファイルを読めないからです。手元のファイルを使う作業は、ローカルで `/weekly-report` などを使って行います（第14章）。

</details>

**問5.** 最後のコミットの前に「.env が含まれていないことも確認して」と頼んだのはなぜですか？

<details><summary>答えを見る</summary>

`.env` には API キーなどの秘密情報が入るからです。Git に記録して GitHub などにアップロードすると、他の人に見られて悪用されるおそれがあります。`.gitignore` に入れたうえで、念のため確認すると安心です（第6章・第7章）。

</details>
