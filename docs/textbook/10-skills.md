## 10-1 スキルとは

スキルは、**決まった手順の作業を書いておく「手順書」** です。一度登録すると、次の2通りで使えます。

1. **自分で呼び出す**: 入力欄に `/スキル名` と打つ
2. **Claude が自動で使う**: 依頼の内容がスキルの説明に合っていれば、Claude が判断して使う

さくらさんは毎週月曜に、こんな長い依頼をしていました。

```text
data/ フォルダの先週分の売上 CSV を読んで、合計と前週比と、よく売れた講座トップ3を出して、
reports/ に日付付きで保存して、最後に気になる変化を3行でコメントして…
```

これをスキルにすると、毎週 `/weekly-report` と打つだけで済みます。

### CLAUDE.md・スキル・サブエージェントの違い

| | CLAUDE.md（第8章） | スキル（この章） | サブエージェント（第11章） |
|---|---|---|---|
| ひとことで | いつも覚えておくこと | 必要なときに開く手順書 | 専門の担当者 |
| 読み込まれるとき | **毎回**、全文が | 名前と説明（`name`・`description`）は毎回、**本文は使うときだけ** | 呼ばれたときに、別の会話で |
| 向いている内容 | お客様像・文体・ルール | 「週報を作る」などの手順 | 大量の調べもの・レビュー |
| コンテキストへの影響 | 全文ぶん常に消費する | 説明ぶんは常に、本文は使うときだけ | メインの会話はほぼ消費しない |

Claude は「どのスキルがあるか」を知るために、すべてのスキルの名前と説明を毎回読んでいます。手順の本文は、使うときにだけ読み込まれます。そのため、長い手順を CLAUDE.md に書くより **スキルに移す** 方が軽くなります（[第9章](09-context-cost.md)）。ただしスキルを作りすぎると説明ぶんが積み重なるので、`description` は短く的確に書きましょう。

## 10-2 最初のスキルを作る

### 置き場所

スキルは **フォルダ1つ＋その中の `SKILL.md`** でできています。

| 置き場所 | 使える範囲 |
|---|---|
| `~/.claude/skills/<スキル名>/SKILL.md` | 自分の **全プロジェクト** |
| `.claude/skills/<スキル名>/SKILL.md` | **そのプロジェクト**（Git で共有できる） |
| プラグインの中（[第13章](13-mcp-plugins.md)） | プラグインを入れた場所 |

### SKILL.md の形

保存するファイル: `.claude/skills/weekly-report/SKILL.md`

```markdown
---
name: weekly-report
description: 先週の売上データから週次レポートを作る。「週報」「週次レポート」「先週の売上」と言われたら使う。
---

# 週次レポートの作り方

1. data/ フォルダから先週分（月曜〜日曜）の売上 CSV を読む
2. 次を計算する
   - 売上合計（税込）
   - 前週比（%）
   - 売上が多かった講座トップ3
3. 計算結果を検算し、元データの合計と一致することを確認する
4. reports/ フォルダに「YYYY-MM-DD_週報.md」という名前で保存する
5. 最後に、気になる変化があれば3行以内でコメントする

# 注意
- お客様の名前やメールアドレスはレポートに書かない
- データが見つからないときは、推測で数字を作らず「データがありません」と報告する
```

- 上の `---` で囲んだ部分（フロントマター）が **設定**、その下が **手順** です。
- `name` はスキルの名前（`/weekly-report` の部分）になります。
- `description` には **何をするか** と **どんなときに使うか** を書きます。Claude はこれを読んで、自動で使うかどうかを決めます。

> **自分でファイルを作るのが面倒なら**: 「先週の売上から週報を作るスキルを .claude/skills/weekly-report に作って」と Claude に頼めば、ファイルごと作ってくれます。

### 使ってみる

```text
/weekly-report
```

または、ふつうに頼むだけでも使われます。

```text
先週の週報を作って
```

## 10-3 フロントマターの主な項目

最初は `name` と `description` だけで十分です。慣れてきたら、次の項目も使えます。

| 項目 | 内容 |
|---|---|
| `name` | スキルの名前 |
| `description` | 何をするか・いつ使うか（自動で使われるかどうかを左右する） |
| `disable-model-invocation` | `true` にすると、Claude が自動で使わず、自分で `/名前` と打ったときだけ使われる |
| `allowed-tools` | このスキルの実行中に使ってよいツール |
| `model` / `effort` | このスキルを使うときのモデルや考える深さ |

> 項目の細かい書き方や、ここにない項目（`when_to_use`、`paths` など）はバージョンにより異なります。必要になったら、Claude に「スキルのフロントマターで使える項目を公式ドキュメントで調べて」と聞いてください。

### 「勝手に使われると困る」スキル

請求書の送付や SNS への投稿など、**実行のタイミングを自分で決めたい作業** は、`disable-model-invocation: true` にしておくと安心です。

```markdown
---
name: publish-post
description: 下書きフォルダの SNS 投稿を最終チェックして、公開用フォルダに移す。
disable-model-invocation: true
---
```

## 10-4 業務で使えるスキルの実例

### 実例1：SNS 投稿を作る

保存するファイル: `.claude/skills/sns-post/SKILL.md`

```markdown
---
name: sns-post
description: ブログ記事や講座の告知から、X（旧Twitter）と Instagram 用の投稿文を作る。「SNS投稿」「告知文」と言われたら使う。
---

1. 指定された記事やメモを読む
2. 次の2種類の投稿文を作る
   - X 用: 140字以内。最後にハッシュタグを2つ
   - Instagram 用: 300字程度。改行を多めに、絵文字は3つまで
3. それぞれ2案ずつ作り、どちらがおすすめか理由を1行で添える
4. sns/ フォルダに「YYYY-MM-DD_投稿案.md」として保存する

# ルール
- 誇大な表現（「絶対」「必ず稼げる」など）は使わない
- 料金を書くときは税込で書く
```

### 実例2：請求書の金額チェック

保存するファイル: `.claude/skills/invoice-check/SKILL.md`

```markdown
---
name: invoice-check
description: invoices/ フォルダの請求書 CSV の金額をチェックする。「請求書チェック」「請求の確認」と言われたら使う。
---

1. invoices/ フォルダの CSV を読む
2. 各行について「単価 × 数量 = 小計」になっているか確認する
3. 消費税（10%）と合計金額が正しいか確認する
4. 問題があった行だけを表にして報告する（問題がなければ「問題なし」と報告）

# 注意
- ファイルは書き換えない。報告だけする
- 計算に自信がない行は「要確認」と書く
```

> **注意**: AI は計算や事実を **自信満々に間違える** ことがあります。お金に関わる結果は、最後に必ず自分の目で確認してください（[第7章](07-safety.md)）。

### 補助ファイルを使う

スキルのフォルダには、`SKILL.md` 以外のファイル（テンプレートなど）も置けます。

```text
.claude/skills/weekly-report/
├── SKILL.md
└── template.md   ← 週報のひな形
```

SKILL.md の中で「`template.md` の形式に沿って書く」と指示すれば、毎回同じ形式のレポートになります。

## 10-5 最初から入っているスキル

Claude Code には、**最初から入っているスキル（コマンドとして呼べる）** もいくつかあります。入力欄で `/` と打つと、使えるスキルやコマンドの一覧が表示されます。

| 最初から入っているスキル | 何をするか |
|---|---|
| `/doctor` | Claude Code の設定や環境の不調を診断し、直し方を提案する |
| `/code-review` | 変更したコードを点検する |
| `/simplify` | 変更したコードを、より簡潔に整える |
| `/loop` | 同じ作業を一定間隔でくり返す |

> 入っているスキルはバージョンにより異なります。`/` と打って表示される一覧で確認してください。

### 以前の「カスタムコマンド」との関係

以前は `.claude/commands/` フォルダに Markdown ファイルを置いて「カスタムコマンド」を作っていました。この方法も **今でも使えます**（現在はスキルと統合されています）。新しく作るなら、補助ファイルも置けるスキルの形がおすすめです。

## 10-6 良いスキルを作るコツ

1. **1スキル1作業**。「週報も請求書もSNSも」ではなく、作業ごとに分ける
2. **`description` に「いつ使うか」を書く**。言われそうな言葉（「週報」「先週の売上」）を入れておくと、自動で使われやすい
3. **手順は番号付きで、具体的に**。「いい感じにまとめる」ではなく「3行以内でまとめる」
4. **確認の手順を入れる**。「検算する」「元データと照合する」を手順に入れると、間違いが減る
5. **やってはいけないことを書く**。「ファイルは書き換えない」「推測で数字を作らない」
6. **3回使って直す**。使ってみて気になった点を「このスキルを〜するように直して」と頼んで改善する

## やってみよう

### 練習1：週報スキルを作って使う

- **目的**: スキルを作り、`/名前` で呼び出せることを確かめる
- **手順**:
  1. 練習用フォルダで起動し（`cd ~/sakura-work` → `claude`）、「テスト用の売上 CSV を data/sales-test.csv に作って。日付・講座名・金額の列で、今日を基準に直近2週間分の日付で20行くらい」と頼む
  2. 10-2 の `weekly-report` スキルを保存する（または Claude に作ってもらう）
  3. `/weekly-report` と入力する
- **期待する結果**: `reports/` に週報のファイルができ、合計や前週比が報告される
- **うまくいかないとき**: 一覧に出ない場合は、ファイルの場所が `.claude/skills/weekly-report/SKILL.md` になっているか、`---` の書式が崩れていないか確認し、Claude Code を起動し直します

### 練習2：自動で使われるか試す

- **目的**: `description` によって自動で使われることを確かめる
- **手順**: `/clear` してから「先週の売上をまとめて」と頼む
- **期待する結果**: Claude が `weekly-report` スキルを使って週報を作る
- **うまくいかないとき**: `description` に「先週の売上をまとめて」に近い言葉を足して、もう一度試します

### 練習3：自分の仕事のスキルを1つ作る

- **目的**: 自分の業務の手順をスキルにする
- **手順**: 最近3回以上同じように頼んだ作業を思い出し、「〜するスキルを作って。手順は次のとおり…」と頼む
- **期待する結果**: 次からは `/名前` だけでその作業が終わる

## まとめ

- スキルは **決まった手順の作業を書いた手順書**。`/名前` で呼ぶか、Claude が自動で使う
- 置き場所は `~/.claude/skills/<名前>/SKILL.md`（全プロジェクト）か `.claude/skills/<名前>/SKILL.md`（そのプロジェクト）
- 必須に近いのは `name` と `description`。**いつ使うか** を書くのがコツ
- 勝手に実行されると困る作業は `disable-model-invocation: true`
- 長い手順は CLAUDE.md ではなくスキルに。名前と説明は毎回読まれるが、本文は使うときだけなので軽い

## 確認テスト

**問1** CLAUDE.md とスキルの、読み込まれるタイミングの違いは何ですか？

<details><summary>答えを見る</summary>

CLAUDE.md は毎回、全文が読み込まれます。スキルは名前と説明（`description`）だけが毎回読まれ、手順の本文は使うときだけ読み込まれます。そのため、長い手順は CLAUDE.md ではなくスキルにすると、コンテキストと利用量の節約になります。

</details>

**問2** 自分の全プロジェクトで使える「sns-post」スキルを作るには、どこにファイルを置けばよいですか？

<details><summary>答えを見る</summary>

`~/.claude/skills/sns-post/SKILL.md` です。そのプロジェクトだけで使うなら `.claude/skills/sns-post/SKILL.md` に置きます。

</details>

**問3** 作ったスキルがなかなか自動で使われません。何を見直すとよいですか？

<details><summary>答えを見る</summary>

`description` です。「何をするか」だけでなく「どんなときに使うか」と、依頼で使いそうな言葉（「週報」「先週の売上」など）を書き足します。確実に使いたいときは `/名前` で直接呼び出します。

</details>

**問4** 「SNS に投稿する」スキルを、Claude が勝手に実行しないようにするには？

<details><summary>答えを見る</summary>

フロントマターに `disable-model-invocation: true` を書きます。こうすると、自分で `/名前` と入力したときだけ使われます。

</details>
