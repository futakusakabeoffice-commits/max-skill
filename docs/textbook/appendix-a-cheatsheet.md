## A-4 権限モード（`Shift + Tab` で切り替え）

| モード | 動き | 使う場面 | 詳しくは |
|---|---|---|---|
| default（画面では「Manual」と表示されることがある） | 編集やコマンドのたびに確認する | 慣れないうち、大事なファイルを扱うとき | 第5章 |
| acceptEdits | ファイル編集は確認なしで進める | テンポよく進めたいとき | 第5章 |
| plan（プランモード） | 編集せず、計画を立てて見せる | 大きな作業の前 | 第5章 |
| auto | 危なそうなときだけ確認する（対応モデル・組織の設定が必要） | 慣れてから | 第5章 |
| dontAsk | 確認が必要な操作はすべて自動で拒否する | 許可済みの操作だけで動かす自動処理 | 第5章・第14章 |
| bypassPermissions | 確認をほぼすべて省略する（deny は有効） | 隔離された専用環境のみ。**普段は使わない** | 第5章・第7章 |

## A-5 ファイルの置き場所

`~/` は自分のホームフォルダ、`./` や `.claude/` はプロジェクトのフォルダの中を表します。

| 何を | 自分の全プロジェクト用 | そのプロジェクト用（共有可） | そのプロジェクト・自分だけ | 詳しくは |
|---|---|---|---|---|
| CLAUDE.md | `~/.claude/CLAUDE.md` | `./CLAUDE.md` | `./CLAUDE.local.md` | 第8章 |
| 設定 | `~/.claude/settings.json` | `.claude/settings.json` | `.claude/settings.local.json` | 第5章 |
| スキル | `~/.claude/skills/<名前>/SKILL.md` | `.claude/skills/<名前>/SKILL.md` | — | 第10章 |
| サブエージェント | `~/.claude/agents/<名前>.md` | `.claude/agents/<名前>.md` | — | 第11章 |
| MCP | `--scope user` で追加 | `.mcp.json`（`--scope project`） | 何も付けずに追加（既定） | 第13章 |

- 同じ項目が複数の場所にあるときは、だいたい **プロジェクトに近い方が優先** されます（設定の場合: 自分だけ → プロジェクト → 全プロジェクト の順）
- `permissions.allow` などのリストは、上書きではなく **足し合わされます**

## A-6 設定ファイルの例

### 権限：`.env` を読ませない・アップロード（push）を禁止する

保存するファイル: `.claude/settings.json`

```json
{
  "permissions": {
    "allow": ["Bash(ls *)"],
    "deny": ["Read(./.env)", "Bash(git push *)"]
  }
}
```

- `allow` = 確認なしで許可、`deny` = 禁止。**deny が常に優先**
- 既にファイルがある場合は、丸ごと上書きせずに中身を合体させる

### サブエージェントの最小形

保存するファイル: `.claude/agents/<名前>.md`

```markdown
---
name: proofreader
description: 日本語の文章を校正する。下書きができたら積極的に使う（use proactively）。
tools: Read, Grep, Glob
---

あなたは校正の専門家です。誤字・表記ゆれを探し、修正案を返してください。ファイルは編集しないこと。
```

### スキルの最小形

保存するファイル: `.claude/skills/<名前>/SKILL.md`

```markdown
---
name: weekly-report
description: 売上 CSV から週次レポートを作る。「週報」と言われたら使う。
---

1. data/ の最新の CSV を読む
2. 今週の合計・前週比を計算し、検算する
3. reports/ に保存し、ファイル名と検算結果を報告する
```

## A-7 よい頼み方のテンプレート

```text
【目的】〜したい（なぜやるか）
【場所】@ファイル名 や フォルダ名
【条件】〜の形式で / 〜は変えないで / 〜字以内で
【確認方法】終わったら〜で確かめて、結果を教えて
```

例:

```text
【目的】講座の申込が増えるように、申込ページの文章を分かりやすくしたい
【場所】@pages/apply.html
【条件】料金と日程は変えない。です・ます調。専門用語は使わない
【確認方法】直したらブラウザで開いて、スマホ幅でも崩れていないか確認して
```

詳しくは第4章を見てください。

## A-8 困ったときの合言葉

| こんなとき | こう言う・こうする |
|---|---|
| 何をしているか分からない | 「今何をしようとしてる？説明して」 |
| 結果が信用できるか不安 | 「出典を付けて」「検算して」 |
| 2回直してもうまくいかない | `/clear` して、指示を書き直す |
| 危なそうな操作を求められた | 確認画面で **No** を選ぶ |
| Claude Code の使い方が分からない | 「〇〇のやり方を公式ドキュメントで調べて」 |
| 調子がおかしい | `/doctor`、またはターミナルで `claude doctor` |
