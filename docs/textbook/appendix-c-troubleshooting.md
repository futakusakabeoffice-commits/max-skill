# 付録C トラブル解決

> 困ったときに、症状から原因と対処を探せるようにまとめました。
> 見つからないときは、まず [C-1 まず試すこと](#c-1) を順番に試してください。
> Claude Code は更新が速いため、表示や動きはバージョンにより異なることがあります。

**目次**: [C-1 まず試すこと](#c-1) ／ [C-2 インストール・起動](#c-2) ／ [C-3 ログイン・プラン](#c-3) ／ [C-4 会話・作業中](#c-4) ／ [C-5 権限・確認画面](#c-5) ／ [C-6 CLAUDE.md・メモリ](#c-6) ／ [C-7 スキル](#c-7) ／ [C-8 サブエージェント](#c-8) ／ [C-9 フック](#c-9) ／ [C-10 MCP・プラグイン](#c-10) ／ [C-11 Git・GitHub](#c-11) ／ [C-12 利用量・コスト](#c-12) ／ [C-13 クラウド・自動化](#c-13) ／ [C-14 安全に関わるとき](#c-14)

<a id="c-1"></a>
## C-1 まず試すこと（どんな症状でも）

1. **`Esc` で止めて、状況を聞く**: 「今何をしようとしてる？何が起きている？」
2. **会話をリセットする**: `/clear` してから、指示を書き直す
3. **診断する**: Claude Code の中で `/doctor`、またはターミナルで `claude doctor`
4. **再起動する**: `/exit` で終了し、もう一度 `claude` で起動する
5. **最新版にする**: ターミナルで `claude update`
6. **Claude Code 自身に聞く**: 「〇〇がうまくいかない。公式ドキュメントで原因と対処を調べて」

<a id="c-2"></a>
## C-2 インストール・起動

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| `claude: command not found` と出る | インストール直後でターミナルが設定を読み込めていない。ターミナルを閉じて開き直す。それでも出る場合は、インストールをもう一度実行する。改善しなければ `claude doctor` で確認し、[PATH](appendix-b-glossary.md#g-path) の設定を見直す | 第2章 |
| Homebrew で入れたら新機能が来ない | Homebrew 版は自動更新されない。`brew upgrade claude-code` を実行する | 第2章 |
| 起動したら関係ないファイルまで見えている | ホームフォルダやデスクトップで起動している。`/exit` して、作業用の専用フォルダに `cd` してから起動し直す | 第2章 |
| `.claude` フォルダが見つからない | `.` で始まる [隠しフォルダ](appendix-b-glossary.md#g-hidden) なので普段は見えない。Mac の Finder では `⌘ + Shift + .` で表示。または Claude に「.claude フォルダの中身を一覧にして」と頼む | 第2章 |

<a id="c-3"></a>
## C-3 ログイン・プラン

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| ログインできない・使えない | 無料プランでは Claude Code は使えない。有料プラン（Pro / Max / Ultra / Team / Enterprise）か、Claude Console のアカウントか確認する | 第2章 |
| 別のアカウントで使いたい | Claude Code の中で `/login` | 第2章 |
| `--cloud` や `/teleport` が使えない | claude.ai アカウントでのログインが必要。API キーだけの利用では使えない。プランも確認する | 第14章 |

<a id="c-4"></a>
## C-4 会話・作業中

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| 指示と違うことを始めた | すぐ `Esc` で止めて、指示を言い直す。目的・場所・条件・確認方法を入れる | 第4章 |
| 2回直してもうまくいかない | 同じ会話で直し続けるより、`/clear` して指示を書き直す方が早いことが多い | 第4章・第9章 |
| 前の状態に戻したい | 入力欄が空の状態で `Esc` を2回、または `/rewind`。コマンドで変わったファイルやサブエージェントによる変更は戻らないので、Git のコミットから戻す | 第3章・第6章 |
| 動きが遅い・返事が要領を得ない | 会話が長くなりすぎている。`/context` で確認し、別の作業なら `/clear`、同じ作業なら `/compact` | 第9章 |
| 前回の続きがしたい | ターミナルで `claude -c`（前回の続き）、`claude --resume`（選んで再開） | 第3章 |
| 画像が貼り付けられない | `Ctrl + V`（Mac でも `⌘` ではなく `Ctrl`。Windows は `Alt + V`）。または入力欄にドラッグ＆ドロップ | 第3章 |
| 数字や事実が間違っていた | AI は自信満々に間違えることがある。「出典を付けて」「検算して」と頼み、最後は自分で確かめる | 第4章・第7章 |

<a id="c-5"></a>
## C-5 権限・確認画面

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| 確認画面が多すぎて進まない | よく使う安全な操作は、確認画面で「今後は確認しない」を選ぶか、`allow` ルールに入れる。`Shift + Tab` で acceptEdits にする方法もある | 第5章 |
| 確認画面で何を許可すればいいか分からない | 分からなければ **No** を選び、「今何をしようとしてる？」と聞く | 第5章・第7章 |
| `Shift + Tab` で auto が出てこない | auto は対応しているモデルと、組織の設定が必要。条件を満たさない環境では選べない | 第5章 |
| deny に書いたのに効いていない気がする | JSON の書き間違い（カンマ・括弧）がないか確認する。`/status` で設定ファイルが読み込まれているか、`claude doctor` で読み込めなかった項目がないか確認する | 第5章 |
| 設定を書いたら他の設定が消えた | 設定ファイルを丸ごと上書きした。Git のコミットから戻すか、中身を合体させて書き直す。次からは「既存の中身を消さずに追加して」と Claude に頼む | 第5章 |

<a id="c-6"></a>
## C-6 CLAUDE.md・メモリ

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| CLAUDE.md のルールを守ってくれない | 長すぎて埋もれている可能性がある。短く整理する（目安は200行以内）。絶対に守らせたいことは権限ルールやフックにする | 第8章 |
| CLAUDE.md が読まれていないようだ | ファイル名（大文字の `CLAUDE.md`）と置き場所を確認する。`/memory` で読み込まれているファイルを確認できる | 第8章 |
| 毎回同じ説明をしている | 3回同じ説明をしたら、CLAUDE.md に書くかスキルにする | 第8章・第10章 |

<a id="c-7"></a>
## C-7 スキル

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| `/スキル名` で呼び出せない | 置き場所が `.claude/skills/<名前>/SKILL.md` になっているか（フォルダの中に `SKILL.md`）確認する。ファイル名は大文字の `SKILL.md` | 第10章 |
| 自動で使ってくれない | `description` に「どんなときに使うか」を具体的に書く | 第10章 |
| 書式が崩れて読み込まれない | 先頭の `---` から2つ目の `---` までの [YAML](appendix-b-glossary.md#g-yaml) の書式（`項目: 値`、字下げ）を確認する | 第10章 |

<a id="c-8"></a>
## C-8 サブエージェント

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| 作ったのに自動で使われない | `description` があいまい。「いつ使うか」と `use proactively` を書く。または名前で指名する | 第11章 |
| 名前で頼んでも動かない | `.claude/agents/` に `.md` で保存されているか、`name` の綴りと頼むときの名前が一致しているか確認する。Claude Code を再起動する | 第11章 |
| 設定が効いていない | 項目名の綴りミス。**知らない項目名はエラーにならず無視される**。例: `disallowed_tools` ではなく `disallowedTools` | 第11章 |
| 「読むだけ」のはずがファイルが変わった | `tools` に `Bash` が入っている。外すか、フックで制限する | 第11章・第12章 |
| サブエージェントが前の話を知らない | 仕様どおり。依頼文に目的・対象・完了条件を書く。会話をまるごと引き継ぎたいならフォークを使う | 第11章 |
| メインの会話がすぐいっぱいになる | サブエージェントの報告が長すぎる。「結論と根拠を10行以内で」など、報告の長さを指定する | 第11章 |

<a id="c-9"></a>
## C-9 フック

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| フックが動かない | 設定ファイルの `hooks` の書式（JSON）を確認する。`/hooks` で登録されているか確認する | 第12章 |
| フックのスクリプトが実行できない | 実行権限がない。`chmod +x スクリプト名` を実行する。`jq` など必要なツールが入っているか確認する | 第12章 |
| 関係ないファイルまで書き換わった | フックのコマンドが `.`（フォルダ全体）を対象にしている。編集されたファイルだけを対象にする形に直す | 第12章 |
| Windows で動かない | Mac / Linux 向けのコマンド（`jq`、`$(...)` など）はそのままでは動かないことがある | 第12章 |

<a id="c-10"></a>
## C-10 MCP・プラグイン

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| MCP サーバーがつながらない | `/mcp` で接続状況を確認し、必要ならログインする。`claude mcp list` で登録されているか確認する | 第13章 |
| 入れたプラグインが反映されない | `/reload-plugins` を実行する | 第13章 |
| 利用量が急に増えた | 使っていない MCP サーバーやプラグインも、有効なだけで毎回少しずつ消費する。不要なものは切る | 第9章・第13章 |
| 他の人と MCP 設定を共有したい | `--scope project` で追加すると `.mcp.json` に保存され、共有できる | 第13章 |

<a id="c-11"></a>
## C-11 Git・GitHub

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| Git の操作が分からない | コマンドを覚えなくてよい。「ここまでの変更をコミットして」「昨日と比べて何が変わったか教えて」と頼む | 第6章 |
| 前のコミットに戻したら作業が消えた | コミットしていない変更は戻すと消える。次からは「戻す前に、消える変更がないか確認して」と添える | 第6章 |
| `.env` をコミットしてしまった | すぐに Claude に相談して記録から取り除く。**GitHub に上げてしまった場合は、そのキーは漏れたものとして、サービス側でキーを無効化・再発行する** | 第6章・第7章 |
| `--worktree` が使えない | Git で管理されていないフォルダでは使えない。先に「このフォルダを Git で管理できるようにして」と頼む | 第14章 |
| `/install-github-app` がうまくいかない | github.com のリポジトリが対象で、リポジトリの管理者権限が必要 | 第14章 |

<a id="c-12"></a>
## C-12 利用量・コスト

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| すぐに利用上限に達する | 別の作業に移るたびに `/clear`。CLAUDE.md を短く。簡単な作業は Sonnet や Haiku に（`/model`）。不要な MCP・プラグインを切る | 第9章 |
| 今どれくらい使ったか知りたい | `/usage` | 第9章 |
| それでも毎日上限に当たる | 使い方を見直しても足りないなら、上位プラン（Max など）を検討する目安 | 第9章 |
| `Concurrent subagent limit reached` と出る | 同時に動かせるサブエージェントの上限（既定20個）に達している。終わるのを待つ | 第11章 |

<a id="c-13"></a>
## C-13 クラウド・自動化

| 症状 | 原因と対処 | 詳しくは |
|---|---|---|
| クラウドで手元のファイルが見つからない | クラウドは手元のパソコンのファイルを直接見られない。ローカルで作業するか、GitHub の非公開リポジトリに置く | 第14章 |
| `/schedule` で予約した作業の時間がずれる | 「日本時間の7時」のようにタイムゾーンを書く | 第14章 |
| `claude -p` で途中で止まる・失敗する | 非対話モードでは確認画面に答えられない。読むだけの作業にするか、必要な操作を `allow` に入れておく | 第14章 |
| 不要になった予約を止めたい | Claude に「予約を一覧にして、〇〇を止めて」と頼む | 第14章 |

<a id="c-14"></a>
## C-14 安全に関わるとき

> **注意**: 次のようなときは、作業を続けずにまず止めてください（`Esc`、確認画面なら **No**）。

| こんなとき | すること | 詳しくは |
|---|---|---|
| Claude が、頼んでいない送信・削除・購入などをしようとしている | すぐ止める。読ませた Web ページやファイルに「隠れた指示」（[プロンプトインジェクション](appendix-b-glossary.md#g-prompt-injection)）が入っていた可能性がある | 第7章 |
| パスワードや API キーを会話に貼ってしまった | そのキーは漏れたものとして扱い、サービス側で無効化・再発行する | 第7章 |
| お客様の個人情報を読ませてしまった | 今後は必要最小限にする。プランごとのデータの保存期間を確認する | 第7章 |
| 知らない MCP サーバーやプラグインを入れてしまった | 削除する（`claude mcp remove <名前>`、`/plugin`）。信頼できる提供元のものだけを使う | 第13章 |
