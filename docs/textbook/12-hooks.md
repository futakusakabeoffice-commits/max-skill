# 第12章 フック：決まったタイミングで必ず実行する

> **この章で学ぶこと**
> - フックとは何か、CLAUDE.md や権限設定とどう違うか
> - フックを書く場所と、設定の基本の形
> - フックが動くタイミング（イベント）の種類
> - 実例：`.env` を守る／編集したファイルを整形する／確認待ちを通知する
> - フックを安全に使うための注意点
>
> **所要時間の目安**: 60分 ／ **前提**: 第5章（権限と設定）・第8章（CLAUDE.md）を読んでいること。この章は少し技術的です。最初は 12-1 と 12-5 の注意点だけ読んで、必要になったら戻ってきても構いません

## 12-1 フックとは

フックは、**「〜したときに、必ずこの処理を実行する」という自動の仕掛け** です。

たとえば次のようなことができます。

- Claude がファイルを編集したら、**必ず** 整形ツールで見た目を整える
- Claude が `.env`（パスワードなどを書いたファイル）を開こうとしたら、**必ず** 止める
- Claude が確認を待っているときに、パソコンに通知を出す

### CLAUDE.md・権限設定・フックの違い

| | CLAUDE.md（第8章） | 権限設定（第5章） | フック（この章） |
|---|---|---|---|
| ひとことで | お願い | 許可・禁止のリスト | 自動で動くプログラム |
| 確実さ | 守られないこともある | ルールに合えば確実 | 確実に実行される |
| できること | 方針や好みを伝える | ツールやコマンドを許可・禁止する | 中身を見て判断する・別の処理を実行する |
| 難しさ | やさしい | ふつう | 少し難しい（コマンドを書く） |

**まずは権限設定の `deny` で足りないか考え、足りないときにフックを使う** のがおすすめです。

> **注意**: フックは **あなたの権限で、確認なしに** 自動実行されます。中身を理解していないフックや、出どころの分からないフックは設定しないでください。

## 12-2 フックを書く場所と基本の形

フックは設定ファイル（JSON 形式）の `hooks` という項目に書きます。

| ファイル | 効く範囲 |
|---|---|
| `~/.claude/settings.json` | 自分の全プロジェクト |
| `.claude/settings.json` | そのプロジェクト（Git で共有できる） |
| `.claude/settings.local.json` | そのプロジェクト・自分だけ |

このほか、サブエージェントの設定の中に書くと、そのサブエージェントが動いている間だけ有効になります（[第11章](11-subagents.md)）。

### 基本の形

```json
{
  "hooks": {
    "イベント名": [
      {
        "matcher": "対象にするツール名",
        "hooks": [
          { "type": "command", "command": "実行するコマンド" }
        ]
      }
    ]
  }
}
```

- **イベント名**: いつ動くか（12-3）
- **matcher**: どのツールのときに動くか。`"Edit|Write"` のように `|` で複数指定できる
- **command**: 実行するコマンド

> **注意**: すでに設定ファイルがある場合は、**丸ごと上書きせずに中身を合体させて** ください。JSON はカンマや括弧が1つずれるだけで動かなくなります。不安なら「このフックを .claude/settings.json に追加して」と Claude に頼むのが安全です。

設定したフックは、Claude Code の中で `/hooks` と入力すると確認できます。

## 12-3 フックが動くタイミング（イベント）

よく使うものだけ覚えれば十分です。

| イベント | いつ動くか | 使いみちの例 |
|---|---|---|
| `PreToolUse` | ツールを使う **直前** | 危ない操作を止める |
| `PostToolUse` | ツールを使った **直後** | 編集したファイルを整形する |
| `Notification` | Claude Code が通知を出すとき（確認待ちなど） | パソコンに通知を出す |
| `Stop` | Claude が作業を終えたとき | 最後にチェックを実行する |
| `SessionStart` | セッションが始まったとき | 作業の準備をする |
| `UserPromptSubmit` | 自分が指示を送ったとき | 指示に情報を書き足す |

このほかにも、サブエージェントの開始・終了（`SubagentStart` / `SubagentStop`）など多くのイベントがあります。種類はバージョンにより異なるので、必要になったら公式ドキュメント（Hooks のページ）で確認してください。

### フックの結果の伝え方（終了コード）

フックのコマンドは、終わるときに **終了コード** という数字を返します。

| 終了コード | 意味 |
|---|---|
| `0` | 問題なし。そのまま進める |
| `2` | **ブロック**。`PreToolUse` なら、そのツールの実行を止める。エラー出力（`>&2` で出したメッセージ）が Claude に伝わる |

`PostToolUse` のように「もう実行し終わった後」のイベントで `2` を返しても、実行は取り消せません。メッセージが Claude に伝わるだけです。

### フックに渡される情報

フックのコマンドには、**標準入力** という形で、ツールの情報が JSON で渡されます。たとえばファイルを編集するときは、`tool_input.file_path` に対象のファイルのパスが入っています。この情報を取り出すために、`jq`（JSON を扱うコマンド）をよく使います。

> jq は Mac なら `brew install jq` などで入れておきます。

## 12-4 実例

### 実例1：`.env` ファイルを読み書きさせない

さくらさんのフォルダには、決済サービスの API キー（サービスを使うための合言葉）を書いた `.env` があります。これを Claude に **絶対に** 読ませたくありません。

保存するファイル: `.claude/hooks/protect-env.sh`

```bash
#!/bin/bash
# jq がないとチェックできないので、その場合は安全側（ブロック）に倒す
command -v jq >/dev/null 2>&1 || { echo "jq が見つかりません。インストールしてください。" >&2; exit 2; }

# ツールの入力（JSON）から、対象のファイルパスを取り出す
FILE=$(jq -r '.tool_input.file_path // empty')
NAME=$(basename "$FILE")

# .env / .env.local / .env.production などはブロック（.env.example は許可）
if [[ "$NAME" == ".env" || ( "$NAME" == .env.* && "$NAME" != ".env.example" ) ]]; then
  echo ".env ファイルは秘密情報なので、読み書きできません。" >&2
  exit 2
fi
exit 0
```

実行できるようにします。

```bash
mkdir -p .claude/hooks
# （上のスクリプトを .claude/hooks/protect-env.sh に保存してから）
chmod +x .claude/hooks/protect-env.sh
```

保存するファイル: `.claude/settings.json`

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Read|Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "\"${CLAUDE_PROJECT_DIR}\"/.claude/hooks/protect-env.sh"
          }
        ]
      }
    ]
  }
}
```

- `matcher` の `Read|Edit|Write` で、ファイルを **読む・編集する・作る** ときにだけ動きます。
- `${CLAUDE_PROJECT_DIR}` は、プロジェクトのフォルダの場所に置き換わります。どのフォルダで作業していても、スクリプトが見つかるようにするための書き方です。
- `.env.example`（中身が空のひな形）は、共有されることが多いので許可しています。

> **注意**: このフックが止めるのは、Claude の **ファイルを読む・書くツール** だけです。コマンド（`Bash`）経由で読む方法は止められません。権限設定の `deny` に `"Read(./.env)"` も書いて二重に守り（[第5章](05-permissions-settings.md)）、そもそも `.env` を Git にコミットしないようにしましょう（[第7章](07-safety.md)）。

### 実例2：編集したファイルだけを整形する（Mac / Linux 向け）

Claude がファイルを編集・作成するたびに、**そのファイルだけ** を整形ツール Prettier で整えます。

保存するファイル: `.claude/settings.json`（実例1と一緒に使うときは、`"hooks"` の中に `"PostToolUse"` を並べて書きます）

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "f=$(jq -r '.tool_input.file_path') && npx --yes prettier --write --ignore-unknown \"$f\""
          }
        ]
      }
    ]
  }
}
```

> - Node.js（プログラムを動かす土台ソフト）と jq が必要です。Windows ではそのままでは動きません。整形ツールを使っていないなら、試さなくて大丈夫です。
> - ブログ記事の Markdown や CLAUDE.md なども整形の対象になり、改行などが変わることがあります。
> - `.`（フォルダ全体）を対象にするコマンドは、関係ないファイルまで書き換えてしまうので避けましょう。

### 実例3：確認待ちのときに通知を出す（Mac 向け）

Claude に作業を任せて別のことをしていると、確認待ちで止まっていることに気づかないことがあります。通知を出すと便利です。

保存するファイル: `~/.claude/settings.json`（全プロジェクトで使う）

```json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude Code が確認を待っています\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}
```

> `osascript` は Mac に最初から入っている命令です。Windows や Linux では別の方法が必要です。

### 実例を組み合わせるとき

1つの設定ファイルに複数のフックを書くときは、`"hooks"` の中にイベントを並べます。

```json
{
  "hooks": {
    "PreToolUse": [ … 実例1の中身 … ],
    "PostToolUse": [ … 実例2の中身 … ]
  }
}
```

（`…` の部分は、実例の `[` から `]` までをそのまま入れます。この形のままでは動かないので注意してください）

## 12-5 フックを安全に使うために

1. **中身を理解したものだけ設定する**。フックは確認なしで実行されます
2. **出どころの分からないフックを貼り付けない**。Web で見つけた設定や、プラグインに入ったフックも内容を確認する
3. **まず小さく試す**。練習用のフォルダで動きを確かめてから、本番のプロジェクトに入れる
4. **失敗したら安全側に倒す**。必要なツール（jq など）がないときは、素通りさせずにブロックする（実例1の1行目）
5. **フックだけに頼らない**。大事なものは権限設定・Git・バックアップと組み合わせて守る

> 自分で書くのが不安なら、「`.env` を読ませないフックを設定して。設定する前に中身を説明して」と Claude に頼むこともできます。**説明を読んで納得してから** 承認しましょう。

## やってみよう

### 練習1：`.env` を守るフックを入れる

- **目的**: `PreToolUse` フックでツールの実行を止められることを確かめる
- **手順**:
  1. 練習用のフォルダに、中身が `TEST_KEY=dummy` だけの `.env` を作る
  2. 実例1のスクリプトと設定を保存し、`chmod +x` する
  3. Claude Code を起動して「.env の中身を教えて」と頼む
- **期待する結果**: 「.env ファイルは秘密情報なので、読み書きできません。」と止められる
- **うまくいかないとき**: `/hooks` でフックが登録されているか確認します。スクリプトの場所（`.claude/hooks/protect-env.sh`）と実行権限、jq が入っているかも確認します

### 練習2：確認待ちの通知を出す（Mac の人）

- **目的**: `Notification` フックを体験する
- **手順**: 実例3を `~/.claude/settings.json` に追加し、Claude Code を起動し直して、ファイルの作成を頼む
- **期待する結果**: 確認画面が出たときに、Mac の画面の右上に通知が出る
- **うまくいかないとき**: Mac の「システム設定」→「通知」で、ターミナル（またはスクリプトエディタ）の通知が許可されているか確認します

## まとめ

- フックは **「〜したときに必ず実行する」自動の仕掛け**。CLAUDE.md の「お願い」と違い、確実に動く
- 設定ファイルの `hooks` に「イベント・matcher・コマンド」で書く。`/hooks` で確認できる
- よく使うイベントは `PreToolUse`（直前に止める）と `PostToolUse`（直後に処理する）
- 終了コード `2` で `PreToolUse` のツール実行をブロックできる
- フックはあなたの権限で確認なしに動く。**中身を理解したものだけ** 設定する

## 確認テスト

**問1.** 「Claude がファイルを編集する前に、内容をチェックして止めたい」とき、どのイベントを使いますか？

<details><summary>答えを見る</summary>

`PreToolUse` です。ツールを使う直前に動くので、終了コード `2` を返せば実行を止められます。`PostToolUse` は実行した後なので、止めることはできません。

</details>

**問2.** フックのスクリプトが終了コード `2` を返し、`>&2` でメッセージを出しました。どうなりますか？（`PreToolUse` の場合）

<details><summary>答えを見る</summary>

そのツールの実行がブロックされ、メッセージが Claude に伝わります。Claude はその理由を読んで、別の方法を考えます。

</details>

**問3.** 実例1の `.env` を守るフックだけで、`.env` の中身は完全に守られますか？

<details><summary>答えを見る</summary>

完全ではありません。止めているのはファイルを読む・書くツールだけで、コマンド経由で読む方法は止められません。権限設定の `deny` と組み合わせ、`.env` を Git にコミットしないなど、複数の方法で守ります。

</details>

**問4.** フックを設定するときに、いちばん気をつけるべきことは何ですか？

<details><summary>答えを見る</summary>

フックはあなたの権限で、確認なしに自動で実行されることです。中身を理解していないものや、出どころの分からないものは設定しないようにします。

</details>
