# Claude Code の教科書

**AI に「手を動かす仕事」を任せるための、はじめての人向け教科書**

- **対象**: Claude Code をこれから使う人、使い始めたばかりの人。プログラミングの経験がなくても読めるように書いています
- **情報の基準**: 公式ドキュメント https://code.claude.com/docs/ （2026年11月時点）
- **注意**: Claude Code は月単位で機能が増えたり名前が変わったりします。画面やコマンドが本書と違うときは、公式ドキュメントを確認するか、Claude Code 自身に「〜のやり方を公式ドキュメントで調べて」と聞いてください

---

## この教科書の使い方

### 一緒に学ぶ人：さくらさん

本書では、架空の個人事業主 **さくらさん** の仕事を例に進めます。

#### 登場人物：さくらさん

| 項目 | 設定 |
|---|---|
| 仕事 | Web デザインとオンライン講座を一人で運営 |
| 講座名 | 「はじめての Web デザイン」 |
| お客様 | 30〜50代の個人事業主・小さなお店のオーナー |
| ブランドカラー | #2E7D6B |
| 練習用フォルダ | `~/sakura-work`（第2〜14章で共通） |
| 総まとめ用フォルダ | `~/sakura-office`（第15章で新しく作る） |

- パソコンは毎日使うが、プログラミングはしたことがない
- 「請求書の集計」「お問い合わせへの返信」「ブログの表記ゆれ直し」「競合の調査」に毎週何時間も取られている

さくらさんと同じように、**自分の仕事に置き換えながら** 読み進めてください。

### 各章の構成

どの章も同じ形でできています。

| パート | 内容 |
|---|---|
| この章で学ぶこと | 章のゴール・所要時間の目安・前提となる章 |
| 本文（N-1, N-2 …） | 仕組みと使い方の説明 |
| やってみよう | 実際に手を動かす練習。**ここを飛ばさないのが上達の近道** |
| まとめ | 章の要点 |
| 確認テスト | 理解度チェック。答えは「答えを見る」をクリック |

### 表記のルール

| 表記 | 意味 |
|---|---|
| **Claude** | AI（頭脳）のこと |
| **Claude Code** | Claude があなたのパソコンで作業するための道具（アプリ）のこと |
| `このような文字` | 入力するコマンドやファイル名 |
| 保存するファイル: `パス` | そのコードを保存する場所 |
| > **注意** | 失敗しやすいポイントや安全上の注意 |

分からない言葉が出てきたら、[付録B 用語集](appendix-b-glossary.md) を開いてください。

## 学習ロードマップ

全部を一度に覚える必要はありません。次の順番で、**使いながら** 少しずつ進めるのがおすすめです。

### 1日目：動かしてみる（約1〜2時間）

- [ ] 第1章を読んで、Claude Code で何ができるかをつかむ
- [ ] 第2章のとおりにインストールしてログインする
- [ ] 第3章で、講座の紹介ページを作って直してみる
- [ ] 第4章を読んで、自分の仕事の依頼文を1つ書いてみる

**ゴール**: 「日本語で頼むと、ファイルを作って直してくれる」を体験する

### 1週目：毎日の仕事で使う（1日15〜30分）

- [ ] 毎日1つ、自分の実際の仕事を Claude Code に頼んでみる（第4章のテンプレートを使う）
- [ ] 第5章で権限モードを理解し、プランモードを使ってみる
- [ ] 第6章で Git を始め、うまくいったらコミットする習慣をつける
- [ ] 第7章を読んで、安全に使うためのルールを確認する
- [ ] 第8章で、自分のプロジェクトに CLAUDE.md を作る
- [ ] 第9章を読んで、`/clear` で会話を区切る習慣をつける

**ゴール**: 安全に、自分の仕事のペースで使えるようになる

### 1か月目：自分専用に育てる

- [ ] 同じ説明を3回したら、CLAUDE.md かスキルにする（第8章・第10章）
- [ ] 校正担当や調査担当のサブエージェントを1つ作る（第11章）
- [ ] 必要になったら、フックや MCP を試す（第12章・第13章）
- [ ] 定期的な作業を自動化する（第14章）
- [ ] 第15章の総まとめに挑戦する

**ゴール**: 「毎週何時間もかかっていた作業」が、依頼1つで終わる状態を作る

> **注意**: 最初から完璧な仕組みを作ろうとしなくて大丈夫です。**小さく始めて、困ったら育てる** のが一番うまくいきます。
