# 第14章 自動化とクラウド：Claude Code に「任せておく」

> **この章で学ぶこと**
> - `claude -p` を使って、1回で終わる作業を自動化する方法
> - 複数の作業を並行して進める方法（ターミナルを複数開く、worktree、バックグラウンド）
> - クラウドで動かして、パソコンを閉じても作業を続けてもらう方法
> - `/schedule` で毎朝の作業を予約する方法と、GitHub との連携
> - 自動化するときの安全の考え方
>
> **所要時間の目安**: 60〜90分
> **前提**: 第1〜13章（特に第5章 権限、第7章 安全、第9章 コンテキストとコスト）

---

ここまでの章では、あなたが Claude Code の前に座って、会話しながら作業を進めてきました。この章では一歩進めて、**あなたが見ていない間も Claude に働いてもらう** 方法を学びます。

さくらの場合なら、こんな使い方が考えられます。

- 寝ている間に、講座の受講者アンケートを集計しておいてもらう
- 外出前にスマホから「ポートフォリオサイトの古いリンクを直しておいて」と頼み、帰りの電車で結果を確認する
- 毎朝7時に、Webデザイン業界のニュースまとめを作ってもらう

> **注意**: 自動化は便利ですが、「見ていない間に動く」ということは「間違いにすぐ気づけない」ということでもあります。最初は小さな作業から始め、結果を必ず確認する習慣をつけてください（14-7）。

---

## 14-1 非対話モード（`claude -p`）：1回で終わる作業を自動化する

ふつう `claude` と起動すると、会話の画面が開きます。これを **対話モード** と呼びます。

一方、`-p` を付けて起動すると、**質問を1回だけ渡して、答えを受け取ったらすぐ終了** します。これを **非対話モード** と呼びます（[用語集](appendix-b-glossary.md#g-noninteractive)）。

```bash
claude -p "data/sales.csv を集計して、今月の売上合計だけを答えて"
```

### 他のコマンドの結果を渡す（パイプ）

`|`（パイプ）を使うと、別のコマンドの出力を Claude に渡せます。

```bash
cat report.txt | claude -p "この文章を3行で要約して"
```

```bash
git log --oneline -20 | claude -p "最近の変更を、お客様向けのお知らせ文にまとめて"
```

### 前回の続きで1回だけ頼む

```bash
claude -c -p "さっき作った週報に、来週の予定も追記して"
```

`-c` は「このフォルダの前回の会話の続き」という意味です（第3章）。

### どんなときに使うか

| 向いている | 向いていない |
|---|---|
| 答えが1回で決まる作業（要約、集計、変換） | 途中で相談しながら決めたい作業 |
| 毎回同じ形の作業（定型レポートなど） | 何をすべきかまだ自分でも分かっていない作業 |
| 他のツールやスクリプトと組み合わせたい作業 | 確認画面に答える必要がある作業 |

> **注意**: 非対話モードでは、途中で「やってもいいですか？」と聞かれても答えられません。許可が必要な操作は、あらかじめ権限ルール（第5章）で許可しておくか、そもそも許可が要らない作業（読むだけ・答えるだけ）に限るのが安全です。

## 14-2 複数の作業を並行して進める

### 方法1：ターミナルを複数開く

いちばん簡単な方法です。ターミナルのウィンドウ（またはタブ）を2つ開き、それぞれで `claude` を起動すれば、2人の Claude に別々の仕事を頼めます。

- ウィンドウ1: 「講座の申込ページの文章を見直して」
- ウィンドウ2: 「先月の売上データを集計して」

> **注意**: 2つの Claude が **同じファイルを同時に編集** すると、片方の変更がもう片方を上書きしてしまうことがあります。並行させるのは、扱うファイルが重ならない作業にしましょう。

### 方法2：worktree（作業用の分身フォルダ）を使う

同じプロジェクトの中で並行して作業させたいときは、**worktree** を使います（[用語集](appendix-b-glossary.md#g-worktree)）。

```bash
claude --worktree lp-renewal
```

`--worktree`（短く書くと `-w`）を付けて起動すると、Git の仕組みを使って **作業用の分身フォルダ** が作られ、その中で Claude が作業します。元のフォルダのファイルには影響しないので、ぶつかる心配がありません。

- Git で管理しているフォルダでのみ使えます（第6章）
- 分身フォルダでの変更を元のフォルダに取り込むのも、Claude に頼めます（「この worktree の変更を main に取り込んで」など）

### 方法3：時間のかかる作業をバックグラウンドに回す

実行中のコマンドやサブエージェントが長引きそうなときは、**`Ctrl + B`** を押すと **バックグラウンド**（裏側）に回せます。その間も会話を続けられます。

- Mac でも `⌘` ではなく `Ctrl` を使います
- 裏で動いている作業の一覧は `/tasks` で確認できます

サブエージェントを並行で動かす方法は、第11章も参照してください。

## 14-3 クラウドで動かす：パソコンを閉じても作業が続く

### クラウドセッションとは

Web 版（claude.ai/code）やスマホの Claude アプリから始めた作業は、あなたのパソコンではなく **Anthropic のクラウド（インターネット上のコンピューター）** で動きます。これを **クラウドセッション** と呼びます。

| | 手元（ローカル）で動かす | クラウドで動かす |
|---|---|---|
| 動く場所 | 自分のパソコン | Anthropic のサーバー |
| パソコンを閉じると | 止まる | **作業が続く** |
| 扱えるファイル | 自分のパソコンのファイル | クラウドに用意された作業場所のファイル（GitHub のリポジトリなど） |
| 始め方 | ターミナルで `claude` | claude.ai/code、スマホアプリ、または `claude --cloud` |

### 使える条件

> **注意**: クラウド機能は **Pro / Max / Ultra / Team / Enterprise** のプランで使えます（Enterprise は席の種類によります。無料プランでは使えません）。`--cloud` や `/teleport` は **claude.ai アカウントでのログイン** が必要で、API キーだけの利用では使えません。また、クラウドでの作業も **プランの利用量にカウント** されます（第9章）。

### ターミナルからクラウドに任せる

```bash
claude --cloud "ポートフォリオサイトのリンク切れを探して直して"
```

### クラウドの作業を手元に持ってくる

クラウドで進めた作業の続きを自分のパソコンでやりたいときは、次のどちらかを使います。

```bash
claude --teleport
```

または、Claude Code の中で次のように入力します。

```text
/teleport
```

### さくらの使い方の例

1. 朝、家を出る前にスマホの Claude アプリで「講座ページの料金表を新料金に更新して、変更点をまとめておいて」と頼む
2. 移動中に、スマホで進み具合と結果を確認する
3. 帰宅後、内容に問題がなければ取り込む

> **注意**: クラウドは **あなたのパソコンの中のファイルや設定（`~/.claude` など）を直接は見られません**。手元にしかないファイルを使う作業は、ローカルで動かすか、GitHub の非公開リポジトリ（第6章）に置いてから頼みましょう。

## 14-4 定期実行：`/schedule` で毎日の作業を予約する

`/schedule` を使うと、**決まった時間に自動で Claude に作業してもらう予約** ができます。クラウドで動く機能です。

```text
/schedule 毎朝 日本時間の7時に、Webデザイン業界の昨日のニュースを5つ選んで3行ずつ要約して
```

- `/schedule` の後ろに、やってほしいことを書きます。設定の途中で Claude が詳細（時間や内容など）を質問してくるので、答えていきます
- 時間は「日本時間の」と書いておくと、ずれる心配がありません

> **注意**:
> - クラウドで動くので、**手元のパソコンのファイルは読めません**
> - **実行のたびにプランの利用量を消費** します。毎時間などの頻繁な予約は、利用量を圧迫します
> - 予約した作業の結果は、ときどき見直しましょう。情報源が変わって品質が落ちていることがあります

### `/loop` との違い

| | `/schedule` | `/loop` |
|---|---|---|
| 動く場所 | クラウド | 今開いている会話の中 |
| 会話を閉じると | 予約は残る | 止まる |
| 向いている | 毎朝・毎週などの定期作業 | 「5分ごとに状況を確認して」など、その場での繰り返し |

## 14-5 GitHub と連携する

GitHub（[用語集](appendix-b-glossary.md#g-github)）を使っている場合は、GitHub 上から Claude に作業を頼めます。

### 設定する

Claude Code の中で次を実行します。

```text
/install-github-app
```

> **注意**: github.com のリポジトリが対象です。設定するには、そのリポジトリの **管理者権限** が必要です。

### 使う

設定が終わると、GitHub の **Issue**（やることメモ）や **プルリクエスト**（変更の取り込み依頼）のコメント欄に `@claude` と書くだけで、Claude が作業してくれます。

```text
@claude トップページのお知らせ欄に「12月の講座日程」を追加してください
```

GitHub 上の操作の考え方は、第6章も参照してください。

## 14-6 知っておくと良い機能

ここで紹介する機能は、最初は使わなくても困りません。「そういう機能があった」と覚えておき、必要になったら公式ドキュメントで調べてください。

| 機能 | ひとことで | メモ |
|---|---|---|
| **エージェントチーム** | 複数の Claude が役割を分担し、互いにやり取りしながら1つの仕事を進める | 利用量がかなり増えます。公式ドキュメントでは、チームメンバーがプランモードで動く場合に **約7倍のトークン** を使うとされています |
| **出力スタイル** | Claude の答え方（口調・詳しさなど）を切り替える | `/output-style` で切り替えます |
| **Remote Control** | 自分のパソコンで動いている Claude Code を、スマホや Web から操作する | `/remote-control` で始めます。クラウドと違い、作業は手元のパソコンで行われます |
| **Slack 連携** | Slack の中から Claude に作業を頼む | Team / Enterprise プラン向けの機能です |

> Claude Code は更新が速く、機能の名前や使い方が変わることがあります（バージョンにより異なる）。分からないときは、Claude Code に「〇〇の使い方を公式ドキュメントで調べて」と聞くのが確実です。

## 14-7 自動化するときの安全の考え方

自動化では、Claude の行動をその場で見張れません。次の5つを守りましょう。

1. **最初は「読むだけ・まとめるだけ」の作業から**
   ファイルを書き換えたり、外部に送信したりする自動化は、慣れてからにします。
2. **権限は最小限に**
   自動で動かす作業に必要な操作だけを `allow` に入れ、危ない操作は `deny` にします（第5章）。確認画面を出さずに **許可していない操作は自動で拒否** する `dontAsk` モードは、こうした自動処理向けのモードです。
3. **確認なしで全部を許すモード（bypassPermissions）は使わない**
   隔離された専用環境のためのモードです。普段の自動化には使いません（第5章・第7章）。
4. **Web から集めた情報には「隠れた指示」が混ざることがある**
   調べもの中に読んだページに、Claude をだまそうとする文章（プロンプトインジェクション）が入っていることがあります。自動で集めた情報をそのまま公開したり、送信したりしないでください（第7章）。
5. **結果は人が確認してから使う**
   特に、お客様へのメール送信・サイトの公開・お金に関わる作業は、必ず自分で内容を見てから実行します。

## やってみよう

### 演習1：`-p` で要約してみる

- **目的**: 非対話モードの動きを体験する
- **手順**:
  1. 練習用のフォルダで、Claude に「テスト用の短いお知らせ文を notice.txt に作って」と頼む（対話モードで）
  2. `/exit` で終了する
  3. ターミナルで次を実行する
     ```bash
     cat notice.txt | claude -p "この文章を1行で要約して"
     ```
- **期待する結果**: 会話の画面は開かず、1行の要約が表示されてすぐ終了する
- **うまくいかないとき**: `notice.txt` が今いるフォルダにあるか確認する（`ls` で一覧表示）。Windows の PowerShell でも `cat` はそのまま使えます

### 演習2：worktree で並行作業してみる

- **目的**: 元のファイルを汚さずに試す方法を体験する
- **手順**:
  1. Git で管理しているフォルダ（第6章で作ったもの）で `claude --worktree trial` と起動する
  2. 「index.html の見出しの色を赤にして」と頼む
  3. 終わったら、元のフォルダの `index.html` が変わっていないことを確認する
- **期待する結果**: 分身フォルダの中だけが変わり、元のフォルダはそのまま
- **うまくいかないとき**: Git で管理されていないフォルダでは使えません。先に「このフォルダを Git で管理できるようにして」と頼みます

### 演習3：毎朝のまとめを予約してみる（クラウドが使えるプランの人のみ）

- **目的**: 定期実行を体験する
- **手順**:
  1. Claude Code の中で `/schedule 毎朝 日本時間の7時に、あなたの業界の昨日のニュースを3つ要約して` と入力する
  2. Claude の質問に答えて設定を終える
  3. 翌朝、結果を確認する
- **期待する結果**: 指定した時間に要約が作られている
- **うまくいかないとき**: claude.ai アカウントでログインしているか、プランが対応しているか確認する（14-3）。不要になった予約は、Claude に「予約を一覧にして、〇〇を止めて」と頼みます

## まとめ

- `claude -p "〜"` は1回だけ答えて終了する。パイプ `|` と組み合わせると、他のコマンドの結果を渡せる
- 並行作業は、ターミナルを複数開くか `claude --worktree <名前>` で。長い作業は `Ctrl + B` で裏に回せる
- クラウド（claude.ai/code、スマホ、`--cloud`）ならパソコンを閉じても作業が続く。ただし手元のファイルは見えない
- `/schedule` で定期作業を予約できる。実行のたびに利用量を消費する
- 自動化は「読むだけの作業から」「権限は最小限」「結果は人が確認」が鉄則

## 確認テスト

**Q1.** `claude -p` で起動したとき、ふつうの `claude` と何が違いますか？

<details><summary>答えを見る</summary>

質問を1回だけ渡して答えを受け取ると、**すぐ終了** します（非対話モード）。会話の画面は開かず、途中の確認画面にも答えられないので、許可が要らない作業か、あらかじめ権限ルールで許可した作業に向いています。

</details>

**Q2.** さくらは、ポートフォリオサイトの修正と講座ページの修正を、同じプロジェクトで同時に進めたいと考えています。ぶつからないようにするにはどうしますか？

<details><summary>答えを見る</summary>

`claude --worktree <名前>`（または `-w`）で、作業用の分身フォルダの中で動かします。それぞれが別のフォルダで作業するので、同じファイルを同時に書き換える心配がありません。Git で管理しているフォルダであることが前提です。

</details>

**Q3.** クラウドで動く `/schedule` に「デスクトップにある売上.xlsx を集計して」と頼みました。うまくいかないのはなぜですか？

<details><summary>答えを見る</summary>

クラウドで動く作業は、**手元のパソコンの中のファイルを直接読めない** からです。手元のファイルを使う作業はローカルで動かすか、GitHub の非公開リポジトリなど、クラウドから見られる場所に置く必要があります。

</details>

**Q4.** 自動化した作業で、Web から集めた情報をそのままお客様にメールで送る仕組みは、なぜ危ないのですか？

<details><summary>答えを見る</summary>

Web ページには、間違った情報や、Claude をだまそうとする「隠れた指示」（プロンプトインジェクション）が含まれていることがあるからです。また AI 自身が間違えることもあります。お客様への送信・公開・お金に関わる作業は、必ず人が内容を確認してから実行します。

</details>
