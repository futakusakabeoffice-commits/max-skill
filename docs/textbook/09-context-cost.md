## 9-1 コンテキストとは：Claude の「作業机」

**コンテキスト** は、Claude がその会話で覚えていられる情報のことです。作業机に例えると分かりやすくなります。

- 会話のやり取り、読んだファイル、コマンドの結果が、どんどん机の上に積まれていく
- 机の広さには **上限がある**
- いっぱいになると、古い内容が **要約されて圧縮される**（細かい部分は忘れてしまう）

机が散らかると、次のような困りごとが起きます。

| 困りごと | 理由 |
|---|---|
| 前の作業の話に引っ張られる | 関係ない情報が机に残っている |
| 最初に伝えたルールを忘れる | 圧縮のときに細かい指示が抜け落ちる |
| 利用量が早く減る | 毎回、机の上の情報を読み直している |

コンテキストの量は **トークン**（AI が文章を数える単位）で数えます。用語は[付録B 用語集](appendix-b-glossary.md)も参照してください。

## 9-2 覚えておきたい4つのコマンド

| コマンド | 何をするか | いつ使うか |
|---|---|---|
| `/clear` | 会話をリセットして、机をまっさらにする | **別の作業に移るとき**（いちばん効果的） |
| `/compact` | これまでの会話を要約して、机を片付ける | 同じ作業を続けたいが、会話が長くなったとき |
| `/context` | 今どれくらい机を使っているか表示する | 重くなってきた気がするとき |
| `/usage` | プランの利用量・上限の状況を表示する | 使いすぎていないか確認したいとき |

### `/clear` と `/compact` の使い分け

```text
講座ページの作成（ずっと同じ作業）
  └─ 会話が長くなってきた → /compact で要約して続ける

講座ページが完成 → 次は請求書の集計（まったく別の作業）
  └─ /clear でリセットしてから始める
```

`/compact` には、残してほしい内容を指示できます。

```text
/compact 料金表のデザインの決定事項と、残りの作業リストを残して
```

> `/clear` しても、CLAUDE.md（第8章）は次の会話でもちゃんと読み込まれます。「毎回伝えたいこと」は CLAUDE.md に書いておけば、安心してリセットできます。

## 9-3 利用上限とコストのしくみ

Claude Code の利用には上限や料金があります。

| 使い方 | しくみ |
|---|---|
| サブスクリプション（Pro / Max など） | プランに利用量が含まれる。**一定時間あたり・1週間あたりの上限** がある |
| API（Claude Console など） | **使った分だけ課金**（トークン数に応じて） |

どちらの場合も、**会話が長いほど、1回のやり取りで消費する量が増えます**。机の上の情報を毎回読み直すからです。`/usage` でこまめに確認しましょう。

> 料金やプランの内容は変わることがあります。最新の情報は公式サイトで確認してください。

## 9-4 節約の7つのコツ

| # | コツ | 理由 |
|---|---|---|
| 1 | **作業が変わったら `/clear`** | 前の話を読み返すぶんの無駄がなくなる |
| 2 | **2回直してだめなら、`/clear` して指示を書き直す** | 失敗のやり取りが机に積もると、かえって迷走する（9-6） |
| 3 | **CLAUDE.md は短く** | 毎回読み込まれるので、長いと毎回コストがかかる（第8章）。`@` で別のファイルを読み込ませても、そのファイルも一緒に毎回読み込まれるので節約にはならない |
| 4 | **簡単な作業は軽いモデルで** | 軽いモデルは消費が少ない（9-5） |
| 5 | **大量の調べものはサブエージェントに** | 途中経過がメインの机に積もらない（第11章）。ただしサブエージェントの分も利用量は消費する |
| 6 | **長い手順書はスキルにする** | 毎回載るのは名前と説明文だけで、本文は使うときだけ読み込まれる（第10章） |
| 7 | **使わないプラグインや MCP は切る** | プラグインに入っているスキルやサブエージェントは、名前と説明文が毎回載る。MCP のツールは使うまで名前だけなので影響は比較的小さい（第13章）。`/mcp` で確認できる |

### それでも上限に当たるとき

- まずは上の7つを見直す
- それでも **毎日のように上限に当たる** なら、上位のプラン（Max など）を検討する目安です
- 上限に当たったら、時間をおけば回復します。その間に、Claude が作ったものを自分で確認する時間に充てるのも一つの手です

## 9-5 モデルと「考える深さ」を選ぶ

### モデル

`/model` で使う AI のモデルを切り替えられます。

| モデル | 特徴 | 向いている作業 |
|---|---|---|
| **Opus** | 最も賢い。多くのプランでの標準モデル | 難しい設計、複雑な不具合、大きな作業の計画 |
| **Sonnet** | 賢さと速さのバランスが良い | 日常的な作業の多く |
| **Haiku** | 速くて軽い | 簡単な修正、単純な調べもの、表記の統一 |

```text
/model sonnet
```

> 選べるモデルや標準のモデルは、プランや利用環境、時期により異なります。`/model` を実行すると、今選べるものが一覧で表示されます。

### 考える深さ（effort）

`/effort` で **考える深さ** を変えられます。

| レベル | 特徴 |
|---|---|
| `low` | 速くて軽い。単純な作業向け |
| `medium` | 最新モデル（Opus 5.5・Sonnet 5.5・Haiku 5.5）の標準 |
| `high` / `xhigh` / `max` | より丁寧に考える。時間と利用量も増える |

```text
/effort high
```

**迷ったら標準のままで構いません**。難しい問題で何度も失敗するときに上げてみる、くらいの使い方がおすすめです。

### さくらさんの使い分け（例）

| 作業 | モデル | 深さ |
|---|---|---|
| ブログ記事の誤字チェック | Haiku | 標準 |
| 講座ページの作成・修正 | Sonnet | 標準 |
| 予約システムの設計を相談 | Opus | high |

## 9-6 なぜ「仕切り直し」が効くのか

同じ会話で修正を重ねると、「うまくいかなかった案」と「それを直す指示」が机の上にどんどん積もります。Claude はそれを毎回読み直すので、

- 失敗した案に引っ張られて、似た間違いを繰り返しやすくなる
- 最初に伝えた大事な条件が、圧縮のときに抜け落ちやすくなる
- やり取りのたびに消費する量も増えていく

だから **2回直してもだめなら、`/clear` で机を片付けて、指示を書き直す** ほうが早くて安く済むことが多いのです。書き直し方は[第4章 4-6](04-prompting.md)を参照してください。

## やってみよう

### 練習1：コンテキストの使用量を見る

- **目的**: `/context` で机の状態を確認できるようになる
- **手順**:
  1. 練習用フォルダ `~/sakura-work` で Claude Code を起動して `/context` を実行する
  2. 「このフォルダのファイルを全部読んで、内容を要約して」と頼む
  3. もう一度 `/context` を実行して、増え方を見る
  4. `/clear` してから、もう一度 `/context`
- **期待する結果**: ファイルを読んだあとに使用量が増え、`/clear` で減る
- **うまくいかないとき**: 表示の形はバージョンにより異なります。数字やグラフのどこが「使用量」か分からなければ、Claude に「この表示の見方を教えて」と聞く

### 練習2：利用量を確認する

- **目的**: 自分の利用状況を把握する
- **手順**: `/usage` を実行して、上限までの残りを確認する
- **期待する結果**: プランの利用量や上限の状況が表示される
- **うまくいかないとき**: API 利用の場合は、表示の内容がサブスクリプションと異なります

### 練習3：モデルを切り替えて比べる

- **目的**: モデルによる速さや答え方の違いを体験する
- **手順**:
  1. `/model haiku` に切り替えて「この文章の誤字を探して：『明日わ会議がありますので、資料お準備してください』」と頼む
  2. `/model sonnet` に切り替えて同じことを頼む
- **期待する結果**: どちらも誤字を見つけるが、速さや説明の詳しさが違う
- **うまくいかないとき**: そのモデルが選べないと表示されたら、`/model` だけを実行して選べるモデルを確認する

## まとめ

- コンテキストは Claude の **作業机**。散らかると忘れっぽくなり、コストも増える
- **別の作業に移るなら `/clear`**、同じ作業を続けるなら `/compact`
- `/context` で机の状態、`/usage` で利用量を確認
- 簡単な作業は **Sonnet や Haiku**、考える深さは **迷ったら標準**
- **2回直してだめなら、`/clear` して指示を書き直す**

## 確認テスト

**問1.** 講座ページの作成が終わり、次は請求書の集計をします。最初に何をするとよいですか？

<details><summary>答えを見る</summary>

`/clear` で会話をリセットします。前の作業の情報が残っていると、無駄に読み返す量が増え、話も混ざりやすくなります。
</details>

**問2.** `/clear` すると、CLAUDE.md に書いたルールも忘れてしまいますか？

<details><summary>答えを見る</summary>

忘れません。CLAUDE.md は会話を始めるたびに自動で読み込まれます。だから「毎回伝えたいこと」は CLAUDE.md に書いておくと、安心してリセットできます。
</details>

**問3.** ブログ記事の表記ゆれチェックを大量に頼みたいです。モデルの選び方として適切なのは？

<details><summary>答えを見る</summary>

Haiku や Sonnet などの軽いモデルです。単純な作業なら十分な品質で、利用量を節約できます。
</details>

**問4.** 同じ不具合を2回直してもらいましたが、まだ直りません。次にどうするのがおすすめですか？

<details><summary>答えを見る</summary>

`/clear` で仕切り直し、原因を踏まえて指示を書き直して頼みます。同じ会話で修正を重ねると、失敗の記録が積もって迷走しがちです。
</details>

**問5.** サブエージェントに調べものを任せると、利用量はゼロになりますか？

<details><summary>答えを見る</summary>

なりません。サブエージェントの分も利用量にカウントされます。メリットは、途中経過がメインの会話に積もらず、会話が長くなりにくいことです。
</details>
