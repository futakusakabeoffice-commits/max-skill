# 第8章 CLAUDE.md とメモリ：Claude に覚えてもらう

> **この章で学ぶこと**
> - Claude が会話をまたいで「覚えていない」理由と、その対策
> - CLAUDE.md の作り方・書き方・置き場所
> - 効く書き方と、逆効果になる書き方
> - 自動メモリ（Claude が自分で取るメモ）の扱い方
> - 「3回ルール」で CLAUDE.md を少しずつ育てる方法
>
> **所要時間の目安**: 40分 ／ **前提**: 第1部（第1〜4章）と第5章を読んでいること

---

## 8-1 Claude は会話が終わると忘れる

Claude Code は、セッション（起動してから終了するまでの1回分の会話）が終わると、その中で話した内容を基本的に忘れます。`/clear` で会話をリセットしたときも同じです。

さくらさんの場合、毎回こんな説明をしていました。

```text
このフォルダは私のオンライン講座のサイトです。
お客様は30〜50代の女性が中心なので、専門用語は使わないでください。
色はブランドカラーの #2E7D6B を基準にしてください。
```

これを **毎回自動で読み込ませるためのファイル** が `CLAUDE.md` です。Claude Code は起動するたびに CLAUDE.md を読んでから仕事を始めます。

| | 毎回口で説明する | CLAUDE.md に書く |
|---|---|---|
| 手間 | 毎回かかる | 最初に1回書くだけ |
| 説明のブレ | 日によって言い方が変わる | いつも同じ内容 |
| 言い忘れ | 起こる | 起こらない |

> CLAUDE.md は Markdown（`#` で見出し、`-` で箇条書きを書く簡単な書式）で書きます。用語は [付録B 用語集](appendix-b-glossary.md) も参照してください。

---

## 8-2 CLAUDE.md を作る：`/init`

いちばん簡単なのは、Claude Code の中で次のコマンドを実行することです。

```text
/init
```

Claude がフォルダの中身を調べて、CLAUDE.md の下書きを作ってくれます。すでに CLAUDE.md がある場合は、上書きせずに改善案を出してくれます。

下書きができたら、次のように頼んで育てていきます。

```text
CLAUDE.md に「文章は です・ます 調で、専門用語は使わない」というルールを追加して
```

> 自分で一から書いても構いません。ただのテキストファイルなので、プロジェクトのフォルダに `CLAUDE.md` という名前で保存すれば読み込まれます。

---

## 8-3 何を書くか：さくらさんの CLAUDE.md

保存するファイル: `CLAUDE.md`（プロジェクトのフォルダの直下）

```markdown
# このプロジェクトについて
- さくらのオンライン講座「はじめての Web デザイン」の公式サイト
- お客様は30〜50代の女性。パソコンに詳しくない人が多い

# 文章のルール
- 「です・ます」調。専門用語は使わず、使うときは一言説明を添える
- 1文は60文字以内を目安にする

# デザインのルール
- 色はブランドカラー #2E7D6B を基準にする
- 画像は images/ フォルダに入れる

# フォルダの構成
- site/ … 公開しているサイトのファイル
- drafts/ … ブログ記事の下書き
- data/ … 売上などの CSV（お客様の個人情報を含むので、外部に送らない）

# 作業の確認方法
- サイトを変更したら、ブラウザで開いてスマホ幅でも崩れていないか確認する
- 金額を集計したら、必ず検算して結果を報告する
```

### 書くべきこと・書かなくていいこと

| 書くべきこと（Claude が見ただけでは分からない） | 書かなくていいこと（見れば分かる・すぐ変わる） |
|---|---|
| お客様像、ブランドのルール、文体 | ファイルの中身をそのまま貼ったもの |
| フォルダの役割、触ってはいけない場所 | 一度きりの作業の指示 |
| 作業の確認方法（検算する、ブラウザで確認する） | 「丁寧にやって」などの当たり前のこと |
| よく間違えられること（例: 「料金は税込で書く」） | 長い文章のマニュアル（別ファイルにして読み込ませる。8-5） |

> **注意**: CLAUDE.md に **パスワードや API キー（サービスを使うための合言葉）を書かないでください**。CLAUDE.md は Git で共有されることが多く、Claude に毎回読まれます。秘密情報の扱いは [第7章](07-safety.md) を参照してください。

## 8-4 置き場所と効く範囲

CLAUDE.md は、置く場所によって効く範囲が変わります。

| ファイル | 効く範囲 | 主な用途 |
|---|---|---|
| `~/.claude/CLAUDE.md` | 自分の **全プロジェクト** | 「日本語で答えて」「説明は短く」など、自分の好み |
| `./CLAUDE.md` または `./.claude/CLAUDE.md` | **そのプロジェクト** | プロジェクトのルール。Git で共有してよい内容 |
| `./CLAUDE.local.md` | そのプロジェクト・**自分だけ** | 共有したくない個人メモ（`.gitignore` に追加しておく） |
| 組織の管理者が配布する場所 | 組織全体 | 会社などで一括設定するもの（個人なら気にしなくてよい） |

- `~/` はホームフォルダ（自分のユーザー用フォルダ）のことです。`.claude` のように `.` で始まるフォルダは隠しフォルダで、Mac の Finder では `⌘ + Shift + .` で表示できます。
- 起動したフォルダと、その **上の階層のフォルダ** にある CLAUDE.md は、起動時にまとめて読み込まれます。
- 下の階層（サブフォルダ）にある CLAUDE.md は、Claude がそのフォルダの作業をするときに読み込まれます。

さくらさんの使い分け:

- `~/.claude/CLAUDE.md` … 「回答は日本語で。結論を先に書いて」
- `講座サイト/CLAUDE.md` … 8-3 の内容
- `講座サイト/CLAUDE.local.md` … 「来月の値上げ案はまだ非公開」などのメモ

> CLAUDE.md がなく `AGENTS.md` がある場合は、その AGENTS.md が代わりに読まれます。他の AI ツールと設定を共有したいときに便利です。

## 8-5 長くしないための工夫

### 目安は1ファイル200行以内

公式の目安は **1ファイル200行以内** です。長くなるほど、次の問題が起きます。

- 大事なルールが埋もれて、守られにくくなる
- 毎回読み込まれるので、そのぶん利用量とコンテキスト（AI が会話で覚えていられる情報）を消費する（詳しくは [第9章](09-context-cost.md)）

### 別のファイルを読み込ませる（`@インポート`）

長い資料は別ファイルにして、CLAUDE.md から `@ファイルのパス` で読み込ませられます。

```markdown
# ブランドのルール
詳しくは @docs/brand-guide.md を参照

# 料金表
@docs/price-list.md
```

- バッククォート（`` ` ``）で囲むと読み込まれないので、そのまま書きます。
- 読み込まれたファイルからさらに別のファイルを読み込むこともできます（深さには上限があります）。

### ルールを分けて置く（`.claude/rules/`）

ルールが増えてきたら、`.claude/rules/` フォルダに Markdown ファイルを分けて置けます。フロントマター（ファイル冒頭の `---` で囲んだ設定欄）に `paths:` を書くと、特定のフォルダを扱うときだけ読み込ませることもできます。

保存するファイル: `.claude/rules/blog.md`

```markdown
---
paths:
  - "drafts/**"
---

# ブログ記事のルール
- タイトルは32文字以内
- 最後に講座への案内を1行入れる
```

> `paths:` の細かい書き方はバージョンにより異なる場合があります。うまく効かないときは、Claude に「.claude/rules の書き方を公式ドキュメントで確認して」と聞いてください。

## 8-6 CLAUDE.md は「お願い」である

CLAUDE.md に書いたことは、Claude にとって **強い参考情報** ですが、**絶対の命令ではありません**。会話が長くなったり、指示が矛盾したりすると、守られないことがあります。

| 守らせたいこと | 向いている仕組み |
|---|---|
| 文体・お客様像・作業のコツ | **CLAUDE.md**（この章） |
| 「`.env` を読ませない」「push させない」 | **権限設定の deny**（[第5章](05-permissions-settings.md)） |
| 「編集したら必ず整形する」「特定のファイルは絶対に触らせない」 | **フック**（[第12章](12-hooks.md)） |
| 決まった手順の作業 | **スキル**（[第10章](10-skills.md)） |

「絶対に守らせたい」ことは、CLAUDE.md だけに頼らず、権限設定やフックで仕組みにしましょう。

## 8-7 自動メモリ：Claude が自分で取るメモ

Claude Code には、作業中に気づいたこと（「このプロジェクトでは〜の方法でうまくいった」など）を **Claude 自身がメモしておく自動メモリ** の機能もあります。

- 自動メモリは `MEMORY.md` というメモに書かれ、次のセッションでは先頭の一部（200行または25KBまで）が読み込まれます。
- `/memory` で、CLAUDE.md の編集や自動メモリのオン・オフ、中身の確認ができます。

| | CLAUDE.md | 自動メモリ |
|---|---|---|
| 書く人 | 自分（または Claude に頼む） | Claude が自分で |
| 中身 | ルール・前提 | 作業中に学んだこと |
| 管理 | 自分で整える | ときどき `/memory` で中身を見て整理する |

> **注意**: 自動メモリに間違った思い込みが残ると、次回以降もその前提で動いてしまいます。「なぜか毎回同じ間違いをする」ときは、`/memory` で中身を確認してください。

## 8-8 育て方：「3回ルール」

最初から完璧な CLAUDE.md を作る必要はありません。おすすめは次の **3回ルール** です。

> **同じ説明を3回したら、CLAUDE.md（またはスキル）にする。**

1. 最初は `/init` の下書きのまま使い始める
2. 「また同じことを言ったな」と思ったら、その場で「今の注意点を CLAUDE.md に追加して」と頼む
3. 月に1回くらい、「CLAUDE.md を読んで、古い内容や重複を整理して。200行以内に収めて」と頼む

手順の決まった作業（「週報を作る」など）が3回出てきたら、CLAUDE.md ではなく **スキル** にするのが向いています（[第10章](10-skills.md)）。

## やってみよう

### 練習1：`/init` で CLAUDE.md を作る

- **目的**: CLAUDE.md の下書きを作り、中身を確認する
- **手順**:
  1. 練習用のフォルダで `claude` を起動する
  2. `/init` を実行する
  3. できた `CLAUDE.md` を開いて読む
- **期待する結果**: フォルダの説明やルールの下書きが書かれた `CLAUDE.md` ができる
- **うまくいかないとき**: フォルダが空だと書く内容が少なくなります。先に「サンプルのブログ記事を drafts/ に2つ作って」と頼んでから `/init` してみてください

### 練習2：ルールを追加して効き目を確かめる

- **目的**: CLAUDE.md のルールが次のセッションでも効くことを確かめる
- **手順**:
  1. 「CLAUDE.md に『文章の最後には必ず「ご質問はお気軽にどうぞ」と入れる』というルールを追加して」と頼む
  2. `/clear` で会話をリセットする
  3. 「講座の紹介文を100字で書いて」と頼む
- **期待する結果**: リセット後でも、紹介文の最後に「ご質問はお気軽にどうぞ」が入る
- **うまくいかないとき**: `/memory` で CLAUDE.md にルールが保存されているか確認します

### 練習3：自分用の CLAUDE.md を作る

- **目的**: 全プロジェクト共通の好みを設定する
- **手順**: 「`~/.claude/CLAUDE.md` に『回答は日本語で、結論を先に書く』と書いて」と頼む
- **期待する結果**: 別のフォルダで起動しても、結論から日本語で答えてくれる
- **うまくいかないとき**: Claude Code を一度終了して、起動し直してから試します

## まとめ

- Claude は会話が終わると忘れる。毎回伝えたいことは **CLAUDE.md** に書く
- 作り始めは `/init`。あとは「CLAUDE.md に〜を追加して」と頼んで育てる
- 書くのは **Claude が見ても分からないこと**（お客様像・ルール・確認方法）。秘密情報は書かない
- 置き場所で効く範囲が変わる（自分用 `~/.claude/`、プロジェクト用 `./`、自分だけ `CLAUDE.local.md`）
- **200行以内** を目安に。長い資料は `@インポート` や `.claude/rules/` に分ける
- CLAUDE.md は「お願い」。絶対のルールは権限設定やフックで

## 確認テスト

**問1.** 「日本語で答えて」という好みを、自分の全プロジェクトに効かせたいとき、どこに書けばよいですか？

<details><summary>答えを見る</summary>

`~/.claude/CLAUDE.md` です。ホームフォルダの `.claude` フォルダに置いた CLAUDE.md は、全プロジェクトで読み込まれます。プロジェクトのフォルダの `CLAUDE.md` は、そのプロジェクトにだけ効きます。

</details>

**問2.** CLAUDE.md が500行になってしまいました。どんな問題があり、どう直せばよいですか？

<details><summary>答えを見る</summary>

大事なルールが埋もれて守られにくくなり、毎回読み込まれるので利用量とコンテキストも余計に消費します。公式の目安は200行以内です。長い資料は別ファイルにして `@ファイル名` で読み込ませる、`.claude/rules/` に分ける、古い内容を整理するなどで短くします。

</details>

**問3.** 「`.env` ファイルは絶対に読ませたくない」というルールは、CLAUDE.md に書くだけで十分ですか？

<details><summary>答えを見る</summary>

十分ではありません。CLAUDE.md は「お願い」なので、守られないことがあります。権限設定の `deny`（第5章）や、フック（第12章）で仕組みとして禁止するのが確実です。

</details>

**問4.** 「3回ルール」とは何ですか？

<details><summary>答えを見る</summary>

同じ説明を3回したら、CLAUDE.md（手順の決まった作業ならスキル）にする、という育て方の目安です。最初から完璧を目指さず、必要になったものから足していきます。

</details>
