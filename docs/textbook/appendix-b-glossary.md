# 付録B 用語集

> この教科書に出てくる用語を、やさしい言葉で説明します。本文中の用語のリンクからここに飛べます。
> 並び順: [記号・英字](#sec-alpha) → [あ行](#sec-a) → [か行](#sec-ka) → [さ行](#sec-sa) → [た行](#sec-ta) → [な行](#sec-na) → [は行](#sec-ha) → [ま行](#sec-ma) → [や・ら・わ行](#sec-yrw)

<a id="sec-alpha"></a>
## B-1 記号・英字

- <a id="g-home"></a>**`~/`（ホームフォルダ）**: 自分のユーザー用フォルダのこと。`~/.claude` は「ホームフォルダの中の `.claude` フォルダ」という意味。→ 第2章（ファイル保存の囲み）・第5章
- <a id="g-dot-slash"></a>**`./`**: 「今いるフォルダ」のこと。`./CLAUDE.md` は「今いるフォルダの中の CLAUDE.md」。→ 第8章
- <a id="g-env"></a>**`.env`（ドットエンブ）**: パスワードや API キーなどの秘密情報を書いておくファイル。人にも AI にも見せず、Git にも記録しない。→ 第7章
- <a id="g-gitignore"></a>**`.gitignore`**: Git に記録しないファイルの一覧を書くファイル。`.env` などを書いておく。→ 第6章
- <a id="g-at"></a>**`@`（アットマーク）**: 入力欄でファイルを指定するときに使う記号。`@docs/plan.md` のように書く。→ 第3章
- <a id="g-bang"></a>**`!`（先頭に付ける）**: 入力の先頭に付けると、そのままターミナルのコマンドとして実行される。→ 第3章
- <a id="g-agent-sdk"></a>**Agent SDK**: Claude Code と同じ仕組みを、自分のプログラムに組み込むための開発者向けの道具。この教科書では扱わない。
- <a id="g-api"></a>**API / API キー**: API はサービス同士をつなぐ窓口。API キーはそれを使うための合言葉（パスワードのようなもの）。漏れると他人に使われてしまう。→ 第7章
- <a id="g-allow-deny"></a>**allow / ask / deny**: 権限ルールの種類。allow は「確認なしで許可」、ask は「毎回確認」、deny は「禁止」。deny が常に優先される。→ 第5章
- <a id="g-claude"></a>**Claude / Claude Code**: この教科書では、**Claude** は Anthropic 社の AI そのもの、**Claude Code** はその AI がパソコンのファイルを読み書きして作業するための道具を指す。→ 第1章
- <a id="g-claude-tag"></a>**Claude Tag**: Slack の中から Claude に作業を頼める機能。Team / Enterprise プラン向けで、組織の Owner（管理者）が claude.ai の管理設定から導入する。→ 第14章
- <a id="g-claude-md"></a>**CLAUDE.md**: プロジェクトのルールや前提を書いておくファイル。起動するたびに自動で読み込まれる。→ 第8章
- <a id="g-cli"></a>**CLI（コマンドラインインターフェース）**: ターミナルに文字を打ち込んで操作する方式のこと。Claude Code の基本の形。→ 第1章
- <a id="g-clt"></a>**Command Line Tools**: Mac でターミナルの基本的な道具（Git など）を使うために必要な Apple の追加ソフト。初めて `git` を使うと、インストールを求める画面が出ることがある。→ 第6章
- <a id="g-csv"></a>**CSV**: 値をカンマ（`,`）で区切って並べた表形式のファイル。Excel やスプレッドシートで開ける。→ 第1章・第15章
- <a id="g-git"></a>**Git（ギット）**: ファイルの変更履歴を記録する仕組み。「セーブポイント」を作っておけば、失敗しても前の状態に戻せる。→ 第6章
- <a id="g-git-for-windows"></a>**Git for Windows**: Windows で Git を使うためのソフト。Windows で Git を使う前に入れておく。→ 第6章
- <a id="g-github"></a>**GitHub（ギットハブ）**: Git の記録をインターネット上に保存・共有できるサービス。公開（Public）と非公開（Private）を選べる。→ 第6章
- <a id="g-homebrew"></a>**Homebrew（ホームブルー）**: Mac でソフトをコマンドでインストールするための道具。Claude Code も `brew install --cask claude-code` で入れられる（自動更新はされない）。→ 第2章
- <a id="g-issue"></a>**Issue（イシュー）**: GitHub の機能。「やること」や「不具合」のメモを書いておく場所。→ 第14章
- <a id="g-json"></a>**JSON（ジェイソン）**: `{ "名前": "値" }` の形で設定などを書く書式。カンマや括弧が1つずれるだけで動かなくなる。コメントは書けない。→ 第5章
- <a id="g-lp"></a>**LP（ランディングページ）**: 広告や SNS から来た人が最初に見る、商品やサービスを紹介する1枚の Web ページ。→ 第11章
- <a id="g-main-branch"></a>**main（メインブランチ）**: Git で本流となるブランチの名前。完成したものをここにまとめる。→ 第14章
- <a id="g-markdown"></a>**Markdown（マークダウン）**: `#` で見出し、`-` で箇条書きを書く簡単な書式。ファイル名の最後は `.md`。→ 第8章
- <a id="g-mcp"></a>**MCP**: Claude Code を外部サービス（Notion、GitHub、ブラウザ操作など）とつなぐ仕組み。→ 第13章
- <a id="g-nodejs"></a>**Node.js（ノード）**: プログラムを動かすための土台ソフトの一つ。一部のツール（整形ツールなど）で必要になる。→ 第12章
- <a id="g-path"></a>**PATH（パス）**: ターミナルが「コマンドの本体がどこにあるか」を探す場所の一覧。`command not found` と出る原因になることがある。→ 付録C
- <a id="g-remote-control"></a>**Remote Control**: 自分のパソコンで動いている Claude Code を、スマホや Web から操作する機能。`/remote-control` で始める。→ 第14章
- <a id="g-settings"></a>**settings.json**: 権限・フック・モデルなどを書く設定ファイル。置き場所によって効く範囲が変わる。→ 第5章
- <a id="g-url"></a>**URL**: Web ページの住所（`https://〜`）。→ 第4章
- <a id="g-winget"></a>**WinGet**: Windows でソフトをコマンドでインストールするための道具。`winget install Anthropic.ClaudeCode` で Claude Code を入れられる（自動更新はされない）。→ 第2章
- <a id="g-worktree"></a>**worktree（ワークツリー）**: Git の仕組みを使って作る「作業用の分身フォルダ」。元のフォルダを汚さずに並行して作業できる。→ 第14章
- <a id="g-wsl"></a>**WSL**: Windows の上で Linux を動かす仕組み。分からなければ使わなくてよい。→ 第2章
- <a id="g-yaml"></a>**YAML（ヤムル）**: `項目: 値` の形で設定を書く書式。スキルやサブエージェントのファイル冒頭（フロントマター）で使う。字下げ（スペース）の数に意味がある。→ 第10章・第11章

<a id="sec-a"></a>
## B-2 あ行

- <a id="g-account"></a>**アカウント / プラン**: Claude を使うための登録と契約の種類。Claude Code は有料プラン（Pro / Max / Ultra / Team / Enterprise）か、Claude Console（API）のアカウントで使える。無料プランでは使えない。→ 第2章
- <a id="g-install"></a>**インストール**: ソフトをパソコンに入れて使える状態にすること。→ 第2章
- <a id="g-agent-teams"></a>**エージェントチーム**: 複数の Claude が役割を分担し、互いにやり取りしながら仕事を進める機能。**実験的な機能** で、最初はオフ（環境変数 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` で有効にする）。利用量がかなり増える。→ 第14章
- <a id="g-editor"></a>**エディタ**: 文章やプログラムを書くためのソフト（VS Code など）。Mac の「テキストエディット」はリッチテキストになりやすいので、設定ファイルの編集には向かない。→ 第2章

<a id="sec-ka"></a>
## B-3 か行

- <a id="g-newline"></a>**改行の入力**: 依頼文の途中で改行すること。`Enter` だけだと送信されてしまうので、`\` を打ってから `Enter`（どの環境でも可）、または `Ctrl + J`。`Shift + Enter` は一部のターミナルのみ。Mac 標準ターミナルや VS Code では `/terminal-setup` を一度実行（Mac 標準ターミナルでは `Option + Enter` に）。→ 第3章
- <a id="g-permission-prompt"></a>**確認画面（許可の確認）**: Claude がファイル編集やコマンド実行の前に「やってもいいですか？」と聞いてくる画面。内容を読んでから Yes / No を選ぶ。→ 第5章
- <a id="g-hidden"></a>**隠しフォルダ**: `.claude` のように `.`（ドット）で始まるフォルダ。普段は見えない。Mac の Finder では `⌘ + Shift + .` で表示できる。→ 第2章（ファイル保存の囲み）・第5章
- <a id="g-effort"></a>**考える深さ（effort）**: Claude がどれだけじっくり考えるかの設定。`low` / `medium` / `high` / `xhigh` / `max`。深いほど丁寧だが、時間と利用量が増える。`/effort` で変える。→ 第9章
- <a id="g-cloud"></a>**クラウド / クラウドセッション**: 自分のパソコンではなく、インターネット上のコンピューター（Anthropic のサーバー）で Claude Code を動かすこと。パソコンを閉じても作業が続くが、手元のファイルは直接見えない。→ 第14章
- <a id="g-permission-mode"></a>**権限モード**: Claude にどこまで確認なしで任せるかの設定。default / acceptEdits / plan / auto など。`Shift + Tab` で切り替える。→ 第5章
- <a id="g-permission-rules"></a>**権限ルール**: 「このコマンドは確認なしで許可」「このファイルは読ませない」などを設定ファイルに書いたもの。→ 第5章
- <a id="g-verify"></a>**検算**: 計算結果が正しいか、別の方法で確かめること。数字を扱う依頼には「最後に検算して」と添えるとよい。→ 第4章
- <a id="g-command"></a>**コマンド**: ターミナルに打ち込む命令文（例: `cd`, `ls`, `claude`）。→ 第2章
- <a id="g-commit"></a>**コミット**: Git で「今のファイルの状態を記録すること」。セーブポイントを作るイメージ。→ 第6章
- <a id="g-context"></a>**コンテキスト**: Claude がその会話で覚えていられる情報（会話の内容、読んだファイルなど）。量に上限があり、いっぱいになると古い内容が要約される。→ 第9章

<a id="sec-sa"></a>
## B-4 さ行

- <a id="g-server"></a>**サーバー**: インターネット上でサービスを提供しているコンピューター。→ 第14章
- <a id="g-subagent"></a>**サブエージェント**: メインの会話とは別のコンテキストで動く「専門の助手」。結果の要約だけが戻ってくるので、メインの会話が散らからない。→ 第11章
- <a id="g-system-prompt"></a>**システムプロンプト**: AI に最初に渡す「あなたは〇〇です。こう動いてください」という指示書。サブエージェントのファイルの本文がこれにあたる。→ 第11章
- <a id="g-auto-memory"></a>**自動メモリ**: 作業中に気づいたことを Claude 自身がメモしておく機能。`/memory` で確認・オン・オフできる。→ 第8章
- <a id="g-output-style"></a>**出力スタイル**: Claude の答え方（口調・詳しさなど）を切り替える機能。`/output-style` で変える。→ 第14章
- <a id="g-skill"></a>**スキル**: よく使う手順や知識をまとめた指示ファイル（`SKILL.md`）。`/名前` で呼び出せ、Claude が必要に応じて自動で使うこともある。→ 第10章
- <a id="g-scope"></a>**スコープ**: 設定などが「効く範囲」のこと（自分だけ / プロジェクト / 全プロジェクトなど）。→ 第13章
- <a id="g-slash-command"></a>**スラッシュコマンド**: Claude Code の中で `/` から始めて入力する命令（例: `/clear`）。→ 第2章
- <a id="g-session"></a>**セッション**: Claude Code を起動してから終了するまでの1回分の会話。→ 第8章

<a id="sec-ta"></a>
## B-5 た行

- <a id="g-terminal"></a>**ターミナル**: 文字でパソコンに命令する画面。Mac は「ターミナル」、Windows は「PowerShell」など。→ 第2章
- <a id="g-interactive"></a>**対話モード**: `claude` で起動したときの、会話しながら進める使い方。→ 第14章
- <a id="g-checkpoint"></a>**チェックポイント / 巻き戻し（rewind）**: Claude Code が自動で記録している途中の状態。`Esc` を2回、または `/rewind` でそこまで戻れる。ただしコマンドで変わったファイルなどは戻らない。→ 第3章・第6章
- <a id="g-tool"></a>**ツール**: Claude が作業に使う道具のこと。`Read`（ファイルを読む）、`Edit`（ファイルを書き換える）、`Bash`（コマンドを実行する）など。権限ルールやサブエージェントの設定で、使えるツールを決められる。→ 第5章・第11章
- <a id="g-schedule"></a>**定期実行（/schedule）**: 決まった時間に Claude に作業してもらう予約。クラウドで動く。→ 第14章
- <a id="g-test"></a>**テスト**: プログラムや作業結果が正しいかを確かめる仕組み・手順。Claude に確認方法を渡すと品質が上がる。
- <a id="g-token"></a>**トークン**: AI が文章を数える単位。料金や利用上限の計算に使われる。→ 第9章

## B-6 な行

- <a id="g-login"></a>**認証（ログイン）**: アカウントで本人確認をすること。初回起動時にブラウザで行う。切り替えは `/login`。→ 第2章

<a id="sec-ha"></a>
## B-7 は行

- <a id="g-background"></a>**バックグラウンド**: 画面の裏側で作業を続けること。`Ctrl + B` で実行中の作業を回せる。一覧は `/tasks`。→ 第14章
- <a id="g-pipe"></a>**パイプ（`|`）**: あるコマンドの出力を、次のコマンドに渡す記号。`cat report.txt | claude -p "要約して"` のように使う。→ 第14章
- <a id="g-filepath"></a>**パス（ファイルパス）**: ファイルの場所を表す文字列（例: `data/sales.csv`）。→ 第3章
- <a id="g-private-repo"></a>**非公開（Private）リポジトリ**: GitHub で、自分（と招待した人）しか見られないリポジトリ。売上や顧客の情報を扱うなら必ずこちら。→ 第6章・第7章
- <a id="g-noninteractive"></a>**非対話モード（`claude -p`）**: 質問を1回だけ渡して、答えを受け取ったらすぐ終了する使い方。自動化に向いている。→ 第14章
- <a id="g-folder"></a>**フォルダ（ディレクトリ）**: ファイルを入れておく入れ物。ターミナルでは「ディレクトリ」とも呼ぶ。→ 第2章
- <a id="g-fork"></a>**フォーク**: それまでの会話をまるごと引き継いだ分身のサブエージェント。説明し直さずに一部の作業を任せられる。→ 第11章
- <a id="g-hook"></a>**フック**: 「ファイルを編集した後に必ず〇〇する」など、決まったタイミングで自動実行される処理。確認なしで実行されるので、内容を理解したものだけ設定する。→ 第12章
- <a id="g-frontmatter"></a>**フロントマター**: Markdown ファイル冒頭の `---` で囲んだ設定欄。YAML で書く。→ 第10章・第11章
- <a id="g-push"></a>**プッシュ**: Git の記録を GitHub などにアップロードすること。→ 第6章
- <a id="g-plugin"></a>**プラグイン**: スキル・サブエージェント・フック・MCP などをまとめた拡張パック。`/plugin` から探して入れる。→ 第13章
- <a id="g-plan-mode"></a>**プランモード**: 編集をせず、計画だけを立てて見せてくれる権限モード。大きな作業の前に使う。→ 第5章
- <a id="g-branch"></a>**ブランチ**: Git で、本流から分かれて作業するための「枝」。試したい変更を本流と分けておける。→ 第6章
- <a id="g-pull-request"></a>**プルリクエスト**: GitHub で「この変更を取り込んでください」と依頼する機能。→ 第6章（GitHub の節）・第14章
- <a id="g-project"></a>**プロジェクト**: 作業対象のフォルダ。Claude Code は起動したフォルダの中を作業場所にする。→ 第2章
- <a id="g-prompt"></a>**プロンプト**: AI への指示文・依頼文。→ 第4章
- <a id="g-prompt-injection"></a>**プロンプトインジェクション**: Web ページやファイルの中に、AI をだまして操ろうとする「隠れた指示」を仕込む手口。読ませた情報に従って危ない操作をしないよう注意する。→ 第7章

<a id="sec-ma"></a>
## B-8 ま行

- <a id="g-marketplace"></a>**マーケットプレイス**: プラグインを探して入れられる「お店」。公式のものは最初から使える。→ 第13章
- <a id="g-main"></a>**メインの会話**: あなたが直接やり取りしている Claude との会話。サブエージェントから見た「親」。→ 第11章
- <a id="g-model"></a>**モデル（Opus / Sonnet / Haiku など）**: Claude の種類。Opus は最も賢い、Sonnet はバランス型、Haiku は速くて軽い。`/model` で切り替える。→ 第9章

---

<a id="sec-yrw"></a>
## B-9 や・ら・わ行

- <a id="g-compact"></a>**要約（/compact）**: これまでの会話を要約して軽くすること。同じ作業を続けたいが会話が長くなったときに使う。→ 第9章
- <a id="g-usage"></a>**利用量 / 利用上限**: プランごとに決まっている、一定時間あたり・1週間あたりに使える量。`/usage` で確認する。サブエージェントやクラウドの作業もカウントされる。→ 第9章
- <a id="g-repository"></a>**リポジトリ**: Git で管理しているフォルダのこと。GitHub 上に置いたものも指す。→ 第6章
- <a id="g-local"></a>**ローカル**: 自分のパソコンの中のこと。「クラウド」の反対。→ 第14章
